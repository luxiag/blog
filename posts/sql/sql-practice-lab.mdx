## 0. 数据集速览

你会用到 5 张表（与 Part 2 相同）：

- `users(id, name, city, signup_date)`：用户
- `products(id, name, category, price)`：商品
- `orders(id, user_id, order_date, status)`：订单（含取消、退款、待支付）
- `order_items(order_id, product_id, quantity, unit_price)`：订单明细（成交价以 unit_price 为准）
- `payments(id, order_id, paid_at, amount, method, status)`：支付（SUCCESS / PENDING / FAILED / REFUNDED）

## 1. CTE 复用与对账

CTE（Common Table Expression，`WITH ... AS (...)`）是处理复杂业务的关键工具——它让你把一个长查询拆成几个逻辑清晰的步骤，先算中间结果，再组合。

### 练习 1：用 CTE 复用"订单金额"

目标：用 `WITH order_amounts AS (...)` 先算每笔订单的金额（`SUM(quantity * unit_price)`），再关联 `orders` 输出 `order_id, user_id, order_date, status, order_amount`。

<SqlSimulator
  dataset="commerce"
  description="涉及表：order_items、orders"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH order_amounts AS (
  SELECT
    order_id,
    SUM(quantity * unit_price) AS order_amount
  FROM order_items
  GROUP BY order_id
)
SELECT
  o.id AS order_id,
  o.user_id,
  o.order_date,
  o.status,
  oa.order_amount
FROM orders o
JOIN order_amounts oa ON oa.order_id = o.id
ORDER BY o.order_date, o.id;`}
/>

### 练习 2：对账——支付金额是否等于订单金额

目标：输出 `order_id, order_amount, paid_amount, diff`，只看支付 `status='SUCCESS'`。`diff = paid_amount - order_amount`，按 `diff` 绝对值降序。

这道题是真实业务中财务对账的缩影：订单系统记录的金额和支付系统记录的金额是否一致？

<SqlSimulator
  dataset="commerce"
  description="涉及表：order_items、payments"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH order_amounts AS (
  SELECT order_id, SUM(quantity * unit_price) AS order_amount
  FROM order_items
  GROUP BY order_id
), paid AS (
  SELECT order_id, SUM(amount) AS paid_amount
  FROM payments
  WHERE status = 'SUCCESS'
  GROUP BY order_id
)
SELECT
  oa.order_id,
  oa.order_amount,
  p.paid_amount,
  (p.paid_amount - oa.order_amount) AS diff
FROM order_amounts oa
JOIN paid p ON p.order_id = oa.order_id
ORDER BY ABS(diff) DESC, oa.order_id;`}
/>

### 练习 3：未支付订单的金额

目标：找出所有没有成功支付记录的订单，输出 `order_id, user_name, order_date, order_amount, status`。即对账中发现"没收到钱"的订单。

<SqlSimulator
  dataset="commerce"
  description="涉及表：orders、users、order_items、payments"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH order_amounts AS (
  SELECT order_id, SUM(quantity * unit_price) AS order_amount
  FROM order_items
  GROUP BY order_id
), paid_orders AS (
  SELECT DISTINCT order_id
  FROM payments
  WHERE status = 'SUCCESS'
)
SELECT
  o.id AS order_id,
  u.name AS user_name,
  o.order_date,
  oa.order_amount,
  o.status
FROM orders o
JOIN users u ON u.id = o.user_id
JOIN order_amounts oa ON oa.order_id = o.id
LEFT JOIN paid_orders po ON po.order_id = o.id
WHERE po.order_id IS NULL
ORDER BY o.order_date, o.id;`}
/>

## 2. 窗口函数——排名与 Top-N

窗口函数不改变行数，而是为每一行附加一个"窗口内"的计算结果。最常见的场景就是排名和 Top-N。

### 练习 4：每个用户的下单次数排名

目标：输出 `user_id, user_name, order_cnt, rank`（按下单次数从多到少排名），没有订单的用户 `order_cnt` 为 0 也要保留。

<SqlSimulator
  dataset="commerce"
  description="涉及表：orders、users"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH user_orders AS (
  SELECT user_id, COUNT(*) AS order_cnt
  FROM orders
  GROUP BY user_id
)
SELECT
  u.id AS user_id,
  u.name AS user_name,
  COALESCE(uo.order_cnt, 0) AS order_cnt,
  RANK() OVER (ORDER BY COALESCE(uo.order_cnt, 0) DESC) AS rank
FROM users u
LEFT JOIN user_orders uo ON uo.user_id = u.id
ORDER BY rank, user_id;`}
/>

### 练习 5：每个品类最贵的商品

目标：输出每个 `category` 中价格最高的商品，返回 `category, product_name, price`。用 `ROW_NUMBER()` 窗口函数实现。

<SqlSimulator
  dataset="commerce"
  description="涉及表：products"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH ranked AS (
  SELECT
    category,
    name AS product_name,
    price,
    ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) AS rn
  FROM products
)
SELECT category, product_name, price
FROM ranked
WHERE rn = 1
ORDER BY category;`}
/>

### 练习 6：每个用户最近一笔订单

目标：输出每个用户的 `user_id, name, last_order_id, last_order_date`，没有订单的用户也要保留。

<SqlSimulator
  dataset="commerce"
  description="涉及表：orders、users"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH ranked_orders AS (
  SELECT
    o.*,
    ROW_NUMBER() OVER (PARTITION BY o.user_id ORDER BY o.order_date DESC, o.id DESC) AS rn
  FROM orders o
)
SELECT
  u.id AS user_id,
  u.name,
  ro.id AS last_order_id,
  ro.order_date AS last_order_date
FROM users u
LEFT JOIN ranked_orders ro
  ON ro.user_id = u.id AND ro.rn = 1
ORDER BY u.id;`}
/>

## 3. 窗口函数——累计与趋势

累计（Running Total）和同环比是业务报表中最常见的时间维度分析。

### 练习 7：按日期的累计收入（Running Total）

目标：只统计 `payments.status='SUCCESS'`，按天汇总收入，再做累计和，输出 `day, revenue, revenue_cum`。

<SqlSimulator
  dataset="commerce"
  description="涉及表：payments"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH daily AS (
  SELECT
    date(paid_at) AS day,
    SUM(amount) AS revenue
  FROM payments
  WHERE status = 'SUCCESS'
  GROUP BY date(paid_at)
)
SELECT
  day,
  revenue,
  SUM(revenue) OVER (ORDER BY day) AS revenue_cum
FROM daily
ORDER BY day;`}
/>

### 练习 8：每个用户的累计消费额

目标：按时间顺序列出每个用户的每一笔订单金额，并计算该用户的累计消费。输出 `user_name, order_date, order_amount, cumulative_amount`。

<SqlSimulator
  dataset="commerce"
  description="涉及表：orders、users、order_items"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH order_amounts AS (
  SELECT
    o.id AS order_id,
    o.user_id,
    o.order_date,
    SUM(oi.quantity * oi.unit_price) AS order_amount
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  GROUP BY o.id
)
SELECT
  u.name AS user_name,
  oa.order_date,
  oa.order_amount,
  SUM(oa.order_amount) OVER (PARTITION BY oa.user_id ORDER BY oa.order_date, oa.order_id) AS cumulative_amount
FROM order_amounts oa
JOIN users u ON u.id = oa.user_id
ORDER BY u.name, oa.order_date, oa.order_id;`}
/>

## 4. 综合报表实战

综合报表是前面所有技巧的集大成——CTE 拆解逻辑、JOIN 关联多表、聚合计算指标、窗口函数做排名。这 4 道题是本篇的终极挑战。

### 练习 9：城市维度的核心指标报表

目标：输出每个城市的报表，字段如下：

- `city`
- `user_cnt`（城市用户数）
- `paid_order_cnt`（订单状态为 PAID 的订单数）
- `success_payment_amount`（成功支付总额）

要求：按 `success_payment_amount` 降序。

<SqlSimulator
  dataset="commerce"
  description="涉及表：users、orders、payments"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH city_users AS (
  SELECT city, COUNT(*) AS user_cnt
  FROM users
  GROUP BY city
), city_paid_orders AS (
  SELECT u.city, COUNT(*) AS paid_order_cnt
  FROM orders o
  JOIN users u ON u.id = o.user_id
  WHERE o.status = 'PAID'
  GROUP BY u.city
), city_payments AS (
  SELECT u.city, SUM(p.amount) AS success_payment_amount
  FROM payments p
  JOIN orders o ON o.id = p.order_id
  JOIN users u ON u.id = o.user_id
  WHERE p.status = 'SUCCESS'
  GROUP BY u.city
)
SELECT
  cu.city,
  cu.user_cnt,
  COALESCE(cpo.paid_order_cnt, 0) AS paid_order_cnt,
  COALESCE(cp.success_payment_amount, 0) AS success_payment_amount
FROM city_users cu
LEFT JOIN city_paid_orders cpo ON cpo.city = cu.city
LEFT JOIN city_payments cp ON cp.city = cu.city
ORDER BY success_payment_amount DESC, cu.city;`}
/>

### 练习 10：品类维度的销售报表

目标：输出每个 `category` 的报表，字段如下：

- `category`
- `product_cnt`（该品类商品数）
- `total_quantity_sold`（总售出件数）
- `total_revenue`（总销售额，`SUM(quantity * unit_price)`）

要求：按 `total_revenue` 降序。

<SqlSimulator
  dataset="commerce"
  description="涉及表：products、order_items"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH category_products AS (
  SELECT category, COUNT(*) AS product_cnt
  FROM products
  GROUP BY category
), category_sales AS (
  SELECT
    p.category,
    SUM(oi.quantity) AS total_quantity_sold,
    SUM(oi.quantity * oi.unit_price) AS total_revenue
  FROM order_items oi
  JOIN products p ON p.id = oi.product_id
  GROUP BY p.category
)
SELECT
  cp.category,
  cp.product_cnt,
  COALESCE(cs.total_quantity_sold, 0) AS total_quantity_sold,
  COALESCE(cs.total_revenue, 0) AS total_revenue
FROM category_products cp
LEFT JOIN category_sales cs ON cs.category = cp.category
ORDER BY total_revenue DESC, cp.category;`}
/>

### 练习 11：用户消费分层

目标：按用户的历史总消费额分层，输出 `user_name, total_spent, tier`：

- 总消费 >= 1000：`'高消费'`
- 总消费 >= 500 且 < 1000：`'中消费'`
- 总消费 < 500：`'低消费'`
- 从未消费：`'未消费'`

要求：按 `total_spent` 降序。

<SqlSimulator
  dataset="commerce"
  description="涉及表：users、orders、order_items"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH user_spending AS (
  SELECT
    u.id AS user_id,
    u.name AS user_name,
    COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS total_spent
  FROM users u
  LEFT JOIN orders o ON o.user_id = u.id
  LEFT JOIN order_items oi ON oi.order_id = o.id
  GROUP BY u.id
)
SELECT
  user_name,
  total_spent,
  CASE
    WHEN total_spent >= 1000 THEN '高消费'
    WHEN total_spent >= 500 THEN '中消费'
    WHEN total_spent > 0 THEN '低消费'
    ELSE '未消费'
  END AS tier
FROM user_spending
ORDER BY total_spent DESC, user_name;`}
/>

### 练习 12：月度趋势报表

目标：输出每个月的报表，字段如下：

- `month`（格式 `YYYY-MM`，用 `strftime('%Y-%m', order_date)`）
- `order_cnt`（当月订单数）
- `revenue`（当月订单金额，基于 order_items）
- `revenue_cum`（累计到当月的总收入）

要求：按 `month` 升序。

<SqlSimulator
  dataset="commerce"
  description="涉及表：orders、order_items"
  defaultQuery="-- 在此输入你的 SQL 查询"
  answerSql={`WITH monthly AS (
  SELECT
    strftime('%Y-%m', o.order_date) AS month,
    COUNT(DISTINCT o.id) AS order_cnt,
    SUM(oi.quantity * oi.unit_price) AS revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  GROUP BY strftime('%Y-%m', o.order_date)
)
SELECT
  month,
  order_cnt,
  revenue,
  SUM(revenue) OVER (ORDER BY month) AS revenue_cum
FROM monthly
ORDER BY month;`}
/>

## 结尾建议

如果你能把这 12 道题都独立写出来，你的 SQL 已经能覆盖大多数复杂业务分析与报表需求。你已经掌握了三个核心武器：

1. **CTE**：把复杂查询拆成可读、可维护的步骤
2. **窗口函数**：排名、Top-N、累计、分组内计算——不改变行数，附加计算结果
3. **综合报表**：多维度指标、分层分析、趋势分析——CTE + JOIN + 聚合 + 窗口函数的组合

到这里，你已经走完了"会写正确 SQL"的全部训练。但真实生产中，能跑出正确结果只是及格线——数据量上来后，**同一个结果可能有 10 倍甚至 100 倍的性能差异**。

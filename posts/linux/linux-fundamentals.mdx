# 深入浅出 Linux

在当今的计算机世界中，Linux 无处不在。从你口袋里的 Android 手机，到支撑互联网的超级服务器，不仅如此，这一操作系统还运行在许多智能家居设备上。那么，Linux 到底是什么？为什么它如此重要？

本文将带你从零开始，系统地掌握 Linux——不只是"认识"它，而是真正**能用命令行驾驭它**。我们会按照这样的路径推进：

1. 先搞清楚 Linux 是什么、怎么选发行版
2. 理解文件系统和基础命令——能"看见"和"操作"文件
3. 掌握权限管理——能"控制"谁能做什么
4. 学会重定向和管道——让命令**协同工作**
5. 掌握文本处理三剑客——能高效处理日志和数据
6. 管理进程和系统资源——能监控和控制系统运行

---

## 1. 什么是 Linux？

简单来说，**Linux** 是一个开源的类 Unix 操作系统内核。通常我们所说的 "Linux"，实际上是指 **Linux 内核** 加上各种 **GNU 工具**、桌面环境和应用程序组成的完整操作系统，更准确的说法应该是 **GNU/Linux**。

### 为什么它如此特别？

*   **开源生态**：Linux 内核采用开源许可证发布，任何人都可以在许可证允许的范围内查看、修改和分发源代码；完整发行版还包含采用不同许可证的软件。
*   **稳定高效**：Linux 能够长期稳定运行并有效利用硬件资源，但仍需及时安装安全更新；内核或关键组件升级后可能需要重启。
*   **安全机制完善**：用户、组、权限、进程隔离和安全模块可以限制风险范围，但安全仍依赖补丁、配置、最小权限和日常运维，不能简单理解为“不会中病毒”。
*   **高度可定制**：从内核功能、系统服务到桌面环境，都可以根据服务器、桌面或嵌入式场景进行取舍。

## 2. Linux 发行版（Distributions）

由于 Linux 内核是开源的，任何人都可以将其打包成一个操作系统。这就诞生了各种各样的"发行版"。

你可以把 Linux 内核想象成汽车的引擎，而发行版就是不同品牌的汽车——有的追求速度（服务器），有的追求舒适（桌面），有的追求极简。

### 常见的发行版：

| 发行版 | 特点 | 适用人群 |
| :--- | :--- | :--- |
| **Ubuntu** | 基于 Debian，发布节奏明确，资料和社区丰富 | 初学者、桌面用户、服务器开发者 |
| **Debian** | 重视稳定性和自由软件原则，Stable 分支更新相对保守 | 服务器、希望稳定维护的用户 |
| **RHEL** | 提供企业订阅、长期维护和厂商支持 | 企业生产环境、系统管理员 |
| **CentOS Stream** | 持续交付，位于 Fedora 与下一版 RHEL 之间；不同于已经结束生命周期的 CentOS Linux | 希望提前验证 RHEL 相关变化的开发和测试环境 |
| **Arch Linux** | 滚动更新、高度自定义，文档丰富 | 愿意自行配置和维护系统的进阶用户 |
| **Alpine** | 极其轻量，安全 | 容器化（Docker）、嵌入式设备 |

## 3. Linux 文件系统：一切皆文件

在 Windows 中，我们习惯了 C 盘、D 盘的概念。但在 Linux 中，**没有盘符**。

Linux 的文件系统是一个树状结构，所有的文件和目录都从根目录 `/` 开始。

### 核心目录结构解析

Linux 发行版通常会按照**文件系统层次结构标准**（Filesystem Hierarchy Standard，FHS）组织目录。不同发行版和服务器镜像可能略有差异，但下面这些目录通常由系统安装程序、文件系统或系统服务创建，而不是某位用户随意建立的：

| 目录 | 主要用途 |
| :--- | :--- |
| `/` | **根目录（Root）**，整个文件系统树的起点，其他磁盘和文件系统也会挂载到这棵树中。 |
| `/bin` | 启动和基本操作所需的常用命令，如 `ls`、`cp` 和 `sh`。现代发行版中它通常是指向 `/usr/bin` 的符号链接。 |
| `/sbin` | 系统管理命令，如 `fsck`、`reboot`。现代发行版中通常链接到 `/usr/sbin`。 |
| `/boot` | 内核、初始内存文件系统和引导加载器等启动文件。不要随意删除其中的内容。 |
| `/dev` | 设备文件目录，磁盘、终端和空设备等会表现为 `/dev/sda`、`/dev/tty`、`/dev/null` 这样的文件。其内容主要由系统动态管理。 |
| `/etc` | 系统级配置目录，例如用户信息、网络和服务配置。它与 Windows 注册表承担了部分相似职责，但由许多独立的文本配置文件组成。 |
| `/home` | 普通用户的家目录。例如用户 `alice` 的家目录通常是 `/home/alice`。 |
| `/root` | 超级管理员 `root` 的家目录；它不是根目录 `/`。 |
| `/lib`、`/lib64` | 基本命令和系统启动所需的共享库、内核模块。现代发行版中可能分别链接到 `/usr/lib`、`/usr/lib64`。 |
| `/usr` | 大部分用户空间程序、库、文档和共享资源所在的位置，常见子目录包括 `/usr/bin`、`/usr/lib` 和 `/usr/share`。这里的名称是历史沿用，并不是普通用户的家目录。 |
| `/var` | 经常变化的数据，如 `/var/log` 日志、缓存、队列和部分服务数据。 |
| `/tmp` | 公共临时文件目录。文件可能在重启后或由定时清理策略删除，因此不能用来长期保存数据。 |
| `/run` | 本次开机期间的运行时数据，如 PID 文件、套接字和服务状态；通常位于内存文件系统中，重启后重新生成。 |
| `/proc` | 由内核提供的虚拟文件系统，用文件形式展示进程和内核信息。例如 `/proc/cpuinfo`；它并不占用普通磁盘空间。 |
| `/sys` | 由内核提供的虚拟文件系统，用于展示和配置设备、驱动及内核对象。 |
| `/mnt` | 管理员临时挂载磁盘或文件系统时使用的通用目录。 |
| `/media` | U 盘、光盘等可移动介质的常见自动挂载位置。服务器上即使暂未使用也可能存在。 |
| `/opt` | 可选的第三方软件通常安装在这里，例如 `/opt/example-app`。目录本身可能由系统创建，里面的软件不一定是系统自带的。 |
| `/srv` | FTP、Web 等服务对外提供的数据可以放在这里，但许多发行版默认不会使用它。 |
| `/lost+found` | ext 系列文件系统通常在格式化时创建。文件系统修复工具会把找回但无法确定原路径的数据放到这里。每个独立文件系统都可能有自己的 `lost+found`。 |

`/proc`、`/sys`、`/dev` 和 `/run` 中的许多内容会由内核或系统服务动态生成；看到它们发生变化并不意味着有人手动修改了服务器。

:::tip 本节先建立目录地图
表格里出现了一些还没有学过的系统术语和命令名称。现阶段只需要知道这些标准目录各自大致存放什么，不需要立即操作它们。等第 4 章介绍命令、选项和路径后，我们会用安全的只读命令回来观察目录。
:::

:::note 标准目录不等于“其中的内容全部自带”
`/opt`、`/srv`、`/mnt` 等目录可以由系统预先创建，但其内部内容往往来自管理员、部署脚本或后来安装的软件。反过来，`/afs` 可能由 OpenAFS 软件创建，`/share`、`/usrapp` 和类似 `koc-python.bak.20260422104146` 的带时间备份目录也不是通用的 Linux 标准根目录。仅凭名称无法确认创建者，学习完后面的命令后才能进一步检查。
:::

> **理解关键**：在 Linux 中，设备、进程信息和系统配置等资源都可以通过类似文件的统一接口访问。这种“一切皆文件”的设计让命令和工具能够以一致的方式协同工作。

## 4. 终端与常用命令

图形界面（GUI）虽然直观，但服务器通常没有桌面环境，因此命令行（CLI）是 Linux 管理中最常用的交互方式。开始输入命令前，先区分三个概念：

- **终端（Terminal）**：显示文字并接收键盘输入的窗口。
- **Shell**：运行在终端中的命令解释器。它读取你输入的文字，处理引号、路径和重定向等语法，再启动相应程序；Bash 是常见 Shell 之一。
- **命令（Command）**：让计算机执行某项操作的指令，例如列出目录、复制文件。命令可能是独立程序，也可能是 Shell 自带功能。

它们的关系可以简单理解为：**你在终端中输入命令，Shell 负责解释并执行。**

### 4.1 命令、选项与参数

一条命令通常可以写成下面的结构：

```text
命令 [选项] [参数]
```

方括号表示该部分通常可以省略，并不是要原样输入。以“列出目录内容”的 `ls` 命令为例：

```bash
ls -la /var/log
```

这里的 `ls` 是命令，`-l` 和 `-a` 是选项，`/var/log` 是要操作的路径参数。短选项经常可以合并，所以 `-la` 相当于 `-l -a`，但并非所有命令都支持合并。

Shell 会先识别引号等语法，再进行变量、通配符等展开，最终得到要交给命令的参数。对初学者最重要的规则是：普通空格用于分开参数；如果一个参数自身包含空格，就要用引号把它包起来。下面先认识两个马上会用到的命令：`mkdir` 用于创建目录，`cd` 用于切换当前目录。

```bash
mkdir "project notes"   # 创建一个名称中包含空格的目录
cd "project notes"      # 引号保证 project notes 是一个完整参数
cd ..                    # 回到上一级目录
```

如果文件名以 `-` 开头，命令可能误把它识别成选项。许多命令支持用 `--` 表示“选项到此结束，后面的内容都是普通参数”。后面的安全练习会展示具体用法。

### 4.2 绝对路径与相对路径

以 `/` 开头的是**绝对路径**，无论当前在哪个目录，都指向同一个位置。没有以 `/` 开头的是**相对路径**，它基于当前工作目录解析。路径中还有几个常见简写：

- `.`：当前目录，例如 `./notes.txt` 是当前目录下的 `notes.txt`。
- `..`：当前目录的上一级目录。
- `~`：由 Shell 展开成当前用户的家目录。
- `*`：通配符，由 Shell 展开成匹配的路径名；默认不会匹配以 `.` 开头的隐藏名称。

```bash
pwd             # 显示当前工作目录
cd /var/log     # 绝对路径：进入固定的 /var/log
cd ..           # 相对路径：进入当前目录的上一级
cd ~            # 回到当前用户的家目录
cd -            # 回到上一次所在的目录；这里的 - 是 cd 的特殊参数
```

路径开头的 `.` 和隐藏文件开头的 `.` 要结合位置判断：单独的 `.` 表示当前目录，而 `.env` 表示名称为 `.env` 的隐藏文件。

`ls` 用于列出目录内容：

```bash
ls              # 当前目录中的非隐藏项目
ls -a           # 包括以 . 开头的隐藏项目
ls -l           # 长格式：权限、所有者、大小、时间等
ls -lh          # 在长格式中把大小显示为 KiB、MiB 等易读单位
```

### 4.3 创建、复制、移动与删除

下面的练习只操作家目录中的 `linux-demo`，可以完整执行。先认识即将使用的命令和选项：

- `mkdir` 创建目录；`-p` 会一并创建缺失的父目录，并允许目标目录已经存在。
- `touch` 在文件不存在时创建空文件；文件已存在时主要更新时间信息。
- `printf` 按指定格式输出文字。格式字符串 `'%s\n'` 中，`%s` 接收后面的字符串参数，`\n` 表示换行。
- `cp` 复制文件，`cp -r` 会递归进入子目录并复制整个目录树。
- `mv` 移动文件，也可以在同一目录中完成重命名。
- `rm` 删除文件，`rmdir` 只能删除空目录。

```bash
# 在家目录中创建 linux-demo/docs 两级目录并进入 linux-demo
mkdir -p ~/linux-demo/docs
cd ~/linux-demo

# 创建空文件
touch notes.txt

# printf 产生一行文字；> 把文字写入 notes.txt，文件已存在时会先清空
# 第 7 章会从标准输出的角度完整解释 >
printf '%s\n' 'Hello Linux' > notes.txt

# 复制文件
cp notes.txt notes-backup.txt

# -r 表示递归复制 docs 及其内部内容
cp -r docs docs-copy

# 把 notes-backup.txt 重命名为 archive.txt
mv notes-backup.txt archive.txt

# 删除文件；-- 表示后面不再是选项
rm -- archive.txt

# 演示删除以 - 开头的文件名：先创建，再用 -- 安全删除
touch -- -example.txt
rm -- -example.txt

# rmdir 只能删除空目录
rmdir docs

# -r 表示递归删除目录及内容；这里只删除刚创建的练习副本
rm -r -- docs-copy
```

:::note 复制目录时要观察目标是否已经存在
当 `folder2` 不存在时，`cp -r folder1 folder2` 会创建名为 `folder2` 的副本；当 `folder2` 已经是目录时，通常会复制成 `folder2/folder1`。执行复制或移动前，可以先用 `ls -ld folder2` 检查目标。
:::

`rm` 默认不会把文件放入回收站。尤其是 `rm -rf`：`-r` 会递归处理整个目录树，`-f` 会跳过大部分确认和不存在提示。使用前应先执行 `pwd` 和 `ls` 核对位置，不要把 `rm -rf` 当成普通删除方式。

### 4.4 查看文件内容

`cat`、`less`、`head` 和 `tail` 都能查看文本，但读取范围和交互方式不同：

| 命令 | 默认行为 | 是否分页 | 典型场景 |
| :--- | :--- | :--- | :--- |
| `cat` | 把整个文件一次输出到终端 | 否 | 快速查看小文件、依次输出多个文件 |
| `less` | 在分页界面中阅读文件 | 是 | 阅读和搜索大文件 |
| `head` | 输出文件开头 10 行 | 否 | 查看表头或配置文件开头 |
| `tail` | 输出文件结尾 10 行 | 否 | 查看最新日志；配合 `-f` 持续跟踪 |

先创建一个 30 行的练习文件。`seq 1 30` 会按顺序输出数字 1 到 30，每个数字一行；`>` 再把这些输出写入 `lines.txt`：

```bash
seq 1 30 > lines.txt
```

然后分别观察四个命令：

```bash
cat lines.txt          # 1～30 行一次全部输出
less lines.txt         # 进入分页界面，不会把所有内容刷过终端
head lines.txt         # 默认输出前 10 行
tail lines.txt         # 默认输出后 10 行
```

在 `less` 中可以使用以下按键：

- `↑`、`↓`：逐行移动。
- `Space`：向下翻一页，`b`：向上翻一页。
- `/关键字`：向下搜索，`n`：跳到下一个匹配结果。
- `q`：退出 `less`。

#### `-n`：指定显示多少行

在 `head` 和 `tail` 中，`-n` 是 `--lines` 的短写，后面需要一个数字：

```bash
head -n 20 lines.txt   # 从开头取 20 行
head -n 1 lines.txt    # 只取第 1 行
tail -n 20 lines.txt   # 从结尾取 20 行
tail -n 1 lines.txt    # 只取最后 1 行
```

选项字母的含义由具体命令决定，并不是全局统一的。例如 `head -n 5` 中的 `-n` 表示输出 5 行，而 `cat -n file.txt` 中的 `-n` 表示给输出添加行号。遇到陌生选项可以使用以下方式查询：

```bash
head --help   # 在终端直接显示 head 的简要帮助
man head      # 打开 head 的手册页；按 / 搜索，按 q 退出
```

#### `-f`：持续跟踪文件末尾

`tail -f` 中的 `-f` 是 `--follow` 的短写。它先显示文件末尾，然后保持运行；文件追加新内容时，终端会立即显示新增部分。这适合观察正在写入的日志。

可以打开两个终端进行练习。在终端 A 中运行：

```bash
printf '%s\n' 'server started' > app.log
tail -n 20 -f app.log
```

`-n 20 -f` 表示“先显示最后 20 行，再持续跟踪”。然后在终端 B 中追加一行：

```bash
printf '%s\n' 'new request' >> app.log
```

终端 A 会立即出现 `new request`。`tail -f` 不会自行退出，需要按 `Ctrl+C` 停止。`Ctrl+C` 通常会请求当前前台任务中断运行，并不是 `tail` 独有的按键；进程和信号会在第 10 章介绍。这里的 `>>` 表示追加而不是覆盖，第 7 章会完整解释 `>`、`>>` 和错误输出重定向。

系统日志位置因发行版而异：Debian/Ubuntu 常见 `/var/log/syslog`，RHEL 系常见 `/var/log/messages`。`journalctl` 是查看 systemd 日志的命令；不同系统可能采用文件日志、systemd 日志或同时使用两者。

### 4.5 `sudo`：临时使用管理员权限

普通用户通常不能修改系统文件或安装软件。`sudo` 会在当前账号获得授权的前提下，以管理员身份执行它后面的**一条命令**，并且可能要求输入当前用户的密码：

```bash
sudo journalctl       # 以管理员权限查看 systemd 日志
```

并不是每个账号都有使用 `sudo` 的权限。执行前必须确认后面的命令及参数，因为管理员权限可以修改或删除系统关键数据。后文出现 `sudo chmod ...` 或 `sudo apt ...` 时，真正执行权限修改或软件安装的是 `sudo` 后面的命令。

### 4.6 回到第 3 章：只读观察系统目录

现在已经认识命令、选项和路径，可以用下面的只读命令观察第 3 章中的系统目录：

```bash
# ls -l 使用长格式，-d 表示查看目录项本身，而不是列出目录内部
ls -ld /bin /proc /usr /var /lost+found

# readlink 查看符号链接，-f 会沿链接逐层解析并输出最终路径
readlink -f /bin
readlink -f /sbin

# findmnt 查看挂载关系；--target 指定要查询的路径
findmnt --target /proc
findmnt --target /sys
findmnt --target /dev
```

这些命令只读取信息。`readlink -f /bin` 如果输出 `/usr/bin`，表示 `/bin` 最终指向 `/usr/bin`；`findmnt` 输出中的 `TARGET` 是挂载位置，`FSTYPE` 是文件系统类型。更深入的符号链接和磁盘挂载知识可以留到后续系统管理章节。

## 5. 权限管理：Linux 安全的基石

Linux 会记录文件的所有者、所属组和权限。权限决定某个进程能否读取、修改或执行文件，但它不是在文件名之间插入几个分隔符，而是一组**位置固定的标志位**。

### 5.1 逐位读懂 `-rwxr-xr--`

假设 `ls -l script.sh` 输出：

```text
-rwxr-xr-- 1 alice devs 1234 Feb 8 10:20 script.sh
```

第一个字段共有 10 个字符，可以这样拆分：

```text
-  rwx  r-x  r--
│   │    │    └── 其他用户（Others）的权限
│   │    └─────── 所属组（Group）的权限
│   └──────────── 所有者（User）的权限
└──────────────── 文件类型
```

第一位表示文件类型，不属于三组权限：

| 字符 | 类型 |
| :--- | :--- |
| `-` | 普通文件 |
| `d` | 目录 |
| `l` | 符号链接 |
| `c` / `b` | 字符设备 / 块设备 |

后面 9 位才是权限，每 3 位一组，而且顺序固定为 `rwx`：

1. 第 2～4 位：所有者 `alice` 的权限
2. 第 5～7 位：所属组 `devs` 的权限
3. 第 8～10 位：其他用户的权限

`r`、`w`、`x` 分别表示读取、写入和执行；`-` 并不是分隔符，而是表示这个固定位置上的权限没有授予。因此：

- `rwx`：可读、可写、可执行。
- `r-x`：可读、不可写、可执行。
- `r--`：只能读取。
- `---`：这组三种权限都没有。

示例中的三个 `r` 含义都是“读取”，只是分别授予所有者、组成员和其他用户。Linux 会根据访问者的身份选择对应的一组进行判断，而不是把三组权限相加。

完整输出中的其余字段依次是硬链接数、所有者、所属组、字节大小、最后修改时间和文件名：

```text
权限         链接数  所有者  组     大小  修改时间         名称
-rwxr-xr--   1      alice   devs   1234  Feb 8 10:20    script.sh
```

这里的 `alice` 和 `devs` 只是示例名称，并不是 Linux 固定使用的单词：

- `alice` 代表这个示例中的用户名，也就是文件所有者。
- `devs` 代表这个示例中的用户组名。
- 你的服务器可能使用 `ecs-user`、`root`、`www-data`、`nginx` 等其他名称。

Linux 内部主要使用数字 UID（用户 ID）和 GID（组 ID）记录归属，`ls -l` 会把它们解析为更易读的用户和组名称。

### 5.2 文件和目录的 `rwx` 并不完全相同

| 权限 | 用在普通文件上 | 用在目录上 |
| :--- | :--- | :--- |
| `r` | 读取文件内容 | 列出目录中的名称 |
| `w` | 修改或清空文件内容 | 在目录中创建、删除或重命名项目 |
| `x` | 请求把文件作为程序执行 | 进入或穿过目录，并访问其中已知名称的项目 |

一个常见误区是：删除文件主要检查的不是文件自身的 `w`，而是其**父目录**是否允许 `w+x`。除此之外，root 特权、ACL、只读挂载、SELinux/AppArmor 等机制也可能影响最终结果；`ls -l` 展示的是最基础的一层权限。

### 5.3 `rwx`、`ls`、`chmod` 和 `chown` 的关系

`rwx` 不是 `chmod` 命令独有的内容，而是文件系统保存的基础**权限位**。几个概念的分工如下：

| 名称 | 作用 | 是否直接修改 `rwx` |
| :--- | :--- | :--- |
| `rwx` | 描述所有者、所属组和其他用户能做什么 | 它本身就是权限状态 |
| `ls -l` | 查看权限、所有者和所属组 | 否 |
| `chmod` | 修改 `rwx` 权限位 | 是 |
| `chown` | 修改文件属于哪个用户、哪个组 | 否 |
| Linux 内核 | 用户访问文件时，根据身份检查对应的权限 | 否 |

新文件创建时就已经有初始权限，通常由程序请求的权限和 `umask` 共同决定。`umask` 是一组用于屏蔽部分默认权限的设置；现阶段只需知道它会影响新文件的初始权限，并不需要先运行 `chmod` 才会出现 `rwx`。具体计算规则可以留到 Shell 脚本章节。

例如，文件最初是：

```text
-rw-r----- 1 alice devs 100 Feb 8 10:20 report.txt
```

运行 `chmod u+x report.txt` 后，只有权限改变：

```text
-rwxr----- 1 alice devs 100 Feb 8 10:20 report.txt
```

运行 `sudo chown bob:ops report.txt` 后，权限位本身不变，但所有者和组发生变化：

```text
-rwxr----- 1 bob ops 100 Feb 8 10:20 report.txt
```

此时第一组 `rwx` 改为适用于 `bob`，第二组 `r--` 改为适用于 `ops` 组成员。因此，`chown` 虽然没有修改权限位，却可能改变实际由谁获得这些权限。

可以把它们记成一句话：**`rwx` 说明有哪些权限，`chmod` 修改权限，`chown` 修改权限作用于谁，`ls -l` 负责查看。**

### 5.4 使用 `chmod` 修改权限

`chmod` 支持符号模式。`u`、`g`、`o`、`a` 分别表示所有者、所属组、其他用户和所有人，`+`、`-`、`=` 分别表示添加、移除和精确设置：

```bash
chmod u+x script.sh    # 只给所有者添加执行权限
chmod g-w report.txt   # 移除所属组的写权限
chmod o=r report.txt   # 其他用户精确设置为只读
chmod a+x script.sh    # 明确给所有人添加执行权限
```

不要把 `chmod +x` 简单理解为“给所有人添加执行权限”：省略身份类别时，具体结果还会受到 `umask` 等规则影响。教程或脚本中最好明确写出 `u` 或 `a`。

数字模式中，每一位分别对应所有者、所属组和其他用户；每位由 `r=4`、`w=2`、`x=1` 相加：

```text
7 = 4 + 2 + 1 = rwx
6 = 4 + 2     = rw-
5 = 4     + 1 = r-x
4 = 4         = r--
0             = ---
```

因此常见设置可以这样读取：

```bash
chmod 755 script.sh    # rwxr-xr-x：所有者可写，所有人可读和执行
chmod 644 article.txt  # rw-r--r--：所有者可写，其他人只读
chmod 600 secret.txt   # rw-------：只有所有者可读写
```

不要用 `chmod 777` 作为通用的权限修复方法，因为它允许所有用户修改文件，往往扩大了安全风险。

### 5.5 使用 `chown` 修改归属

`chown` 的基本结构是：

```text
chown 用户名:用户组名 文件
```

冒号左边是新的所有者，右边是新的所属组。用户名和组名必须以当前系统中真实存在的名称为准；下面的 `alice` 和 `devs` 仍然只是占位示例：

```bash
sudo chown alice:devs file.txt  # 所有者改为 alice，所属组改为 devs
sudo chown alice file.txt       # 只修改所有者，原所属组保持不变
sudo chown :devs file.txt       # 只修改所属组，原所有者保持不变
sudo chgrp devs file.txt        # 也可以用 chgrp 只修改所属组
```

可以先查询当前机器上的真实身份：

```bash
whoami              # 显示当前用户名，例如 ecs-user
id                   # 显示当前用户的 UID、主要 GID 和全部所属组
id -gn               # -g 选择主要组，-n 把数字 GID 显示成组名
id ecs-user          # 查询 ecs-user；请替换成实际存在的用户名
```

假设 `whoami` 输出 `ecs-user`，而 `id -gn` 也输出 `ecs-user`，那么使用真实名称的命令是：

```bash
sudo chown ecs-user:ecs-user file.txt
```

如果系统中不存在 `alice` 或 `devs`，直接复制示例命令会出现 `invalid user` 或 `invalid group` 等错误。修改后应再次检查：

```bash
ls -l file.txt
```

普通用户通常可以修改自己文件的权限；把文件所有权转交给其他用户通常需要管理员权限，因此 `chown` 经常需要 `sudo`。

## 6. 软件管理

Linux 通常通过**软件仓库**和**包管理器**安装软件：

- **软件包**：程序及其版本、文件清单和安装信息组成的发布单元。
- **仓库**：集中保存软件包的服务器。
- **软件包索引**：本机保存的仓库目录，记录有哪些软件和版本；刷新索引不等于升级软件。
- **依赖**：某个软件运行时还需要的其他软件包，包管理器会帮助解析和安装。
- **签名**：用于验证软件包来源和内容是否被篡改。

下面用 Nginx 这个常见 Web 服务器软件包演示。应使用发行版或可信厂商提供的仓库，不要随意添加来源不明的软件源。

### Debian/Ubuntu 系列（APT）

```bash
# 只刷新本机的软件包索引，不会升级已经安装的软件
sudo apt update

# 安装或升级指定软件包
sudo apt install nginx

# 卸载程序，但通常保留系统级配置文件
sudo apt remove nginx

# 连配置文件一起清除前，应先确认这些配置不再需要
sudo apt purge nginx
```

### RHEL、CentOS Stream、Fedora 系列（DNF）

```bash
sudo dnf search nginx   # 搜索仓库
sudo dnf install nginx  # 安装
sudo dnf remove nginx   # 卸载
```

较旧的 RHEL/CentOS 使用 `yum`；一些较新的系统仍提供 `yum` 兼容入口，但应以当前发行版文档为准。CentOS Linux 与 CentOS Stream 也不是同一个发布模式。

### Arch Linux（pacman）

`pacman` 的 `-S` 表示同步仓库并操作软件包，组合在一起的 `y` 表示刷新软件包数据库，`u` 表示升级所有可更新的软件包：

```bash
# 刷新数据库、完整升级系统，并把 nginx 作为目标软件包安装
sudo pacman -Syu nginx
```

以上是 Linux 的“地基”——文件系统、基础命令和权限。接下来，我们要进入命令行的核心能力：**让命令协同工作**。

## 7. 深入理解 I/O 重定向

可以把一个正在运行的程序想象成默认连接了三条“通道”：一条接收输入，两条发送输出。数字 `0`、`1`、`2` 是这些通道的固定编号，正式名称是**文件描述符**（File Descriptor，FD），不是错误数量或状态码。

```text
终端输入 ──────> [ 0：stdin  程序读取数据 ]
                 [ 1：stdout 正常结果     ] ──────> 终端
                 [ 2：stderr 错误与诊断   ] ──────> 终端
```

| FD | 名称 | 常见默认连接位置 | 用途 |
| :--- | :--- | :--- | :--- |
| `0` | stdin，标准输入 | 终端键盘 | 程序读取的数据 |
| `1` | stdout，标准输出 | 终端屏幕 | 正常结果 |
| `2` | stderr，标准错误 | 终端屏幕 | 错误和诊断信息 |

stdout 和 stderr 默认都显示在同一个终端，所以肉眼看起来没有区别，但它们实际上是两条独立通道。**重定向**就是让某条通道不再连接默认位置，改为连接文件、管道或其他设备。

### 7.1 `>`：把正常输出覆盖写入文件

`>` 默认操作编号为 `1` 的 stdout：

```bash
printf '%s\n' 'Hello Linux' > result.txt
```

它等价于显式写出编号 `1`：

```bash
printf '%s\n' 'Hello Linux' 1> result.txt
```

Shell 会先创建 `result.txt`；如果文件已经存在，就先**清空原内容**，然后让 `printf` 的正常输出写入该文件，而不是显示在终端。因此可以把 `>` 简记为“覆盖写入”，但更准确地说，它是在改变 stdout 的去向。

可以通过下面的实验观察覆盖效果：

```bash
printf '%s\n' 'old content' > result.txt
printf '%s\n' 'new content' > result.txt
cat result.txt
# 只输出 new content，old content 已被覆盖
```

即使命令没有产生正常输出，Shell 仍可能创建或清空目标文件，因为重定向发生在命令运行之前。

如果要保留旧内容并写到文件末尾，应使用 `>>`：

```bash
printf '%s\n' 'first line' > result.txt
printf '%s\n' 'second line' >> result.txt
cat result.txt
# first line
# second line
```

### 7.2 `1` 和 `2`：正常输出与错误输出

使用已经学过的 `ls` 就能同时观察两条输出通道。下面让它查看一个通常存在的文件和一个特意写成不存在的路径：

```bash
ls /etc/passwd /not-exist
```

`/etc/passwd` 的文件名属于正常结果，进入 stdout；“无法访问 `/not-exist`”属于诊断信息，进入 stderr。两条消息默认都显示在终端。

如果只使用 `>`：

```bash
ls /etc/passwd /not-exist > normal.log
```

此时：

```text
1（/etc/passwd 的正常结果）──────> normal.log
2（/not-exist 的错误消息）────────> 终端
```

如果只使用 `2>`：

```bash
ls /etc/passwd /not-exist 2> error.log
```

则结果相反：

```text
1（正常结果）──────> 终端
2（错误消息）──────> error.log
```

所以 `2` 不是“发生了两个错误”，而是 stderr 这条通道的编号。

### 7.3 逐步拆解 `2>&1`

`2>&1` 可以分成三部分理解：

```text
2  >  &1
│     │
│     └── 文件描述符 1 当前指向的位置
└──────── 文件描述符 2
```

它的含义是：**让 stderr（FD 2）指向 stdout（FD 1）此刻所指向的位置。** `&` 表明后面的 `1` 是文件描述符编号，而不是文件名。

因此，下面这条可运行的命令会让 stdout 和 stderr 都写入 `all.log`。这里假设 `/not-exist` 不存在：

```bash
ls /etc /not-exist > all.log 2>&1
```

Shell 会从左向右处理：

1. `> all.log` 等价于 `1> all.log`，先让 stdout 指向文件。
2. `2>&1` 再让 stderr 跟随 stdout 当前的位置。

最终结构是：

```text
1（stdout）──────> all.log
2（stderr）──────> all.log
```

查看文件即可确认两类消息都被保存：

```bash
ls /etc/passwd /not-exist > all.log 2>&1
cat all.log
# 内容同时包含 /etc/passwd 的正常结果和 /not-exist 的错误消息
```

注意下面少了 `&` 的写法含义完全不同：

```bash
ls /not-exist 2>1
```

它会把 stderr 写入一个名字就叫 `1` 的普通文件，而不是让 FD 2 跟随 FD 1。

### 7.4 如果没有错误，FD 2 会怎样？

重定向只是在提前连接通道，不会凭空制造错误。如果程序没有向 stderr 写入内容，那么 FD 2 就没有数据可写，文件中也不会多出任何内容：

```bash
printf '%s\n' '执行成功' > all.log 2>&1
cat all.log
# 只有“执行成功”
```

这个过程可以理解为：

```text
1 产生“执行成功”──────> all.log
2 没有产生内容────────> 什么也不写
```

但“stderr 没有内容”并不一定表示命令成功。命令是否成功由独立的**退出状态**表示，`$?` 是 Shell 的特殊参数，可以读取紧邻的上一条命令的退出状态；通常 `0` 表示成功，非 `0` 表示失败。`false` 是专门用于测试的命令：它不输出内容，只返回失败状态。

```bash
false > silent.log 2>&1
printf 'exit status: %s\n' "$?"
# 输出 exit status: 1，但 silent.log 仍然是空文件
```

因此要区分三个概念：

- stdout/stderr：命令输出了什么。
- `>`、`2>`、`2>&1`：这些输出要去哪里。
- 退出状态：命令最终成功还是失败。

### 7.5 为什么重定向顺序很重要？

`2>&1` 会复制 FD 1 **当时**的去向，所以左右顺序不能随意交换。下面两条都是可以直接运行的命令：

```bash
# stdout 先指向文件，stderr 再跟随：正常结果和错误都进入 all.log
ls /etc/passwd /not-exist > all.log 2>&1

# stderr 先跟随原 stdout，随后只有 stdout 改到文件：错误仍显示在终端
ls /etc/passwd /not-exist 2>&1 > out.log
```

第二种写法最终相当于：

```text
1（stdout）──────> out.log
2（stderr）──────> 原来的终端
```

`/dev/null` 是会丢弃写入数据的特殊设备：

```bash
ls /etc /not-exist > /dev/null 2>&1
```

这会隐藏正常输出和错误。只有在明确不需要诊断信息且仍会检查退出状态时才应使用；定时任务和后台服务通常更适合把 stderr 保留到日志。

:::note 教程中的“实际命令”
技术资料有时会用 `command` 表示“请替换成你真正要执行的命令”，例如 `python app.py` 或 `ls /etc`，它不是固定要输入的单词。Bash 确实另有一个名为 `command` 的内建命令，但与这种占位写法不是一回事。本文后续尽量使用能够直接运行的真实命令，避免混淆。
:::

### 7.6 `<` 与 `wc`：从文件读取标准输入

`<` 会让右侧文件连接到程序的 stdin（FD 0）。它不会修改这个输入文件：

```text
names.txt ──────> 0（stdin）──────> wc
```

`wc` 是 **word count** 的缩写，用于统计文本。先创建一个练习文件：

```bash
printf 'hello linux\nsecond line\n' > sample.txt
wc sample.txt
```

默认输出依次是行数、单词数、字节数和文件名：

```text
2 4 24 sample.txt
│ │ │  └── 文件名
│ │ └───── 字节数
│ └─────── 单词数
└───────── 行数
```

常用选项如下：

| 选项 | 含义 | 示例 |
| :--- | :--- | :--- |
| `-l` | 只统计行数（lines） | `wc -l sample.txt` |
| `-w` | 只统计单词数（words） | `wc -w sample.txt` |
| `-c` | 只统计字节数（bytes） | `wc -c sample.txt` |
| `-m` | 只统计字符数（characters） | `wc -m sample.txt` |

直接把文件名交给 `wc` 时，`wc` 知道文件名，所以结果中会带上名称：

```bash
printf 'alpha\nbeta\n' > names.txt
wc -l names.txt
# 输出：2 names.txt
```

通过 `<` 传入内容时，Shell 只把文件内容连接到 stdin，`wc` 不知道输入文件叫什么，因此只显示数量：

```bash
wc -l < names.txt
# 输出：2
```

两种写法统计的是同一份内容，区别只在于 `wc` 是否直接收到了文件名参数。

:::note `wc -l` 实际统计换行符
如果最后一行没有以换行符结束，肉眼看起来虽然有一行，`wc -l` 却可能得到 `0`：

```bash
printf 'hello' > no-newline.txt
wc -l no-newline.txt
# 输出：0 no-newline.txt
```
:::

### 7.7 Here Document

当一条命令需要从 stdin 接收多行内容时，可以使用 Here Document（常简称 heredoc）。`<<` 后面的 `EOF` 是自选的结束标记；Shell 会把两个 `EOF` 之间的多行文字交给 `cat`，而 `>` 再把 `cat` 的输出写入文件：

```bash
cat <<'EOF' > config.ini
[Server]
Port=8080
Host=127.0.0.1
EOF
```

结束位置的 `EOF` 必须独占一行，前后不能有其他字符。标记名称不一定非要叫 `EOF`，只要开头和结尾一致即可。

使用 `<<'EOF'` 时，正文按字面内容传递；使用未加引号的 `<<EOF` 时，Shell 会展开其中的 `$变量` 和命令替换。这些展开规则会在 Shell 脚本文章中进一步介绍。

## 8. 管道、`find` 与批量处理

管道符 `|` 会把左侧命令的 stdout 直接连接到右侧命令的 stdin。数据在命令之间流动，不必先保存成临时文件：

```text
左侧命令 ──stdout──> | ──stdin──> 右侧命令
```

### 8.1 先用已经学过的命令理解管道

下面的 `printf` 产生三个单词，`wc -w` 从 stdin 接收它们并统计单词数：

```bash
printf '%s\n' 'red green blue' | wc -w
# 输出：3
```

也可以把 `cat` 输出的文件内容交给 `less` 分页显示：

```bash
cat lines.txt | less
```

这里用它演示数据流；实际查看单个文件时直接写 `less lines.txt` 更简单。类似地：

```bash
cat lines.txt | wc -l
```

表示由 `cat` 读取文件，再让 `wc -l` 统计行数；直接写 `wc -l lines.txt` 通常更简洁。

stderr 默认不会进入普通管道。例如：

```bash
cat not-exist.txt | wc -l
```

`cat` 的错误消息仍显示在终端，`wc` 没收到正常内容，因此通常输出 `0`。管道的退出状态、`pipefail` 等错误处理规则属于 Shell 脚本进阶内容，会在后续脚本文章中介绍。

### 8.2 `find`：按条件查找文件和目录

`find` 会从指定路径开始，递归检查目录树，并按条件筛选文件或目录。基本结构是：

```text
find 起始路径 [条件] [动作]
```

先创建一个安全的练习目录：

```bash
mkdir -p ~/find-demo/logs
cd ~/find-demo
touch report.txt .hidden.txt logs/app.log logs/debug.txt
```

最简单的写法只有起始路径。`.` 已在第 4 章介绍过，表示当前目录：

```bash
find .
```

`find` 默认递归进入子目录，并打印找到的路径，因此会看到 `.`、当前目录中的文件、`logs` 目录以及 `logs` 中的文件。

常见条件和动作如下：

| 写法 | 含义 |
| :--- | :--- |
| `.` | 从当前目录开始查找 |
| `-maxdepth 1` | 最多检查一层，不进入更深的子目录 |
| `-type f` | 只匹配普通文件（file） |
| `-type d` | 只匹配目录（directory） |
| `-type l` | 只匹配符号链接（link） |
| `-name '*.log'` | 只匹配名称以 `.log` 结尾的项目 |
| `-print` | 输出匹配到的路径 |

例如，只查看当前目录第一层的普通文件：

```bash
find . -maxdepth 1 -type f -print
```

输出会包括 `report.txt` 和 `.hidden.txt`，但不会包括目录 `logs` 或它内部的文件。`find` 不会像普通的 `*` 展开那样自动忽略隐藏文件。

递归查找所有 `.log` 文件：

```bash
find . -type f -name '*.log' -print
```

这里必须注意引号：单引号保护 `*.log`，防止 Shell 提前展开；去掉引号后，Shell 可能先把它替换成当前目录中的名称。保留引号后，模式会原样交给 `find -name`，由 `find` 在整个目录树中匹配。

现在再拆解文件计数命令：

```bash
find . -maxdepth 1 -type f -printf '.' | wc -c
```

执行过程是：

1. `find .` 从当前目录开始。
2. `-maxdepth 1` 只检查当前层。
3. `-type f` 只保留普通文件。
4. `-printf '.'` 每找到一个文件就输出一个英文句点，不输出文件名。
5. `| wc -c` 统计句点占用的字节数；一个句点占 1 字节，因此结果就是文件数量。

假设当前层有 2 个普通文件，`find` 会产生 `..` 两个句点，`wc -c` 最终输出 `2`。`-maxdepth` 和 `-printf` 是 GNU `find` 的功能，在常见 Linux 发行版中可用，但其他 Unix 系统的实现可能不同。

### 8.3 找到以后执行操作：`-exec` 与 `xargs`

批量删除前，第一步永远是用 `-print` 预览：

```bash
find . -type f -name '*.log' -print
```

确认结果只包含练习文件后，可以让 `find` 执行 `rm`：

```bash
find . -type f -name '*.log' -exec rm -- {} +
```

新增部分的含义是：

- `-exec`：对匹配结果执行后面的命令。
- `rm --`：删除文件；`--` 表示后面都是路径参数。
- `{}`：由 `find` 替换成找到的路径。
- `+`：一次向 `rm` 传入尽可能多的路径，减少启动命令的次数。

`xargs` 是另一种把 stdin 内容转换成命令行参数的工具。普通空格和换行无法安全分隔所有合法文件名，因此处理路径时应配合 NUL（空字符）分隔：

```bash
# 先重新创建两个练习日志
touch logs/app.log logs/debug.txt

# -print0 用 NUL 分隔路径；-0 让 xargs 按 NUL 读取
# GNU xargs 的 -r 表示没有输入时不要运行 rm
find . -type f -name '*.log' -print0 | xargs -0 -r rm --
```

:::warning 批量操作先预览
不要直接在重要目录中运行批量删除命令。先使用完全相同的 `find` 条件配合 `-print` 检查结果，再执行 `-exec` 或 `xargs`。如果只是学习 `find`，停留在 `-print` 即可。
:::

## 9. 文本处理三剑客：grep、sed、awk

`grep` 负责筛选行，`sed` 擅长按规则编辑文本流，`awk` 擅长按记录和字段分析数据。它们的价值不在于孤立记忆，而在于能够通过管道组合。

### 9.1 `grep`：按模式筛选行

`grep` 会逐行检查文本，只输出符合模式的行。先认识本节会使用的选项：

| 选项 | 含义 |
| :--- | :--- |
| `-F` | 把模式当作普通固定文字，不解释正则特殊字符 |
| `-i` | 忽略英文字母大小写 |
| `-n` | 在结果前显示原文件行号 |
| `-E` | 使用扩展正则表达式；正则是描述一类文本的模式语法 |
| `-v` | 反选，输出不匹配的行 |
| `-r` | 递归进入子目录搜索 |

下面先创建一个可重复练习的日志：

```bash
cat <<'EOF' > app.log
2026-02-08 INFO server started
2026-02-08 Warning disk usage 80%
2026-02-08 ERROR database unavailable
2026-02-08 DEBUG retry scheduled
EOF

# -F 固定文字，-i 忽略大小写，-n 显示行号；短选项合并为 -Fin
grep -Fin 'error' app.log

# -E 使用扩展正则；引号内的 | 属于正则，表示“或者”，不是 Shell 管道
grep -En 'ERROR|Warning' app.log

# -v 反选：输出不包含 DEBUG 的行
grep -v 'DEBUG' app.log

# 创建子目录和日志副本，再用 -r 递归搜索；-F 和 -n 含义与上面相同
mkdir -p logs
cp app.log logs/copy.log
grep -rFn 'ERROR' logs
```

`grep` 的退出状态也有意义：`0` 表示至少匹配一行，`1` 表示没有匹配，`2` 表示发生错误。因此“没有输出”可能只是没找到，而不一定是命令执行失败。

### 9.2 `sed`：按规则编辑文本流

`sed` 默认把结果写到 stdout，不修改原文件。替换规则 `s/旧/新/g` 可以逐部分读取：`s` 是 substitute（替换）动作，斜杠分隔旧模式和新文字，末尾的 `g` 表示替换**每一行中的全部匹配**；没有 `g` 时通常只替换每行的第一处。

```bash
printf '%s\n' 'Hello World World' | sed 's/World/Linux/g'
# 输出：Hello Linux Linux

printf '%s\n' one two three four five > lines.txt
sed '2,4d' lines.txt
# d 删除第 2～4 行，stdout 中剩下 one 和 five；原文件不变
```

需要原地修改时，应先在普通文件上练习并生成备份：

```bash
printf '%s\n' 'color=blue' > settings.ini
sed -i.bak 's/color=blue/color=green/' settings.ini
cat settings.ini       # color=green
cat settings.ini.bak   # color=blue
```

上例适用于 GNU sed（常见于 Linux）。BSD/macOS 的 `sed -i` 参数规则不同。不要直接拿系统关键配置文件练习原地替换。

### 9.3 `awk`：按记录和字段分析

`awk` 程序的基本结构是 `条件 { 动作 }`。它默认一行是一条记录，以连续空白拆分字段：`$0` 表示整行，`$1` 表示第一个字段，依此类推。命令中的 awk 程序通常放在单引号内，这样 Shell 不会提前把 `$1`、`$2` 当成自己的特殊参数。

```bash
cat <<'EOF' > scores.txt
alice 90 frontend
bob 72 backend
carol 95 backend
EOF

# 对每一行打印第 1 和第 3 个字段
awk '{print $1, $3}' scores.txt

# 只有第 2 个字段大于等于 90 时才执行动作
awk '$2 >= 90 {print $1, $2}' scores.txt

# -F: 把冒号设置为字段分隔符，打印 /etc/passwd 的第 1 个字段
awk -F: '{print $1}' /etc/passwd
```

可以把多个工具串起来统计 `scores.txt` 中每个方向出现的次数。执行前先认识两个新命令：`sort` 按行排序，`uniq` 合并**相邻**的重复行；因此通常先排序，再去重或计数。

```bash
awk '{print $3}' scores.txt | sort | uniq -c | sort -nr
```

这条命令分四步执行：

1. `awk '{print $3}'` 提取第 3 个字段，也就是 `frontend` 或 `backend`。
2. 第一个 `sort` 把相同方向排列到一起，为 `uniq` 做准备。
3. `uniq -c` 合并相邻重复行，并在前面显示出现次数（count）。
4. `sort -nr` 按数值（`-n`）倒序（`-r`）排列计数结果。

基于前面创建的三行数据，结果表示 `backend` 出现 2 次、`frontend` 出现 1 次。

:::note `awk -F,` 不等于完整 CSV 解析器
简单的逗号分隔可以用 `-F,`，但标准 CSV 允许字段被引号包裹并在字段内包含逗号或换行。遇到这类数据时应使用真正的 CSV 解析库。
:::

## 10. 进程与资源管理

**进程（Process）**是一个正在运行的程序实例。每个进程都有一个由系统分配的数字编号，叫作 **PID（Process ID，进程 ID）**。同一个程序可以同时运行多个进程，因此操作进程时不能只看名称，还要确认 PID。

### 10.1 使用 `ps` 和 `top` 观察进程

`ps` 显示进程在执行命令那一刻的快照。常见写法 `ps aux` 使用的是 BSD 风格选项，所以 `aux` 前面没有 `-`：

| 字母 | 含义 |
| :--- | :--- |
| `a` | 显示其他用户与终端关联的进程 |
| `u` | 使用包含用户、CPU、内存等字段的详细格式 |
| `x` | 也包括没有关联终端的进程 |

```bash
ps aux
```

输出通常包含 `USER`（运行用户）、`PID`、`%CPU`、`%MEM`、`STAT`（进程状态）和 `COMMAND`（启动命令）等列。

`top` 会持续刷新进程和系统资源，而不是只显示一次快照：

```bash
top
```

在 `top` 中按 `q` 退出。不同系统也可能安装 `htop` 等替代工具，但它们不一定默认存在。

### 10.2 查找进程并理解信号

`pgrep` 按进程名称查找 PID，`-a` 会同时显示完整命令行：

```bash
pgrep -a nginx
```

如果没有输出，通常表示当前没有名称匹配的进程。获得 PID 后，可以让 `ps` 只查看这个进程：

```bash
# 请把 1234 替换成 pgrep 实际返回的 PID
ps -p 1234 -o pid,user,stat,cmd
```

这里 `-p 1234` 表示只选择 PID 1234，`-o` 表示自行指定输出列；`pid`、`user`、`stat`、`cmd` 分别是进程编号、用户、状态和完整命令。

`kill` 的本质是向 PID 发送**信号**，并不总是立即“杀死”进程：

- **SIGTERM（15）**：默认信号，请求进程退出。程序可以捕获或忽略它，通常会借此保存数据、关闭连接。
- **SIGKILL（9）**：由内核强制终止，程序不能捕获，也没有机会执行用户态清理，只应作为最后手段。
- **SIGHUP（1）**：最初表示终端断开。部分服务约定用它重载配置，但其他程序可能直接退出，不能把它当成通用重载命令。

下面的 `PID` 是占位文字，必须替换为你已经核对过的真实数字；不要原样输入，也不要对不认识的系统进程尝试：

```text
kill -TERM PID     # 请求进程正常退出
ps -p PID          # 等待后再次检查进程是否仍存在
kill -KILL PID     # 只有确认无响应并了解影响后才考虑强制终止
```

正式服务通常应优先使用软件或服务管理器规定的停止、启动和重载方式，而不是直接向陌生 PID 发送信号。

### 10.3 前台、后台与作业控制

前台任务占用当前终端并接收键盘输入。在命令末尾添加 `&`，Shell 会在后台启动任务并立即返回提示符，但进程仍可能与当前终端关联。

`sleep` 是一个等待指定秒数后退出的简单命令，很适合安全练习：

```bash
sleep 300 &    # 在后台等待 300 秒；Shell 会显示作业号和 PID
jobs -l        # 查看当前 Shell 的作业；-l 会额外显示 PID
```

Shell 显示的 `[1]` 表示 1 号作业，后续使用 `%1` 引用它：

```bash
fg %1          # 把 1 号作业切到前台
```

当 `sleep` 回到前台后，按 `Ctrl+Z` 通常会暂停它。然后可以运行：

```bash
bg %1          # 让暂停的 1 号作业在后台继续
fg %1          # 再次切回前台；随后可按 Ctrl+C 结束练习
```

`jobs`、`bg`、`fg` 只管理当前 Shell 会话中的作业，不代表系统里的全部进程。

`nohup` 的名称来自“no hang up”，主要让程序忽略终端断开时常见的 SIGHUP。下面仍用 `sleep` 做无副作用练习：

```bash
nohup sleep 300 > output.log 2>&1 &
```

这条命令还复用了前面学过的后台符号和重定向。`nohup` 不能保证程序崩溃后自动重启，也不能在服务器重启后恢复；长期运行的正式服务应交给 systemd 等服务管理器。

## 总结

从文件系统的树状结构，到基础命令的操作，到权限的严格控制，再到管道、重定向、文本三剑客的组合之力——Linux 体现了一种崇尚**简洁、逻辑与组合**的哲学。

命令行不是用来死记硬背的，而是用来**组合**的：

*   用 `grep` 过滤、用 `sed` 修改文本流、用 `awk` 提取字段，再通过管道连接它们。
*   用 `>` 保存输出，用 `wc` 统计文本，用 `sort` 排序并用 `uniq` 合并重复行。
*   用 `find` 按路径、类型和名称查找项目；批量操作前先通过 `-print` 预览。
*   用 `ps`、`top` 观察进程，用 `jobs`、`bg`、`fg` 管理当前 Shell 的作业。
*   后续《[网络排查与磁盘管理](/posts/linux/networking-and-disk)》会再介绍 `df`、`du` 等磁盘空间命令。

当你开始习惯用管道连接一切时，你就真正掌控了 Linux。下一篇《[Shell 脚本编程](/posts/linux/shell-scripting)》，我们将学会把这些命令串成可复用的脚本，让 Linux 替你自动干活。

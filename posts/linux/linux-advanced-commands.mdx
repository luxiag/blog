# Linux 进阶之路：掌控命令行的艺术

在上一篇《深入浅出 Linux》中，我们已经熟悉了文件系统的导航和基本的 CRUD 操作。但 Linux 真正的威力在于它遵循 Unix 哲学：**编写只做一件事并把它做好的程序；让程序能够协同工作。**

这种协同工作的机制，就是通过**管道（Pipe）**和**重定向（Redirection）**实现的。掌握了它们，你就拥有了无穷的组合能力。

---

## 1. 深入理解 I/O 重定向

在 Linux 中，每个进程启动时都会打开三个标准文件流：

1.  **stdin (标准输入)**：代码 `0`，通常是键盘输入。
2.  **stdout (标准输出)**：代码 `1`，通常是屏幕输出。
3.  **stderr (标准错误)**：代码 `2`，通常也是屏幕输出（但作为独立的流）。

### 1.1 输出重定向

为什么有时候 `>` 无法捕获报错信息？因为它默认自捕获 `stdout`。

```bash
# 1. 覆盖写入 stdout
ls -l > list.txt

# 2. 追加写入 stdout
echo "New Line" >> list.txt

# 3. 只重定向 stderr (错误信息)
rm not_exist_file 2> error.log

# 4. 同时重定向 stdout 和 stderr
# 将 stderr (2) 重定向到 stdout (1) 的位置，然后一起写入文件
command > output.log 2>&1
```

> **实用技巧**：`> /dev/null 2>&1`
> 这是一个非常常见的写法，意思是不显示任何输出（既不显示正常结果，也不显示错误）。`/dev/null` 是 Linux 的黑洞设备。

### 1.2 输入重定向

```bash
# 从文件读入内容作为输入
wc -l < large_file.txt

# Here Document (常用在脚本中生成配置文件)
cat <<EOF > config.ini
[Server]
Port=8080
Host=0.0.0.0
EOF
```

## 2. 管道与命令组合技

管道符 `|` 的作用是将前一个命令的 `stdout` 直接作为下一个命令的 `stdin`。这就像把不同的乐高积木拼在一起。

### 2.1 简单组合

```bash
# 查看进程并分页显示
ps aux | less

# 统计某个目录下的文件数量
ls | wc -l
```

### 2.2 xargs：参数传递神器

很多命令（如 `rm`, `mkdir`, `cp`）不支持从标准输入读取**参数**，它们只接受命令行参数。这时就需要 `xargs`。

```bash
# ❌ 错误：rm 无法从 stdin 读取文件名
find . -name "*.log" | rm

# ✅ 正确：xargs 将 stdin 转换成参数传递给 rm
find . -name "*.log" | xargs rm

# 并行执行（利用多核 CPU 加速）
# -P 4 表示同时启动 4 个进程
find . -name "*.jpg" | xargs -P 4 -I {} convert {} {}.png
```

## 3. 文本处理三剑客：grep, sed, awk

这是 Linux 进阶必须翻越的三座大山。一旦掌握，你处理日志和数据的效率将提升 100 倍。

### 3.1 grep：文本搜索

**grep (Global Regular Expression Print)** 用于查找包含特定模式的行。

```bash
# 基础查找
grep "Error" app.log

# 忽略大小写 (-i) 并显示行号 (-n)
grep -in "error" app.log

# 递归查找当前目录所有文件 (-r)
grep -r "TODO" ./src

# 反向查找（除了...之外的行）
grep -v "DEBUG" app.log

# 使用正则表达式 (-E)
grep -E "Error|Warning" app.log
```

### 3.2 sed：流编辑器

**sed (Stream Editor)** 用于对文本进行自动化编辑（替换、删除、新增）。它不会修改原文件，除非使用 `-i` 选项。

```bash
# 替换（打印到屏幕）
# s/旧/新/g (global)
echo "Hello World" | sed 's/World/Linux/g'

# 删除第 2 到 5 行
sed '2,5d' file.txt

# ⚠️ 直接修改文件 (慎用，建议先备份)
sed -i 's/localhost/127.0.0.1/g' /etc/hosts
```

### 3.3 awk：文本分析报告生成器

**awk** 实际上是一门编程语言，特别擅长处理**列式数据**（如 CSV、日志）。

```bash
# 打印第 1 列和第 3 列（默认以空格/Tab 分隔）
ps aux | awk '{print $1, $3}'

# 指定分隔符 (-F)
# 打印 /etc/passwd 的用户名（第 1 列），分隔符是冒号
awk -F: '{print $1}' /etc/passwd

# 带条件的打印
# 打印 CPU 占用超过 50% 的进程
ps aux | awk '$3 > 50.0 {print $0}'

# 统计 Nginx 日志中每个 IP 的访问次数
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
```

## 4. 进程与资源管理进阶

除了 `top`，还有更多强大的工具来监控系统。

### 4.1 进程信号控制

`kill` 命令不仅是杀进程，它实际上是发送**信号 (Signal)**。

*   **SIGTERM (15)**：默认信号。礼貌地请求进程停止，允许进程清理资源（保存文件、关闭连接）。
*   **SIGKILL (9)**：强制杀死。进程立即终止，可能导致数据丢失。
*   **SIGHUP (1)**：通常用于通知进程**重载配置文件**（如 Nginx）。

```bash
# 查找 PID
pidof nginx

# 优雅停止
kill 1234

# 强制停止
kill -9 1234

# 重载配置
kill -HUP 1234
```

### 4.2 任务前后台管理

如果你运行一个耗时的脚本，不想让它占用终端：

```bash
# 1. 在后台运行 (&)
./long-script.sh &

# 2. 如果已经运行了，按 Ctrl+Z 暂停，然后放入后台
bg

# 3. 查看后台任务
jobs

# 4. 调回前台
fg %1

# 5. 防断线运行 (nohup)
# 即使关闭终端，进程也不会被杀死
nohup ./long-script.sh > output.log 2>&1 &
```

### 4.3 网络连接监控

`netstat` 已逐渐被 `ss` (Socket Statistics) 取代，后者更快。

```bash
# 查看所有监听的 TCP 端口
ss -lnt

# 查看谁在使用 80 端口
ss -lntp | grep :80

# 统计连接状态（查看并发数）
ss -ant | awk '{print $1}' | sort | uniq -c
```

## 5. 查找文件的艺术：find

`find` 是一个实时遍历文件系统的命令，功能极其强大但语法稍显复杂。

```bash
# 按名称查找
find /etc -name "nginx.conf"

# 按类型查找 (f=文件, d=目录)
find . -type d -name "src"

# 按大小查找 (+ 大于, - 小于)
find . -type f -size +100M

# 按时间查找
# 过去 24 小时内修改过的文件 (mtime 0)
find . -mtime 0
# 7 天前修改过的文件
find . -mtime +7

# 组合拳：查找并删除生成的临时文件
find . -name "*.tmp" -type f -delete
```

## 6. 磁盘空间分析

服务器报警磁盘满了怎么办？

```bash
# 1. 查看挂载点和整体使用率 (Disk Free)
# -h: human readable (GB, MB)
df -h

# 2. 查看当前目录下各文件夹大小 (Disk Usage)
# --max-depth=1: 只看一层
du -h --max-depth=1

# 3. 找出最大的 10 个文件/目录
du -ah . | sort -rh | head -n 10
```

---

## 总结

命令行不是用来死记硬背的，而是用来**组合**的。

*   用 `grep` 过滤，用 `awk` 提取，用 `sort` 排序，用 `uniq` 去重，用 `> ` 保存。
*   用 `ctrl+z` 和 `bg` 管理后台任务。
*   用 `find` 和 `xargs` 批量处理文件。

当你开始习惯用管道连接一切时，你就真正掌控了 Linux。

# 深入理解法线 (Normal)：图形学光照的基石

在 3D 图形学中，有一个向量比位置 (`position`) 更重要——它决定了物体看起来是平的还是圆的，是凹的还是凸的。它就是**法线 (Normal)**。

如果你想做光照、反射、法线贴图，或者任何涉及表面质感的技术，你必须先搞懂法线。

前置阅读：
- [图形学世界观](/posts/glsl/the-big-picture)——你需要理解 Vertex Shader 中的 `normal` attribute 从哪来
- [几何工坊](/posts/glsl/geometry-deep-dive)——面法线和顶点法线的区别与索引绘制有关

## 一、什么是法线？

**法线就是垂直于表面的方向向量，长度为 1。**

想象一个放在桌面上的皮球：
- 在球的最顶端，法线指向**正上方**
- 在球的最右侧，法线指向**正右方**
- 在球的每个点上，法线都从球心指向外面

<ShaderPreview title="Normal Visualization" code={`
varying vec2 vUv;

void main() {
    vec2 p = vUv * 2.0 - 1.0;
    float r = length(p);
    if (r > 1.0) {
        gl_FragColor = vec4(0.0, 0.0, 0.0, 1.0);
        return;
    }

    // 球面上任意一点的法线 = 从球心指向该点的方向
    // x² + y² + z² = 1 → z = sqrt(1 - x² - y²)
    float z = sqrt(1.0 - p.x*p.x - p.y*p.y);
    vec3 normal = vec3(p.x, p.y, z);

    // 法线范围 -1~1，颜色范围 0~1，所以映射：normal * 0.5 + 0.5
    gl_FragColor = vec4(normal * 0.5 + 0.5, 1.0);
}
`} />

**看懂法线颜色**：
- **蓝色 (0, 0, 1)**：法线指向屏幕外 (Z+)，正对着你
- **红色 (1, 0, 0)**：法线指向右边 (X+)
- **绿色 (0, 1, 0)**：法线指向上方 (Y+)
- **粉紫色**：法线斜着指向上右方

这种五颜六色的球，在图形学调试中随处可见，它就是法线的"身份证"。

## 二、面法线 vs 顶点法线

这是初学者最容易混淆的概念，它决定了物体看起来是棱角分明还是圆润光滑。

### 1. 面法线 (Face Normal)

**"这块三角形朝向哪？"**

对于一个三角形，它的法线可以用叉乘算出来：

```javascript
// 已知三角形的三个顶点 A, B, C
const edge1 = subtract(B, A);  // 边 AB
const edge2 = subtract(C, A);  // 边 AC
const faceNormal = normalize(cross(edge1, edge2));
```

`cross(edge1, edge2)` 得到一个垂直于三角形所在平面的向量——这就是面法线。同一个三角形上所有点共享同一条面法线。

**效果**：物体棱角分明，像钻石或低模 (Low Poly) 风格。

### 2. 顶点法线 (Vertex Normal)

**"这个角朝向哪？"**

我们给每个顶点单独定义法线。三角形内部的像素法线由 GPU 自动**插值**得到——三个顶点的法线平滑过渡。

对于球体这样的平滑曲面，顶点法线通常取**共享该顶点的所有面法线的平均值**：

```javascript
// 对于顶点 v，它被 N 个三角形共享
vertexNormal = normalize(
  faceNormal1 + faceNormal2 + ... + faceNormalN
);
```

**效果**：物体看起来圆润光滑，即使它其实是由三角形拼成的。

<ShaderPreview title="Flat vs Smooth Shading" code={`
varying vec2 vUv;
uniform float uTime;

void main() {
    vec2 uv = vUv * 2.0 - 1.0;

    // 左半边：面法线（棱角）
    // 右半边：顶点法线（平滑）
    float isSmooth = step(0.0, uv.x);

    // 模拟一个由 8 段组成的"圆"
    float segments = 8.0;
    float angle = floor(atan(uv.y, uv.x) * segments / 6.2832) * 6.2832 / segments;

    // 面法线：每段的方向一致（阶梯状）
    vec3 flatNormal = vec3(cos(angle), sin(angle), 0.5);

    // 顶点法线：连续的方向（平滑）
    vec3 smoothNormal = vec3(uv.x, uv.y, sqrt(max(0.0, 1.0 - uv.x*uv.x - uv.y*uv.y)));

    vec3 normal = mix(flatNormal, smoothNormal, isSmooth);
    normal = normalize(normal);

    // 光照
    vec3 lightDir = normalize(vec3(0.5, 0.5, 1.0));
    float diff = max(dot(normal, lightDir), 0.0);
    vec3 color = vec3(0.3, 0.6, 1.0) * (diff * 0.8 + 0.2);

    // 分界线
    float divider = smoothstep(-0.005, 0.005, abs(uv.x));
    color *= 1.0 - divider * 0.5;

    // 标签
    if (uv.y > 0.9) {
        color = isSmooth > 0.5 ? vec3(0.2, 1.0, 0.3) : vec3(1.0, 0.3, 0.2);
    }

    gl_FragColor = vec4(color, 1.0);
}
`} />

:::tip 和索引绘制的关系
在 [几何工坊](/posts/glsl/geometry-deep-dive) 中我们学过：索引绘制让多个三角形共享同一个顶点。当顶点被共享时，它的法线是所有相邻面法线的平均值，自动产生平滑效果。如果需要硬边，就必须把共享顶点拆开（非索引），让每个面拥有独立的法线。
:::

## 三、法线与光照：dot(N, L)

法线最重要的用途就是光照计算。漫反射的核心公式：

```
亮度 = dot(法线, 光线方向)
```

| 法线与光线的关系 | 夹角 | dot 值 | 效果 |
|---|---|---|---|
| 法线正对光线 | 0° | 1.0 | 最亮 |
| 法线与光线成 45° | 45° | 0.71 | 较亮 |
| 法线与光线垂直 | 90° | 0.0 | 全黑 |
| 法线背对光线 | `> 90°` | `< 0` | `max()` 截断为 0 |

**这意味着：如果我们欺骗了法线，我们就欺骗了光照。** 这就是法线贴图的原理。

## 四、Normal Matrix：为什么法线变换不能直接乘 Model Matrix

在 Vertex Shader 中，位置变换用 `modelViewMatrix`，但法线变换必须用 `normalMatrix`。为什么？

### 问题

当你对一个模型做**非均匀缩放**（比如 X 方向拉伸 2 倍），法线会被"歪掉"：

```
原始：圆球 → 法线径向朝外 ✓
X 方向拉伸 2x → 椭球 → 法线不再垂直于表面 ✗
```

因为法线是方向向量，它只关心"垂直于表面"，不关心"有多长"。但 `modelMatrix` 包含了缩放信息，直接乘会让法线不再垂直于表面。

### 解决方案：Normal Matrix

Normal Matrix 是 Model Matrix 的**逆转置矩阵的左上 3×3 部分**：

$$N = (M^{-1})^T$$

在 Three.js 中，它已经帮你算好了：

```glsl
// Vertex Shader
varying vec3 vNormal;

void main() {
  // 正确：用 normalMatrix 变换法线
  vNormal = normalMatrix * normal;

  // 错误：直接用 modelViewMatrix 变换法线
  // vNormal = (modelViewMatrix * vec4(normal, 0.0)).xyz;
  //         ↑ 非均匀缩放时法线会歪
}
```

**什么时候可以不用 normalMatrix？**

只有当 Model Matrix 只包含旋转和平移（没有缩放）时，`normalMatrix` 等价于 `modelViewMatrix` 的左上 3×3。所以如果你确定没有缩放，两种写法结果一样。但为了安全，**始终用 normalMatrix**。

## 五、法线贴图 (Normal Mapping)

如果我想在一个光滑的球面上画出砖块的凹凸感，难道要把模型加到几百万个三角形？不需要。**修改法线就够了。**

### 1. 原理

法线贴图是一张特殊的图片（通常是蓝紫色的）。它不存颜色，存的是**每个像素的法线方向**：

- 纯蓝色 (128, 128, 255) → 法线指向正前方 (0, 0, 1)，即"没有扰动"
- 偏红 → 法线偏向右边
- 偏绿 → 法线偏向上面

在 Fragment Shader 中，我们用贴图中的法线替代几何体的真实法线。光照计算以为表面有凹凸，于是产生明暗变化。**实际上模型还是平的！**

<ShaderPreview title="Normal Perturbation" code={`
varying vec2 vUv;
uniform float uTime;

void main() {
    // 1. 基础平面法线 (指向 Z+)
    vec3 normal = vec3(0.0, 0.0, 1.0);

    // 2. 用正弦波模拟法线贴图的扰动
    // 扰动 X 分量 → 法线左右摇摆 → 光照产生水平条纹
    normal.x += sin(vUv.y * 30.0 + uTime) * 0.3;
    // 扰动 Y 分量 → 法线上下摇摆 → 光照产生垂直条纹
    normal.y += cos(vUv.x * 30.0 + uTime * 0.7) * 0.3;
    normal = normalize(normal);

    // 3. 计算光照
    vec3 lightDir = normalize(vec3(1.0, 1.0, 1.0));
    float diff = max(dot(normal, lightDir), 0.0);

    vec3 color = vec3(0.2, 0.5, 1.0) * (diff * 0.8 + 0.2);

    gl_FragColor = vec4(color, 1.0);
}
`} />

看——明明是平面，看起来却像有波浪起伏。这就是法线贴图的魔法。

### 2. 切线空间 (Tangent Space)

法线贴图存储的法线是在**切线空间**中的。什么是切线空间？

**切线空间是以表面上的一个点为原点的局部坐标系**：

| 轴 | 名称 | 含义 |
|---|---|---|
| T (Tangent) | 切线 | 沿 UV 的 U 方向 |
| B (Bitangent) | 副切线 | 沿 UV 的 V 方向 |
| N (Normal) | 法线 | 垂直于表面 |

法线贴图中的蓝色 (0,0,1) 表示"法线指向 N 轴"——也就是"没有扰动"。其他颜色表示法线在 T、B 方向上有偏移。

### 3. TBN 矩阵：从切线空间到世界空间

光照计算需要法线在世界空间（或观察空间）中。法线贴图给出的是切线空间的法线，所以我们需要一个变换矩阵把它转到世界空间——这就是 **TBN 矩阵**：

$$\text{TBN} = \begin{bmatrix} T_x & B_x & N_x \\ T_y & B_y & N_y \\ T_z & B_z & N_z \end{bmatrix}$$

其中：
- **N** = 顶点法线（从 geometry 的 normal attribute 读取）
- **T** = 切线（沿 UV 的 U 方向的向量）
- **B** = 副切线 = `cross(N, T)`（沿 UV 的 V 方向的向量）

在 Three.js 中，如果你的几何体有 `tangent` attribute，TBN 矩阵在 Shader 中这样构建：

```glsl
// Vertex Shader
varying vec3 vNormal;
varying vec3 vTangent;
varying vec3 vBitangent;
varying vec2 vUv;

void main() {
  vUv = uv;

  // 用 normalMatrix 变换三个基向量到世界空间
  vNormal = normalize(normalMatrix * normal);
  vTangent = normalize(normalMatrix * tangent);
  // bitangent = normal × tangent，保持右手坐标系
  vBitangent = normalize(normalMatrix * bitangent);

  gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}
```

```glsl
// Fragment Shader
varying vec3 vNormal;
varying vec3 vTangent;
varying vec3 vBitangent;
varying vec2 vUv;
uniform sampler2D uNormalMap;

void main() {
  // 从法线贴图读取切线空间的法线
  // texture2D 返回 0~1 范围，法线是 -1~1 范围，所以 ×2-1
  vec3 tangentNormal = texture2D(uNormalMap, vUv).xyz * 2.0 - 1.0;

  // 构建 TBN 矩阵，把切线空间法线转到世界空间
  mat3 tbn = mat3(vTangent, vBitangent, vNormal);
  vec3 worldNormal = normalize(tbn * tangentNormal);

  // 现在可以用 worldNormal 做光照计算了
  vec3 lightDir = normalize(vec3(1.0, 1.0, 1.0));
  float diff = max(dot(worldNormal, lightDir), 0.0);

  gl_FragColor = vec4(vec3(diff), 1.0);
}
```

**为什么法线贴图要在切线空间而不是世界空间？**

因为切线空间是"跟着表面走的"——无论模型怎么旋转、缩放，切线空间的法线都不需要改。如果法线贴图存的是世界空间法线，那模型一旋转，所有法线就错了。

### 4. 没有 tangent attribute 时怎么办？

大多数简单几何体没有预计算 tangent。你可以用导数在 Fragment Shader 中即时计算：

```glsl
// Fragment Shader（不需要 tangent attribute 的方案）
varying vec2 vUv;
varying vec3 vNormal;

void main() {
  vec3 normal = normalize(vNormal);

  // 用 dFdx/dFdy 计算切线和副切线
  // dFdx(vUv) = UV 沿屏幕 X 方向的变化率 → 对应切线方向
  vec3 Q1 = dFdx(vUv);
  vec3 Q2 = dFdy(vUv);

  // 这是一种近似方法，适用于大多数情况
  vec3 tangent = normalize(dFdx(normal));
  vec3 bitangent = normalize(dFdy(normal));

  // 读取法线贴图
  vec3 tangentNormal = texture2D(uNormalMap, vUv).xyz * 2.0 - 1.0;

  // 构建近似 TBN
  mat3 tbn = mat3(tangent, bitangent, normal);
  vec3 worldNormal = normalize(tbn * tangentNormal);

  // 光照...
}
```

:::note dFdx/dFdy 是什么？
`dFdx` 和 `dFdy` 是 GLSL 的内置函数，计算任意值在屏幕 X/Y 方向上的变化率（偏导数）。它们在 GPU 上是免费的——光栅化时 GPU 本来就要做差分。但它们只在 Fragment Shader 中可用。
:::

## 六、在 Ray Marching 中计算法线

在 [光线步进](/posts/glsl/advanced-glsl-techniques) 中，我们没有几何体，也没有 normal attribute。但法线可以从 SDF 函数的**梯度**推导出来：

```glsl
// SDF 场景函数（返回到最近表面的距离）
float map(vec3 p) {
  return length(p) - 1.0;  // 球体
}

// 计算法线：采样周围 6 个点，算梯度
vec3 calcNormal(vec3 p) {
  float d = 0.001;  // 极小的偏移量
  // 中心差分法：沿 x/y/z 各偏移 d，看 SDF 值的变化
  float dx = map(p + vec3(d, 0, 0)) - map(p - vec3(d, 0, 0));
  float dy = map(p + vec3(0, d, 0)) - map(p - vec3(0, d, 0));
  float dz = map(p + vec3(0, 0, d)) - map(p - vec3(0, 0, d));

  // 梯度方向 = SDF 增长最快的方向 = 远离表面的方向 = 法线
  return normalize(vec3(dx, dy, dz));
}
```

**为什么梯度就是法线？**

SDF 函数的值从物体内部（负值）到外部（正值）是单调递增的。梯度（变化最快的方向）就是"从内部穿出表面"的方向——也就是法线方向。

<ShaderPreview title="Ray Marching Normals" code={`
varying vec2 vUv;
uniform float uTime;

float sdfSphere(vec3 p, float r) {
    return length(p) - r;
}

float map(vec3 p) {
    // 两个球的融合
    float d1 = sdfSphere(p - vec3(sin(uTime)*0.5, 0, 0), 0.6);
    float d2 = sdfSphere(p - vec3(-sin(uTime)*0.5, 0, 0), 0.6);
    return min(d1, d2);
}

vec3 calcNormal(vec3 p) {
    float d = 0.001;
    float dx = map(p + vec3(d,0,0)) - map(p - vec3(d,0,0));
    float dy = map(p + vec3(0,d,0)) - map(p - vec3(0,d,0));
    float dz = map(p + vec3(0,0,d)) - map(p - vec3(0,0,d));
    return normalize(vec3(dx, dy, dz));
}

void main() {
    vec2 uv = vUv * 2.0 - 1.0;
    vec3 ro = vec3(0, 0, 3);
    vec3 rd = normalize(vec3(uv, -1.0));

    float t = 0.0;
    float hit = 0.0;

    for(int i = 0; i < 64; i++) {
        vec3 p = ro + rd * t;
        float d = map(p);
        if(d < 0.001) { hit = 1.0; break; }
        t += d;
        if(t > 10.0) break;
    }

    vec3 color = vec3(0.05);

    if(hit > 0.5) {
        vec3 p = ro + rd * t;
        vec3 normal = calcNormal(p);

        // 左半：法线可视化（彩色）
        // 右半：光照结果（黑白）
        float isRight = step(0.0, uv.x);

        vec3 normalColor = normal * 0.5 + 0.5;

        vec3 lightDir = normalize(vec3(1.0, 1.0, 1.0));
        float diff = max(dot(normal, lightDir), 0.0);
        vec3 litColor = vec3(diff);

        color = mix(normalColor, litColor, isRight);
    }

    gl_FragColor = vec4(color, 1.0);
}
`} />

左半边是法线颜色图（调试视图），右半边是光照结果。你可以看到法线颜色和明暗之间的直接对应关系——蓝色区域（法线朝前）最亮，偏红/偏绿区域（法线侧向）较暗。

## 总结

| 你学到的 | 关键要点 |
|---|---|
| 法线定义 | 垂直于表面的单位向量 |
| 面法线 vs 顶点法线 | 面法线→棱角，顶点法线→平滑 |
| Normal Matrix | 法线必须用 $(M^{-1})^T$ 变换，不能用 Model Matrix |
| 法线贴图 | 用贴图存储法线扰动，在平面上伪造凹凸 |
| 切线空间 | 法线贴图在切线空间中存储，需 TBN 矩阵转到世界空间 |
| SDF 法线 | 用中心差分法算梯度，梯度方向 = 法线方向 |
| dot(N, L) | 法线和光线方向的点积决定亮度 |

**核心认知**：法线是图形学中"欺骗"光照的手段——无论模型多粗糙，只要法线是对的，光照就是对的。

# 图形学世界观：从屏幕像素到渲染管线

学习图形学最容易迷失在细节里：一会儿是矩阵乘法，一会儿是 GLSL 语法，一会儿又是光照公式。

你会觉得："我学会了怎么写代码，但我不知道这行代码在整个系统中处于什么位置。"

今天，我们跳出细节，站在上帝视角，看看计算机图形学的**全貌**。我们将回答三个终极问题：
1.  **屏幕**到底是什么？
2.  **GPU** 到底在忙什么？（渲染管线）
3.  **我们**到底在算什么？（光与影）

## 一、 屏幕：光的欺骗

图形学的第一课，是理解你的画布——屏幕。

### 1. 像素不是点，是小灯泡
你以为屏幕是一张画纸，其实它是一块布满了微型红绿蓝 (RGB) 灯泡的阵列。
当你想显示"黄色"时，你并不是真的涂了黄色颜料，而是同时点亮了**红色**和**绿色**的灯泡。你的眼睛被欺骗了，大脑混合出了黄色。

这就是为什么我们在 Shader 里用 `vec4(r, g, b, a)`。我们在控制灯泡的亮度。

### 2. 帧率：视觉暂留
屏幕不仅在欺骗你的颜色感官，还在欺骗你的时间感官。
它每秒钟刷新 60 次 (60Hz)。因为刷新得太快，连续的静态画面在人脑中变成了动态。

**这对我们意味着什么？**
意味着你的 Shader 代码，必须在 **16.6 毫秒** (1000ms / 60) 内跑完所有像素的计算！如果跑慢了，画面就会卡顿（掉帧）。这也是为什么我们如此强调 GPU 的并行计算能力。

## 二、 渲染管线：从数据到图像的流水线

这是图形学最核心的概念。
当你告诉电脑："给我画一个红色的立方体"。GPU 内部发生了一场精密的接力赛，这就是**渲染管线 (Rendering Pipeline)**。

我们可以把它简化为四个阶段：

### 阶段 1：顶点处理 (Vertex Processing) —— "点在哪里？"
*   **输入**：一堆 3D 坐标（立方体的 8 个角）。
*   **工作**：
    1.  **模型变换**：把立方体摆到世界中正确的位置。
    2.  **视图变换**：根据摄像机的角度，旋转整个世界。
    3.  **投影变换**：把 3D 世界压扁成 2D 屏幕坐标（近大远小）。
*   **输出**：屏幕上的 2D 点。
*   **对应代码**：`Vertex Shader`。

### 阶段 2：光栅化 (Rasterization) —— "点变成了面"
*   **输入**：屏幕上的 2D 点（比如三角形的三个角）。
*   **工作**：找出这三个点围成的三角形覆盖了屏幕上的哪些**像素**。
*   **输出**：一堆待处理的像素（片元）。
*   **注意**：这一步是硬件自动完成的，你通常无法编程控制。

### 阶段 3：片元处理 (Fragment Processing) —— "面是什么颜色？"
*   **输入**：每一个待处理的像素。
*   **工作**：这是最耗时的一步。你需要计算光照、纹理、阴影，最后决定这个像素到底是什么颜色。
*   **输出**：RGBA 颜色。
*   **对应代码**：`Fragment Shader`。

### 阶段 4：输出合并 (Output Merging) —— "谁挡住了谁？"
*   **工作**：
    1.  **深度测试 (Depth Test)**：如果这个像素比之前画在这个位置的像素更远，那就丢弃它（被挡住了）。
    2.  **混合 (Blending)**：如果这个像素是半透明的，就和背景色混合。

## 三、 坐标系：我们在哪一层？

初学者最容易晕的就是坐标系。因为在管线的不同阶段，我们处于不同的空间。

1.  **局部空间 (Local Space)**：模型自己的世界。原点是模型的中心。
    *   *乘以 Model Matrix ->*
2.  **世界空间 (World Space)**：所有模型都在同一个大世界里。原点是世界的中心。光照计算通常在这里进行。
    *   *乘以 View Matrix ->*
3.  **观察空间 (View Space)**：以摄像机为原点的世界。摄像机永远在 (0,0,0) 看向 Z 轴负方向。
    *   *乘以 Projection Matrix ->*
4.  **裁剪空间 (Clip Space)**：一个 x,y,z 都在 -1 到 1 之间的立方体盒子。超出盒子的东西会被剪掉。这是 Vertex Shader 的终点 (`gl_Position`)。
    *   *视口变换 ->*
5.  **屏幕空间 (Screen Space)**：最终的像素坐标 (x: 0~1920, y: 0~1080)。

## 四、 光照：图形学的灵魂

如果没有光，我们看到的只是一团色块。图形学的很大一部分工作，就是在模拟光。

### 1. 也是欺骗
真实的物理光照（光线追踪）非常昂贵。为了在 16ms 内算完，我们发明了很多"作弊"算法。

### 2. 冯氏光照模型 (Phong Lighting)
这是最经典的作弊方法，它把光拆成三部分：

1.  **环境光 (Ambient)**：即使没有光直射，物体也不是全黑的（光会乱反射）。我们给它一个底色。
2.  **漫反射 (Diffuse)**：光照在粗糙表面上。正对着光的地方最亮 (`dot(Normal, LightDir)`).
3.  **镜面光 (Specular)**：光照在光滑表面上。反射光直接射进眼睛的地方，会有一个高光亮点。

<ShaderPreview title="Phong Lighting" code={`
varying vec2 vUv;
uniform float uTime;

void main() {
    // 1. 模拟球体几何
    vec2 p = vUv * 2.0 - 1.0;
    float r = length(p);
    if (r > 1.0) discard; // 圆外丢弃
    
    // 计算法线：球面法线就是从球心指出来的方向
    float z = sqrt(1.0 - r*r);
    vec3 normal = vec3(p.x, p.y, z);
    
    // 2. 光源位置 (旋转)
    vec3 lightPos = vec3(sin(uTime)*2.0, 1.0, cos(uTime)*2.0);
    vec3 lightDir = normalize(lightPos - vec3(0.0, 0.0, 0.0));
    
    // 3. 视线方向 (假设相机在正前方)
    vec3 viewDir = vec3(0.0, 0.0, 1.0);
    
    // --- 计算光照 ---
    
    // Ambient: 环境光
    vec3 ambient = vec3(0.1, 0.0, 0.0); // 暗红色底光
    
    // Diffuse: 漫反射 (N dot L)
    float diff = max(dot(normal, lightDir), 0.0);
    vec3 diffuse = diff * vec3(1.0, 0.0, 0.0); // 红色物体
    
    // Specular: 镜面光 (Blinn-Phong)
    vec3 halfwayDir = normalize(lightDir + viewDir);
    float spec = pow(max(dot(normal, halfwayDir), 0.0), 32.0); // 32是反光度
    vec3 specular = spec * vec3(1.0, 1.0, 1.0); // 白光
    
    vec3 result = ambient + diffuse + specular;
    
    gl_FragColor = vec4(result, 1.0);
}
`} />

## 总结

现在，你再看那些碎片化的知识点，应该能找到它们的位置了：

*   **GLSL**：是控制管线中 *Vertex* 和 *Fragment* 两个可编程阶段的语言。
*   **矩阵**：是连接 *局部空间* 到 *裁剪空间* 的桥梁。
*   **向量**：是计算 *光照* 和 *坐标* 的基本单位。

图形学就是一场关于**欺骗**的艺术：利用数学和算法，在平面的屏幕上，让红绿蓝三个灯泡，骗过你的眼睛，让你相信那里有一个真实的世界。

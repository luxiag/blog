# GLSL 新手指南：带你走进 Shader 的奇妙世界

如果你是一个前端开发者，或者对计算机图形感兴趣，你可能听说过 "Shader"（着色器）这个词。也许你见过那些炫酷的 3D 网页背景，或者游戏里逼真的水面和火焰效果。

其实，这些魔法背后，大都是 **GLSL** (OpenGL Shading Language) 在发挥作用。

别被"图形学"这三个字吓跑了！本文就是专门为你准备的。我们将从最根本的问题出发：**Shader 到底是什么？它怎么跑起来的？**

## 一、 Shader 是什么？—— 改变像素的程序

先忘掉所有专业术语。用最朴素的话说：

> **Shader 就是一段告诉 GPU "每个像素/顶点应该长什么样"的程序。**

你在屏幕上看到的每一帧画面，都是由几百万个像素组成的。每个像素都有颜色。Shader 的工作就是：**给我一个像素的位置，我告诉你它应该是什么颜色。**

这和 JavaScript 的思路完全不同：

| | JavaScript | Shader |
|---|---|---|
| 执行方式 | 一条指令一条指令地执行 | 同一条指令在几百万个像素上**同时**执行 |
| 思维方式 | "先做这个，再做那个" | "给定输入，算出输出" |
| 能不能看邻居？ | 能，你什么都能访问 | **不能**，你只知道当前像素的信息 |

最后一点特别重要：在 Fragment Shader 里，你**不能**问旁边的像素是什么颜色。你只能根据当前像素的位置（和其他已知的输入），通过数学公式算出它的颜色。这就像一场考试，每个像素拿到同一张试卷，独立作答，不许偷看。

## 二、 两个 Shader：一个管位置，一个管颜色

这是很多人忽略的关键知识：**Shader 不止一个，它们是配合工作的。**

一个完整的 Shader 程序由两个部分组成：

### Vertex Shader（顶点着色器）—— 决定"东西在哪里"

3D 世界里的一切都是由三角形拼成的。三角形的角叫做**顶点 (Vertex)**。Vertex Shader 的工作就是：**告诉你输入了一个 3D 顶点，它在屏幕上的哪个位置。**

它回答的问题：**"这个点在屏幕上画在哪里？"**

### Fragment Shader（片元着色器）—— 决定"看起来什么颜色"

当三个顶点确定了屏幕上的一个三角形区域后，GPU 会用像素去填充这个三角形。每个待填充的像素叫做**片元 (Fragment)**。Fragment Shader 的工作就是：**告诉你这个像素应该是什么颜色。**

它回答的问题：**"这个像素涂什么颜色？"**

### 它们怎么配合？—— 数据流水线

两个 Shader 不是各干各的，它们通过一个叫 **varying** 的机制传递数据。完整的数据流是这样的：

```
JavaScript 定义几何体（顶点坐标、UV、法线……）
        │
        ▼
┌─────────────────────────────┐
│     Vertex Shader            │  对每个顶点执行一次
│  输入：position, uv, normal  │  ← 从 JS 传入
│  输出：gl_Position           │  ← 顶点在屏幕上的位置
│  同时：把 uv 赋给 varying    │  ← 传递给 Fragment
└─────────────────────────────┘
        │
        ▼  GPU 自动插值
│  三个顶点的 varying 值 → 像素间的渐变值  │
        │
        ▼
┌─────────────────────────────┐
│     Fragment Shader          │  对每个像素执行一次
│  输入：varying vUv 等        │  ← 插值后的数据
│  输出：gl_FragColor          │  ← 这个像素的颜色
└─────────────────────────────┘
        │
        ▼
    屏幕上的像素
```

**关键理解**：Vertex Shader 跑的次数 = 顶点数（几千个），Fragment Shader 跑的次数 = 像素数（几百万个）。所以 Fragment Shader 的性能影响远大于 Vertex Shader。

## 三、 动手时刻：从最简单的 Fragment Shader 开始

在本文的交互示例中，我们使用 `ShaderPreview` 组件。它已经帮你设置好了 Vertex Shader（自动把顶点摆成一个全屏矩形，并把 UV 坐标传下来），你只需要写 Fragment Shader。

这就像 ShaderToy 的模式——你只需要关心"这个像素是什么颜色"。

### 1. 你好，色彩！

在 GLSL 中，颜色用 `vec4` 表示，分别是 **红(R)、绿(G)、蓝(B)、透明度(A)**。范围是 `0.0` 到 `1.0`。

<ShaderPreview title="Hello Color" code={`
// varying：从 Vertex Shader 传来的数据
// vUv 是当前像素在画面中的归一化坐标
// (0,0) 是左下角，(1,1) 是右上角
varying vec2 vUv;

void main() {
  // 把所有像素都涂成红色
  gl_FragColor = vec4(1.0, 0.0, 0.0, 1.0);
}
`} />

所有像素都拿到了同样的颜色，所以整个画面是纯红色。这很无聊——我们不知道自己在哪里。

### 2. 认识坐标 (UV)

`vUv` 是你写 Fragment Shader 最重要的输入。它告诉你当前像素在画面中的位置：

- `vUv.x`：从左到右，0.0 → 1.0
- `vUv.y`：从下到上，0.0 → 1.0

让我们把坐标"画"出来：

<ShaderPreview title="坐标渐变" code={`
varying vec2 vUv;

void main() {
  // 把 X 坐标直接当作红色分量
  // 左边 (x=0) 是黑的，右边 (x=1) 是红的
  float red = vUv.x;
  
  // 把 Y 坐标直接当作绿色分量
  // 下边 (y=0) 无绿，上边 (y=1) 满绿
  float green = vUv.y;
  
  gl_FragColor = vec4(red, green, 0.0, 1.0);
}
`} />

看！左下角是黑的 (0,0)，右上角是黄的 (1,1，红+绿=黄)。**你第一次用坐标控制了颜色。** 这就是 Shader 的核心思路：坐标 → 公式 → 颜色。

### 3. 混合颜色 (mix)

`mix(a, b, t)` 在两个值之间插值：`t=0` 时得到 `a`，`t=1` 时得到 `b`。

<ShaderPreview title="颜色混合" code={`
varying vec2 vUv;

void main() {
  vec3 colorA = vec3(0.0, 0.0, 1.0); // 纯蓝
  vec3 colorB = vec3(1.0, 0.5, 0.0); // 橙色
  
  // 根据 X 坐标混合
  // 左边是蓝，右边是橙，中间自动过渡
  vec3 finalColor = mix(colorA, colorB, vUv.x);
  
  gl_FragColor = vec4(finalColor, 1.0);
}
`} />

### 4. 绘制形状：画一个圆

画圆的思路：**"如果当前像素离中心的距离小于半径，就涂白色"**。

<ShaderPreview title="绘制圆形" code={`
varying vec2 vUv;

void main() {
  // 1. 把坐标原点从左下角移到中心
  // 现在的坐标范围是 -0.5 到 0.5
  vec2 center = vUv - 0.5;
  
  // 2. 计算当前像素到中心的距离
  float dist = length(center);
  
  // 3. 画圆
  // step(0.2, dist) 在 dist < 0.2 时返回 0，dist >= 0.2 时返回 1
  // 1.0 - step(...) 取反：圆内为 1，圆外为 0
  float circle = 1.0 - step(0.2, dist);
  
  gl_FragColor = vec4(vec3(circle), 1.0);
}
`} />

**新手提示**：为什么不用 `if (dist < 0.2)`？虽然可以用，但在 GPU 上，`if` 分支的效率通常不如数学函数。习惯用数学公式来表达逻辑是 Shader 编程的一大特点。

### 5. 让画面动起来 (Time)

静止的画面不够酷？我们需要引入**时间**。

`uTime` 是一个 `uniform` 变量——它从 JavaScript 传入，每一帧更新一次，所有像素共享同一个值。

<ShaderPreview title="动态呼吸" code={`
// uniform：所有像素共享的"全局变量"
// 由 JavaScript 每帧更新
uniform float uTime;

varying vec2 vUv;

void main() {
  vec2 center = vUv - 0.5;
  float dist = length(center);
  
  // 让半径随时间变化
  // sin(uTime) 范围是 -1 ~ 1
  // * 0.1 + 0.2 范围变成 0.1 ~ 0.3
  float radius = sin(uTime * 2.0) * 0.1 + 0.2;
  
  // smoothstep 比 step 更柔和，产生抗锯齿效果
  float circle = 1.0 - smoothstep(radius, radius + 0.01, dist);
  
  // 加上颜色：随时间变色的圆
  vec3 color = vec3(circle) * vec3(0.5 + sin(uTime)*0.5, 0.5, 1.0);
  
  gl_FragColor = vec4(color, 1.0);
}
`} />

到目前为止，你只写了 Fragment Shader，Vertex Shader 由组件自动处理。这是学习 Fragment Shader 最纯粹的方式——你只需要关心"给定位置，算出颜色"。

## 四、 两个 Shader 如何配合：完整工作流

现在我们要进入真正的 3D 世界了。当你把 Shader 挂载到一个 3D 模型上时，Vertex Shader 和 Fragment Shader 必须同时编写，它们通过 `varying` 变量传递数据。

让我们看一个真实的例子：给一个 3D 平面做水面效果。

### Vertex Shader：让顶点动起来

<ShaderSceneDemo
  title="3D 动态水面"
  description="拖动视角，并调整波浪高度、速度和水面颜色。"

  vertexShader={`
// Vertex Shader 的输入（Three.js 自动提供）
// position：顶点的 3D 坐标 (vec3)
// uv：顶点的纹理坐标 (vec2)
// normal：顶点的法线方向 (vec3)

// uniform：从 JavaScript 传入的共享数据
uniform float uTime;
uniform float uWaveHeight;
uniform float uWaveSpeed;

// varying：传递给 Fragment Shader 的数据
varying float vElevation;
varying vec2 vUv;

void main() {
  // 第一步：把 uv 传给 Fragment Shader
  // 在 Vertex Shader 中赋值，GPU 会在三个顶点之间自动插值
  vUv = uv;
  
  // 第二步：修改顶点位置
  vec3 pos = position;
  float time = uTime * uWaveSpeed;
  float waveA = sin(pos.x * 4.0 + time) * uWaveHeight;
  float waveB = cos(pos.y * 5.0 - time * 0.8) * uWaveHeight * 0.55;
  pos.z += waveA + waveB;
  
  // 第三步：把高度信息也传给 Fragment Shader
  vElevation = waveA + waveB;
  
  // 第四步：计算顶点在屏幕上的最终位置
  // projectionMatrix：投影矩阵（把 3D 压成 2D）
  // modelViewMatrix：模型+视图矩阵（把模型放到世界中，再从相机角度看）
  // vec4(pos, 1.0)：把 vec3 变成 vec4（4D 齐次坐标）
  gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
}
  `}
  fragmentShader={`
precision mediump float;

// 从 Vertex Shader 传来的插值数据
varying float vElevation;
varying vec2 vUv;

uniform vec3 uDeepColor;
uniform vec3 uSurfaceColor;
uniform float uWaveHeight;

void main() {
  // 根据高度混合颜色
  float level = vElevation / max(uWaveHeight * 1.55, 0.001);
  level = clamp(level * 0.5 + 0.5, 0.0, 1.0);
  vec3 color = mix(uDeepColor, uSurfaceColor, level);
  
  // 浪尖加白色泡沫
  float foam = smoothstep(0.82, 1.0, level);
  color += foam * vec3(0.45, 0.75, 0.85);
  
  gl_FragColor = vec4(color, 1.0);
}
  `}

### 逐行理解 Vertex Shader

上面的 Vertex Shader 用到了几个你还没见过的变量，我们来一一解释：

**`position`、`uv`、`normal`**——这些是 Three.js 自动注入的 **attribute** 变量，代表每个顶点独有的数据：

| 变量 | 类型 | 含义 | 来源 |
|---|---|---|---|
| `position` | `vec3` | 顶点在模型中的 3D 坐标 | 由 JS 定义的几何体提供 |
| `uv` | `vec2` | 顶点的纹理坐标 (0,0)~(1,1) | 由 JS 定义的几何体提供 |
| `normal` | `vec3` | 顶点的法线方向 | 由 JS 定义的几何体提供 |

你不需要声明它们，Three.js 会自动帮你加上。

**`projectionMatrix`、`modelViewMatrix`**——这些是 Three.js 自动注入的 **uniform** 变量，所有顶点共享：

| 变量 | 含义 |
|---|---|
| `modelViewMatrix` | = 模型矩阵 × 视图矩阵。把顶点从"模型自己的坐标系"变换到"以相机为原点的坐标系" |
| `projectionMatrix` | 投影矩阵。把 3D 坐标"压扁"成 2D 屏幕坐标（近大远小） |

**`gl_Position`**——Vertex Shader 的唯一输出。它是一个 `vec4`，表示顶点在屏幕上的位置。每个 Vertex Shader **必须**设置这个变量，否则 GPU 不知道把顶点画在哪里。

### varying 的数据流：从顶点到像素

注意这行代码：

```glsl
vUv = uv;
```

它做了一件看似多余的事：把 `uv` 赋值给 `vUv`。为什么要这样？

因为 `uv` 是 attribute（每个顶点独有），Fragment Shader **不能直接读取 attribute**。只有通过 `varying` 才能把数据从 Vertex Shader 传到 Fragment Shader。

而且 GPU 会在传递过程中**自动插值**。假设一个三角形的三个顶点 UV 分别是 (0,0)、(1,0)、(0,1)，那么三角形正中间的像素拿到的 `vUv` 大约是 (0.33, 0.33)——三个顶点值的平滑混合。这就是为什么 Fragment Shader 里用 `vUv` 就能精确知道"我在画面中的哪个位置"。

:::tip 总结：三种变量限定符
- **attribute**：每个顶点独有（如 position、uv）。只能在 Vertex Shader 中读取。
- **uniform**：所有顶点/像素共享（如 uTime、projectionMatrix）。Vertex 和 Fragment 都能读取。
- **varying**：从 Vertex Shader 传给 Fragment Shader，自动插值。两边都需要声明同名变量。
:::

## 五、 更多实际场景

### 场景一：给真实图片添加滤镜

<ShaderSceneDemo
  title="GPU 图片滤镜"
  description="切换效果或上传图片，观察 Fragment Shader 如何处理真实像素。"
  scene={{ kind: "fullscreen" }}
  fragmentShader={`
precision mediump float;

// sampler2D：纹理采样器，代表一张图片
uniform sampler2D uImage;
uniform vec2 uResolution;
uniform int uEffect;
uniform float uStrength;
varying vec2 vUv;

// 把 RGB 颜色转为亮度（灰度值）
// dot() 是点积：把三个分量按权重相加
float toLuma(vec3 color) {
  return dot(color, vec3(0.299, 0.587, 0.114));
}

void main() {
  // texture2D：从纹理中采样当前像素的颜色
  vec4 original = texture2D(uImage, vUv);
  vec3 effectColor = original.rgb;

  if (uEffect == 1) {
    // 灰度：把 RGB 亮度转换成单一颜色值
    effectColor = vec3(toLuma(original.rgb));
  } else if (uEffect == 2) {
    // 马赛克：同一网格中的像素读取同一个位置
    float blocks = 36.0;
    vec2 pixelUv = (floor(vUv * blocks) + 0.5) / blocks;
    effectColor = texture2D(uImage, pixelUv).rgb;
  } else if (uEffect == 3) {
    // 边缘检测：比较当前像素上下左右的亮度差
    vec2 pixel = 1.0 / uResolution;
    float left = toLuma(texture2D(uImage, vUv - vec2(pixel.x, 0.0)).rgb);
    float right = toLuma(texture2D(uImage, vUv + vec2(pixel.x, 0.0)).rgb);
    float bottom = toLuma(texture2D(uImage, vUv - vec2(0.0, pixel.y)).rgb);
    float top = toLuma(texture2D(uImage, vUv + vec2(0.0, pixel.y)).rgb);
    effectColor = vec3(length(vec2(right - left, top - bottom)) * 4.0);
  }

  gl_FragColor = vec4(mix(original.rgb, effectColor, uStrength), original.a);
}
  `}
  textures={[
    {
      name: "uImage",
      label: "输入图片",
      src: "/posts/glsl/images/shader-filter-default.svg",
      uploadable: true,
    },
  ]}
  uniforms={[
    {
      name: "uEffect",
      type: "int",
      value: 1,
      label: "滤镜类型",
      control: "select",
      options: [
        { label: "原图", value: 0 },
        { label: "灰度", value: 1 },
        { label: "马赛克", value: 2 },
        { label: "边缘检测", value: 3 },
      ],
    },
    {
      name: "uStrength",
      type: "float",
      value: 1,
      label: "滤镜强度",
      control: "range",
      min: 0,
      max: 1,
      step: 0.01,
    },
  ]}
/>

这里出现了一个新类型 `sampler2D` 和一个新函数 `texture2D()`：

- **`sampler2D uImage`**：代表一张纹理图片，由 JavaScript 传入
- **`texture2D(uImage, vUv)`**：根据 UV 坐标，从图片中读取那个位置的颜色

这就是"图片滤镜"的本质：从图片里读颜色 → 用数学公式修改颜色 → 输出新颜色。Photoshop 的滤镜、Instagram 的调色、手机的美颜，底层都是这个套路。

:::note 关于 precision
示例第一行有 `precision mediump float;`，它告诉 GPU 使用中等精度的浮点数。在 ShaderPreview 组件中，这行由系统自动添加。但在 ShaderSceneDemo 中需要手动写。这不是本文重点，你只需要知道：**Fragment Shader 需要 precision 声明，Vertex Shader 不需要**（它默认 highp）。
:::

### 场景二：根据数据生成交互热力图

<ShaderSceneDemo
  title="交互式热力图"
  description="在预览区域移动鼠标，观察实时热点。"
  scene={{ kind: "fullscreen" }}
  fragmentShader={`
precision mediump float;
uniform vec2 uPointer;
uniform float uRadius;
varying vec2 vUv;

// heat()：计算某个点到热源点的"热度"
// distance()：计算两点距离
// exp()：指数衰减，距离越远热度越低
float heat(vec2 point, float strength) {
  float distanceToPoint = distance(vUv, point);
  return strength * exp(-distanceToPoint * distanceToPoint / uRadius);
}

void main() {
  float value = 0.0;
  // 三个固定热点 + 鼠标位置的热点
  value += heat(vec2(0.22, 0.32), 0.9);
  value += heat(vec2(0.48, 0.72), 0.75);
  value += heat(vec2(0.76, 0.42), 1.0);
  value += heat(uPointer, 1.2);
  value = clamp(value, 0.0, 1.0);

  // 冷→暖→热的颜色映射
  vec3 cold = vec3(0.03, 0.08, 0.28);
  vec3 warm = vec3(0.95, 0.12, 0.02);
  vec3 hot = vec3(1.0, 0.95, 0.25);
  vec3 color = value < 0.65
    ? mix(cold, warm, value / 0.65)
    : mix(warm, hot, (value - 0.65) / 0.35);

  gl_FragColor = vec4(color, 1.0);
}
  `}
  uniforms={[
    {
      name: "uRadius",
      type: "float",
      value: 0.018,
      label: "热点扩散范围",
      control: "range",
      min: 0.004,
      max: 0.08,
      step: 0.001,
    },
  ]}
/>

实际项目可以把示例中写死的三个点替换成接口数据，用于地图客流、网站点击区域和设备温度监控。GPU 会并行完成大量像素的颜色计算。

## 六、 什么时候不需要 Shader？

普通按钮位移、淡入淡出和布局动画优先使用 CSS。只有当任务需要对大量像素或顶点执行相似计算时，Shader 才更能发挥 GPU 并行处理的优势。

## 七、 常见疑问 (Q&A)

**Q: 学习 GLSL 需要很好的数学基础吗？**
A: 入门不需要。你只需要理解加减乘除和基本的坐标系概念。当你想要做非常复杂的效果（如光线追踪、分形）时，才会用到高级数学。对于初学者，**向量**和**三角函数** (sin/cos) 是最重要的两个工具。

**Q: Vertex Shader 和 Fragment Shader 能不能只写一个？**
A: 在 WebGL 中，Vertex Shader 是**必须**的（没有它 GPU 不知道顶点在哪），Fragment Shader 也是必须的（没有它像素没有颜色）。在 ShaderToy 和本文的 ShaderPreview 中，Vertex Shader 由系统自动提供，所以你只需要写 Fragment Shader。但在实际项目中，你必须两个都写。

**Q: 我应该在哪里写 GLSL？**
A: 
1. **学习阶段**：ShaderToy 或本文的 ShaderPreview，只需要写 Fragment Shader
2. **实际项目**：使用 Three.js 的 ShaderMaterial，需要同时写 Vertex 和 Fragment
3. **游戏引擎**：Unity 和 Unreal 也大量使用 Shader（语法略有不同，但原理通通一样）

**Q: 为什么代码里变量名有时候是 vec3 有时候是 vec4？**
A: 
- `vec3`：通常表示 RGB 颜色，或者 XYZ 坐标
- `vec4`：通常表示 RGBA 颜色（多一个透明度），或者齐次坐标（3D 变换需要第 4 个分量）
- GLSL 允许你灵活转换：`vec4(colorVec3, 1.0)` 就是把 vec3 变成 vec4

# GLSL 进阶三部曲：顶点位移、后期处理与光线步进

在掌握了基础的 Fragment Shader 之后，你可能已经能画出漂亮的 2D 图案了。但 GLSL 的能力远不止于此。

本文将带你通过三个循序渐进的阶段，探索 GLSL 更深层的魔法。我们将从修改模型的形状开始，到处理整个屏幕的像素，最后进入纯数学构建的 3D 世界。

## 第一阶段：顶点位移 (Vertex Displacement)

到目前为止，我们只在 Fragment Shader 里改变**颜色**。但如果我们想改变**形状**呢？
这就需要用到 **Vertex Shader**（顶点着色器）。

### 原理
Vertex Shader 决定了模型上每个点（顶点）在屏幕上的位置。我们可以通过修改 `position` 变量，让静态的模型动起来。

### 1. 简单的波动
让我们让一个平面像波浪一样起伏。原理很简单：**根据顶点的 X 坐标和时间，修改它的 Z 坐标（高度）。**

<ShaderPreview title="Sine Wave Vertex" vertexCode={`
uniform float uTime;
varying vec2 vUv;

void main() {
  vUv = uv;
  vec3 pos = position;
  
  // 核心魔法：Z 轴高度随 X 轴和时间变化
  // sin 函数创造波动
  pos.z += sin(pos.x * 5.0 + uTime) * 0.2;
  
  gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
}
`} code={`
varying vec2 vUv;

void main() {
  // 简单的颜色，方便观察起伏
  gl_FragColor = vec4(vUv.x, vUv.y + 0.5, 1.0, 1.0);
}
`} />

### 2. 复杂的噪声地形
正弦波太规则了。如果我们把上一篇学到的 **Perlin Noise** 用在顶点上，就能创造出像山脉或水面那样自然的起伏。

*(注：由于 WebGL 限制，这里演示简单的叠加波来模拟噪声)*

<ShaderPreview title="Water Surface" vertexCode={`
uniform float uTime;
varying vec2 vUv;

void main() {
  vUv = uv;
  vec3 pos = position;
  
  // 叠加两个不同频率的波，模拟更自然的水面
  float wave1 = sin(pos.x * 4.0 + uTime) * 0.1;
  float wave2 = cos(pos.y * 3.0 + uTime * 0.8) * 0.1;
  
  pos.z += wave1 + wave2;
  
  gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
}
`} code={`
varying vec2 vUv;

void main() {
  // 根据 UV 加上一点高光效果
  float strength = step(0.9, sin(vUv.x * 20.0) + sin(vUv.y * 20.0));
  vec3 color = mix(vec3(0.0, 0.5, 1.0), vec3(1.0), strength * 0.5);
  gl_FragColor = vec4(color, 1.0);
}
`} />

## 第二阶段：后期处理 (Post-processing)

后期处理就像是给整个 3D 场景加了一层 Instagram 滤镜。
我们不再关心具体的模型，而是把整个渲染好的画面当成一张**图片（纹理）**，然后在 Fragment Shader 里对这张图片进行像素级处理。

### 1. 简单的反色
最基础的后期处理。读取颜色，然后用 `1.0 - color`。

*(注：由于 ShaderPreview 只能演示 Shader 本身，这里我们用一张生成的图案来模拟"原图")*

<ShaderPreview title="Invert Colors" code={`
varying vec2 vUv;

void main() {
  // 1. 模拟"原图"：一个红色的圆
  float dist = length(vUv - 0.5);
  vec3 originalColor = vec3(step(dist, 0.3), 0.0, 0.0); // 红色圆，黑色背景
  
  // 2. 后期处理：反色
  // 红色 (1,0,0) -> 青色 (0,1,1)
  // 黑色 (0,0,0) -> 白色 (1,1,1)
  vec3 postColor = 1.0 - originalColor;
  
  gl_FragColor = vec4(postColor, 1.0);
}
`} />

### 2. 故障艺术 (Glitch Effect)
通过对 UV 坐标进行随机偏移，可以模拟出信号故障的效果。

<ShaderPreview title="Glitch Effect" code={`
uniform float uTime;
varying vec2 vUv;

// 简单的随机函数
float random(vec2 st) {
    return fract(sin(dot(st.xy, vec2(12.9898,78.233))) * 43758.5453123);
}

void main() {
    vec2 uv = vUv;
    
    // 模拟原图：简单的网格
    vec3 color = vec3(step(0.9, fract(uv.x * 10.0)));
    
    // Glitch 逻辑
    // 1. 随机产生"故障条"
    float glitchTime = floor(uTime * 10.0); // 每秒变化10次
    float bar = step(0.95, random(vec2(floor(uv.y * 10.0), glitchTime)));
    
    // 2. 在故障条区域偏移 X 坐标
    float offset = random(vec2(glitchTime)) * 0.1;
    if (bar > 0.5) {
        color = vec3(step(0.9, fract((uv.x + offset) * 10.0)));
        color.r += 0.5; // 故障处变红
    }
    
    gl_FragColor = vec4(color, 1.0);
}
`} />

## 第三阶段：光线步进 (Ray Marching)

这是 GLSL 的终极奥义。
在传统的 3D 渲染中，我们通过三角形网格来构建模型。但在 Ray Marching 中，我们**没有模型**。整个 3D 场景是用数学公式（SDF）定义的。

### 原理
想象你的眼睛发射出一束光线。
1.  光线向前走一步。
2.  问："我现在离最近的物体有多远？"（SDF 函数）
3.  如果距离极小（撞到了），就画颜色。
4.  如果距离还很远，就继续向前走那个距离（步进）。

### 1. 绘制一个球体
在 Ray Marching 中，球体不是由几千个三角形组成的，它只是一个公式：`length(point) - radius`。

<ShaderPreview title="Ray Marching Sphere" code={`
varying vec2 vUv;

// 球体的 SDF (有向距离函数)
// p: 当前光线到达的点
// r: 球体半径
float sdfSphere(vec3 p, float r) {
    return length(p) - r;
}

void main() {
    // 1. 归一化坐标 (-1 到 1)
    vec2 uv = vUv * 2.0 - 1.0;
    
    // 2. 定义相机和光线
    vec3 cameraPos = vec3(0.0, 0.0, 3.0); // 相机在 Z=3
    vec3 rayDir = normalize(vec3(uv, -1.0)); // 光线向 Z 负方向发射
    
    // 3. 光线步进循环
    vec3 currentPos = cameraPos;
    float totalDist = 0.0;
    float minHitDist = 0.001; // 撞击阈值
    float maxDist = 100.0;    // 最远距离
    
    float hit = 0.0; // 是否击中
    
    for(int i = 0; i < 64; i++) {
        // 计算当前点到球体的距离
        float d = sdfSphere(currentPos, 1.0); // 半径为 1 的球
        
        if (d < minHitDist) {
            hit = 1.0;
            break;
        }
        
        if (totalDist > maxDist) break;
        
        // 步进
        totalDist += d;
        currentPos += rayDir * d;
    }
    
    // 4. 简单的光照
    vec3 color = vec3(0.0);
    if (hit > 0.5) {
        // 简单的漫反射：根据法线计算亮度
        // 球体表面的法线就是归一化的位置向量
        vec3 normal = normalize(currentPos);
        vec3 lightDir = normalize(vec3(1.0, 1.0, 1.0));
        float diff = max(dot(normal, lightDir), 0.0);
        
        color = vec3(1.0, 0.5, 0.2) * (diff * 0.8 + 0.2);
    }
    
    gl_FragColor = vec4(color, 1.0);
}
`} />

### 2. 形状融合 (Smooth Min)
Ray Marching 最酷的地方在于，因为形状是数学公式，所以它们可以像液体一样融合。
我们只需要改变距离场的计算方式，使用 `smin`（平滑最小值）代替 `min`。

<ShaderPreview title="Metaballs (Liquid)" code={`
uniform float uTime;
varying vec2 vUv;

// 平滑最小值函数 (创造融合效果)
float smin(float a, float b, float k) {
    float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
    return mix(b, a, h) - k * h * (1.0 - h);
}

float sdfSphere(vec3 p, float r) {
    return length(p) - r;
}

// 场景定义：两个球的融合
float map(vec3 p) {
    // 球 1：上下移动
    vec3 sphere1Pos = vec3(0.0, sin(uTime) * 1.0, 0.0);
    float d1 = sdfSphere(p - sphere1Pos, 0.8);
    
    // 球 2：静止在中心
    float d2 = sdfSphere(p, 0.6);
    
    // 融合！k = 0.2 是融合强度
    return smin(d1, d2, 0.2);
}

void main() {
    vec2 uv = vUv * 2.0 - 1.0;
    vec3 ro = vec3(0.0, 0.0, 3.0);
    vec3 rd = normalize(vec3(uv, -1.0));
    
    float t = 0.0;
    float hit = 0.0;
    
    for(int i = 0; i < 64; i++) {
        vec3 p = ro + rd * t;
        float d = map(p);
        
        if(d < 0.001) {
            hit = 1.0;
            break;
        }
        t += d;
        if(t > 10.0) break;
    }
    
    vec3 col = vec3(0.1); // 背景色
    
    if(hit > 0.5) {
        // 简单的深度着色
        col = vec3(0.0, 0.8, 1.0) * (1.0 - t * 0.15);
    }
    
    gl_FragColor = vec4(col, 1.0);
}
`} />

## 总结

从**顶点位移**的动态模型，到**后期处理**的全屏特效，再到**光线步进**的数学建模。这三项技术构成了现代 Shader 编程的高阶领域。

它们每一个深挖下去都是一个巨大的世界。希望这篇文章能成为你探索这些领域的地图。

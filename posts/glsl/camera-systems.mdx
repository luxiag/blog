# 掌镜者：深入理解 3D 摄像机系统

在 3D 世界中，**摄像机 (Camera)** 其实是不存在的。
我们并没有真的去移动"眼睛"，而是把整个世界往反方向移动了。

*   **View Matrix (视图矩阵)**：这就是摄像机的本质。如果摄像机向右移动 5 米，视图矩阵就是把所有物体向左移动 5 米。

今天，我们将解构摄像机背后的数学与逻辑。

## 一、 两种经典的控制模式

### 1. 轨道相机 (Orbit Controls)
这是展示模型最常用的方式：相机绕着一个目标点旋转。
想象摄像机被固定在一个**球体表面**上，它盯着球心。

**数学原理：球坐标系 (Spherical Coordinates)**
我们不直接存相机的 `x, y, z`，而是存：
*   **Radius (半径)**：离目标的距离。
*   **Phi (极角)**：与 Y 轴的夹角 (俯仰)。
*   **Theta (方位角)**：在 XZ 平面上的角度 (旋转)。

每次渲染时，我们把球坐标转回直角坐标：
```glsl
x = radius * sin(phi) * cos(theta);
y = radius * cos(phi);
z = radius * sin(phi) * sin(theta);
```

### 2. FPS 相机 (First Person Controls)
这是游戏的标准配置：WASD 移动，鼠标控制视角。
这里没有"目标点"，只有"前方"。

**核心逻辑**：
*   **Pitch (俯仰)**：绕 X 轴旋转（点头）。
*   **Yaw (偏航)**：绕 Y 轴旋转（摇头）。
*   **Roll (翻滚)**：绕 Z 轴旋转（歪头，FPS 中很少用）。

## 二、 欧拉角 vs 四元数：旋转的噩梦

当你尝试写一个 FPS 相机时，你可能会遇到一个恐怖的问题：**万向节死锁 (Gimbal Lock)**。

### 1. 欧拉角 (Euler Angles)
这是最直观的旋转表示：`Rotation(x, y, z)`。
意思是：先绕 X 转，再绕 Y 转，再绕 Z 转。

**死锁问题**：
当你向上看（绕 X 轴转 90 度）时，你的 Z 轴和 Y 轴重合了。这时候，无论你改变 Y 还是 Z，效果都是一样的（都在转同一个圈）。你失去了一个自由度！

### 2. 四元数 (Quaternion)
这是图形学的救星，也是数学的噩梦。它用 4 个数 `(x, y, z, w)` 来表示旋转。
你不需要理解它的复数原理，只需要记住它的**好处**：
*   **没有死锁**。
*   **插值平滑**：想在两个角度之间平滑过渡（比如摄像机跟随），用 **Slerp (球面线性插值)**，效果比欧拉角完美得多。

**实战建议**：在 Three.js 中，尽量使用 `camera.quaternion` 进行旋转，而不是 `camera.rotation`。

## 三、 视锥体剔除 (Frustum Culling)

渲染管线中最快的优化，就是**不渲染**。
如果一个物体在你的背后，或者在屏幕外面，为什么还要把它的几万个顶点送给 GPU 呢？

**视锥体 (Frustum)** 就是摄像机能看到的那个"平头金字塔"区域。

### 原理
1.  **提取平面**：视锥体由 6 个面组成（上、下、左、右、近、远）。
2.  **点面测试**：对于场景里的每个物体，我们算一下它是不是在所有 6 个面的"内侧"。
3.  **包围盒 (Bounding Box)**：为了算得快，我们不用物体的几万个顶点去算，而是给物体套一个简单的盒子（AABB 或 OBB），只要盒子在视锥体内，我们就认为物体可见。

*(注：下面的示例演示了视锥体剔除的概念。你可以移动方块，看它什么时候变红——变红代表"被剔除")*

<ShaderPreview title="Frustum Culling Logic" code={`
varying vec2 vUv;
uniform float uTime;

// 简单的盒子 SDF
float sdBox(vec2 p, vec2 b) {
    vec2 d = abs(p)-b;
    return length(max(d,0.0)) + min(max(d.x,d.y),0.0);
}

void main() {
    vec2 st = vUv * 2.0 - 1.0;
    
    // 1. 定义视锥体 (梯形区域)
    // 简单模拟：x 随 y 变宽
    float frustumWidth = 0.5 + (st.y + 1.0) * 0.5;
    float inFrustum = step(abs(st.x), frustumWidth) * step(-0.8, st.y) * step(st.y, 0.8);
    
    // 2. 移动的物体 (代表包围盒)
    vec2 pos = vec2(sin(uTime)*1.5, cos(uTime)*0.5);
    float boxDist = sdBox(st - pos, vec2(0.1));
    float isBox = 1.0 - step(0.0, boxDist);
    
    // 3. 剔除检测
    // 实际上是在 CPU 做，这里用 Shader 模拟视觉效果
    // 判断物体中心是否在视锥体内 (简化版)
    float boxInFrustumWidth = 0.5 + (pos.y + 1.0) * 0.5;
    bool isVisible = (abs(pos.x) < boxInFrustumWidth) && (pos.y > -0.8) && (pos.y < 0.8);
    
    vec3 color = vec3(0.1);
    
    // 绘制视锥体区域 (绿色背景)
    color += vec3(0.0, 0.2, 0.0) * inFrustum;
    
    // 绘制物体
    if (isBox > 0.5) {
        // 如果可见就是白色，被剔除就是红色
        color = isVisible ? vec3(1.0) : vec3(1.0, 0.0, 0.0);
    }
    
    gl_FragColor = vec4(color, 1.0);
}
`} />

## 总结

1.  **控制**：
    *   **轨道相机** = 球坐标系转换。
    *   **FPS 相机** = 俯仰 (Pitch) + 偏航 (Yaw)。
2.  **旋转**：
    *   **欧拉角**直观但有死锁。
    *   **四元数**复杂但完美，是插值和避免死锁的最佳选择。
3.  **优化**：
    *   **视锥体剔除**是 3D 引擎的第一道防线，它利用简单的几何运算（包围盒 vs 6个平面）在 CPU 端剔除看不见的物体，大幅减轻 GPU 负担。

掌握了摄像机，你就掌握了世界的"视角"。

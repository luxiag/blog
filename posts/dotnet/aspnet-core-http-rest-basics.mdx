# HTTP 与 RESTful API 基础：ASP.NET Core 开发前置知识

ASP.NET Core Web API 处理的是 HTTP 请求。如果不理解 HTTP，就很容易把 API 设计成“能跑但不清晰”的远程方法调用。

这篇文章先不讲 ASP.NET Core API，而是讲 Web API 开发必须知道的 HTTP 和 RESTful 基础。

## HTTP 请求由什么组成

一个 HTTP 请求通常包含：

- Method：请求方法，例如 `GET`、`POST`
- URL：请求地址，例如 `/api/products/1`
- Query String：查询字符串，例如 `?page=1&pageSize=20`
- Headers：请求头，例如 `Content-Type`、`Authorization`
- Body：请求体，常见是 JSON

示例请求：

```http
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <token>

{
  "name": "Keyboard",
  "price": 199
}
```

ASP.NET Core 的参数绑定，就是把这些位置的数据绑定到 Action 参数或 DTO 上。

## HTTP 响应由什么组成

HTTP 响应通常包含：

- Status Code：状态码，例如 `200`、`404`
- Headers：响应头，例如 `Content-Type`
- Body：响应体，常见是 JSON

示例响应：

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/products/1

{
  "id": 1,
  "name": "Keyboard",
  "price": 199
}
```

状态码是 API 设计的一部分，不要所有结果都返回 `200`。

## 常用 HTTP 方法

| 方法 | 语义 | 示例 |
|---|---|---|
| `GET` | 查询资源 | `GET /api/products` |
| `POST` | 创建资源或提交动作 | `POST /api/products` |
| `PUT` | 整体更新资源 | `PUT /api/products/1` |
| `PATCH` | 局部更新资源 | `PATCH /api/products/1` |
| `DELETE` | 删除资源 | `DELETE /api/products/1` |

建议按资源语义设计 API，而不是把动词都塞进 URL。

```text
推荐：GET /api/products/1
不推荐：GET /api/getProductById?id=1

推荐：POST /api/products
不推荐：POST /api/createProduct
```

## 常用状态码

| 状态码 | 含义 | 常见场景 |
|---|---|---|
| `200 OK` | 请求成功 | 查询成功、更新成功并返回内容 |
| `201 Created` | 创建成功 | 创建资源成功 |
| `204 No Content` | 成功但无响应体 | 删除成功、更新成功不返回内容 |
| `400 Bad Request` | 请求不合法 | 参数格式错误、模型验证失败 |
| `401 Unauthorized` | 未认证 | 没有登录或 Token 无效 |
| `403 Forbidden` | 无权限 | 已登录但权限不足 |
| `404 Not Found` | 资源不存在 | 商品 ID 不存在 |
| `409 Conflict` | 状态冲突 | 重复提交、并发冲突 |
| `500 Internal Server Error` | 服务器错误 | 未处理异常 |

ASP.NET Core Controller 中可以直接返回这些语义：

```csharp
return Ok(product);
return CreatedAtAction(nameof(GetById), new { id = product.Id }, product);
return NoContent();
return BadRequest();
return NotFound();
return Conflict();
```

## Header 的作用

Header 用来描述请求或响应的元信息。

常见请求头：

| Header | 作用 |
|---|---|
| `Content-Type` | 请求体格式，例如 `application/json` |
| `Accept` | 客户端期望的响应格式 |
| `Authorization` | 认证信息，例如 Bearer Token |
| `User-Agent` | 客户端信息 |
| `Origin` | 跨域请求来源 |

常见响应头：

| Header | 作用 |
|---|---|
| `Content-Type` | 响应体格式 |
| `Location` | 新资源地址，常配合 `201 Created` |
| `Cache-Control` | 缓存策略 |
| `Set-Cookie` | 设置 Cookie |

## Cookie

Cookie 是浏览器自动携带的小块数据，常用于认证和会话管理。

服务端通过 `Set-Cookie` 响应头设置 Cookie：

```http
HTTP/1.1 200 OK
Set-Cookie: session_id=abc123; Path=/; HttpOnly; Secure; SameSite=Strict
```

浏览器之后对同一域的请求会自动带上：

```http
GET /api/orders HTTP/1.1
Cookie: session_id=abc123
```

Cookie 关键属性：

| 属性 | 作用 |
|---|---|
| `HttpOnly` | JavaScript 无法读取，防止 XSS 窃取 |
| `Secure` | 只在 HTTPS 下传输 |
| `SameSite` | 控制跨站请求是否携带，防止 CSRF |
| `Path` | Cookie 生效的路径范围 |
| `Expires / Max-Age` | 过期时间 |

Web API 认证中，Cookie 和 JWT 是两种常见方案。Cookie 由浏览器自动管理，JWT 需要前端手动存储和携带。

## CORS

前后端分离时，前端（`https://app.example.com`）和后端 API（`https://api.example.com`）不同源，浏览器会阻止跨域请求。这叫同源策略。

CORS（Cross-Origin Resource Sharing）是浏览器和服务器协商跨域访问的机制。

预检请求：浏览器先发 `OPTIONS` 请求询问服务器是否允许跨域：

```http
OPTIONS /api/products HTTP/1.1
Origin: https://app.example.com
Access-Control-Request-Method: GET
```

服务器响应允许：

```http
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Authorization, Content-Type
Access-Control-Allow-Credentials: true
```

ASP.NET Core 中配置 CORS：

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowApp", policy =>
    {
        policy.WithOrigins("https://app.example.com")
              .AllowAnyHeader()
              .AllowAnyMethod()
              .AllowCredentials();
    });
});

app.UseCors("AllowApp");
```

注意：

- 不要用 `AllowAnyOrigin()` + `AllowCredentials()`，浏览器不允许。
- `UseCors()` 要放在 `UseRouting()` 之后、`UseAuthentication()` 之前。
- 生产环境必须明确指定允许的源。

## HTTPS

HTTPS = HTTP + TLS 加密。生产环境必须使用 HTTPS：

- 防止请求和响应被窃听。
- 防止请求被篡改（中间人攻击）。
- Cookie 和 JWT 在 HTTPS 下才安全传输。
- 很多浏览器 API（如 Service Worker、Geolocation）只允许 HTTPS 环境。

ASP.NET Core 默认启用 HTTPS 重定向：

```csharp
app.UseHttpsRedirection();
```

生产环境还应启用 HSTS，告诉浏览器始终使用 HTTPS：

```csharp
if (!app.Environment.IsDevelopment())
{
    app.UseHsts();
}
```

## RESTful API 的核心思想

RESTful API 的重点不是“URL 好看”，而是围绕资源设计接口。

资源示例：

- 商品：`/api/products`
- 订单：`/api/orders`
- 用户：`/api/users`

针对商品资源的 API：

| 方法 | 路径 | 含义 |
|---|---|---|
| `GET` | `/api/products` | 商品列表 |
| `GET` | `/api/products/1` | 商品详情 |
| `POST` | `/api/products` | 创建商品 |
| `PUT` | `/api/products/1` | 更新商品 |
| `DELETE` | `/api/products/1` | 删除商品 |

## Query、Route、Body 怎么选

| 位置 | 适合放什么 | 示例 |
|---|---|---|
| Route | 资源身份 | `/api/products/1` |
| Query | 筛选、排序、分页 | `?page=1&pageSize=20` |
| Body | 复杂输入数据 | JSON 创建商品请求 |
| Header | 元信息、认证信息 | `Authorization` |

示例：

```http
GET /api/products?keyword=keyboard&page=1&pageSize=20
```

```http
POST /api/products
Content-Type: application/json

{
  "name": "Keyboard",
  "price": 199
}
```

## 一个标准商品 API 设计

```text
GET    /api/products?keyword=keyboard&page=1&pageSize=20
GET    /api/products/{id}
POST   /api/products
PUT    /api/products/{id}
DELETE /api/products/{id}
```

创建商品请求：

```json
{
  "name": "Keyboard",
  "price": 199,
  "stock": 50
}
```

商品响应：

```json
{
  "id": 1,
  "name": "Keyboard",
  "price": 199,
  "stock": 50
}
```

## 总结

ASP.NET Core Web API 的所有高级能力，最终都会落到 HTTP 请求和响应上。先掌握 Method、URL、Header、Body、Status Code 和 RESTful 资源设计，再学习 Controller、参数绑定、认证授权和异常处理，会更清晰。

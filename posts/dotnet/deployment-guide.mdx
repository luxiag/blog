# .NET 应用企业级部署指南

在完成了应用的开发和测试之后，如何将其安全、稳定、高效地部署到生产环境，是每个技术团队必须面对的挑战。

本文将以一个典型的 .NET 8 Web API 项目为例，带你走完从服务器选型到最终上线的全过程。我们将采用现代化的容器化部署方案，这也是目前业界的主流选择。

---

## 1. 服务器选型

在购买服务器之前，我们需要根据业务规模和预算做出选择。

### 1.1 云服务商 vs 自建机房

*   **公有云（AWS/Azure/阿里云/腾讯云）**：
    *   **优点**：弹性伸缩，无需维护硬件，服务丰富（RDS, Redis, 对象存储）。
    *   **缺点**：长期运行成本可能较高。
    *   **适用**：初创企业、互联网业务、需要快速迭代的项目。
*   **自建机房 / 托管服务器**：
    *   **优点**：硬件资源可控，数据安全性高（物理隔离），长期成本低。
    *   **缺点**：前期投入大，维护成本高，不仅要维护软件还要维护硬件和网络。
    *   **适用**：大型国企、银行、对数据安全有极高要求的场景。

### 1.2 配置估算

对于一个初期日活 1万左右的 .NET 应用，推荐配置：

*   **Web 服务器**：2核 4G 或 4核 8G（建议至少 2 台做负载均衡）。
*   **数据库**：4核 8G 或更高（强烈建议使用云数据库 RDS，省去运维麻烦）。
*   **Redis**：2核 4G（云 Redis）。
*   **带宽**：按流量计费或固定带宽（初期 5M-10M）。

## 2. 操作系统准备 (Linux)

虽然 .NET 可以在 Windows 上运行，但在服务器端，Linux（如 Ubuntu 或 CentOS/AlmaLinux）通常是更优的选择，因为它们更轻量、更稳定且免费。

以下以 **Ubuntu 22.04 LTS** 为例。

### 2.1 基础初始化

```bash
# 1. 更新系统
sudo apt update && sudo apt upgrade -y

# 2. 设置时区（非常重要，避免日志时间对不上）
sudo timedatectl set-timezone Asia/Shanghai

# 3. 创建部署用户（不要直接用 root 跑应用）
sudo adduser deployer
sudo usermod -aG sudo deployer
```

### 2.2 安装 Docker 环境

参照之前的《Docker 完全指南》，安装 Docker 和 Docker Compose。

```bash
# 简易安装脚本
curl -fsSL https://get.docker.com | bash

# 将当前用户加入 docker 组（避免每次都输 sudo）
sudo usermod -aG docker deployer
newgrp docker
```

## 3. 应用容器化

要实现"一次构建，到处运行"，我们需要为 .NET 应用编写 `Dockerfile`。

### 3.1 编写 Dockerfile

在项目根目录下创建 `Dockerfile`：

```dockerfile
# 第一阶段：构建 (Build)
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# 先复制 csproj 并还原依赖（利用层缓存）
COPY ["MyApi/MyApi.csproj", "MyApi/"]
RUN dotnet restore "MyApi/MyApi.csproj"

# 复制其余代码并发布
COPY . .
WORKDIR "/src/MyApi"
RUN dotnet publish "MyApi.csproj" -c Release -o /app/publish /p:UseAppHost=false

# 第二阶段：运行 (Runtime)
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS final
WORKDIR /app
EXPOSE 8080

# 设置时区
ENV TZ=Asia/Shanghai

# 复制发布产物
COPY --from=build /app/publish .

# 启动命令
ENTRYPOINT ["dotnet", "MyApi.dll"]
```

### 3.2 添加 .dockerignore

避免将不必要的文件（如 bin, obj, .git）复制到镜像中：

```text
**/.dockerignore
**/.env
**/bin
**/obj
**/.git
**/.vscode
```

## 4. 搭建 CI/CD 流水线

手动构建镜像并上传服务器太慢且容易出错。我们使用 **GitHub Actions**（或 GitLab CI/Jenkins）来实现自动化。

### 4.1 GitHub Actions 示例

在项目根目录创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to Production

on:
  push:
    branches: [ "main" ]

env:
  IMAGE_NAME: my-registry.com/my-api
  TAG: ${{ github.sha }}

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v3
    
    # 登录 Docker 仓库（如阿里云镜像服务）
    - name: Login to Registry
      uses: docker/login-action@v2
      with:
        registry: registry.cn-hangzhou.aliyuncs.com
        username: ${{ secrets.DOCKER_USERNAME }}
        password: ${{ secrets.DOCKER_PASSWORD }}
        
    # 构建并推送镜像
    - name: Build and Push
      run: |
        docker build -t $IMAGE_NAME:$TAG .
        docker push $IMAGE_NAME:$TAG
        
  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest
    steps:
    - name: SSH Remote Commands
      uses: appleboy/ssh-action@master
      with:
        host: ${{ secrets.SERVER_HOST }}
        username: ${{ secrets.SERVER_USER }}
        key: ${{ secrets.SSH_PRIVATE_KEY }}
        script: |
          # 登录仓库
          docker login --username=${{ secrets.DOCKER_USERNAME }} --password=${{ secrets.DOCKER_PASSWORD }} registry.cn-hangzhou.aliyuncs.com
          
          # 更新服务（假设使用 docker-compose）
          cd /app/deploy
          # 修改 .env 文件中的 TAG 变量
          sed -i "s/TAG=.*/TAG=${{ github.sha }}/" .env
          
          # 拉取新镜像并重启
          docker-compose pull
          docker-compose up -d
          
          # 清理旧镜像
          docker image prune -f
```

## 5. 生产环境部署方案

在生产环境，我们通常不会只跑一个容器。我们需要考虑反向代理、HTTPS、健康检查和日志。

### 5.1 目录结构规划

在服务器上建立规范的目录：

```
/app/deploy/
├── docker-compose.yml
├── .env                 # 存放版本号和敏感信息
├── nginx/
│   ├── nginx.conf
│   └── certs/           # SSL 证书
└── logs/                # 挂载日志目录
```

### 5.2 编写 docker-compose.yml

```yaml
version: '3.8'

services:
  # .NET 核心应用
  app:
    image: my-registry.com/my-api:${TAG}
    restart: always
    environment:
      - ConnectionStrings__Default=Server=db;Database=mydb;User=root;Password=secret;
      - ASPNETCORE_ENVIRONMENT=Production
    volumes:
      - ./logs/app:/app/logs
    networks:
      - app-net

  # Nginx 反向代理
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/certs:/etc/nginx/certs:ro
      - ./logs/nginx:/var/log/nginx
    depends_on:
      - app
    networks:
      - app-net

networks:
  app-net:
    driver: bridge
```

### 5.3 Nginx 配置 (反向代理)

`/app/deploy/nginx/nginx.conf`:

```nginx
events { worker_connections 1024; }

http {
    upstream dotnet_app {
        # 如果跑了多个 app 实例，可以在这里配置负载均衡
        server app:8080;
    }

    server {
        listen 80;
        server_name myapp.com;
        # 强制跳转 HTTPS
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl;
        server_name myapp.com;

        ssl_certificate     /etc/nginx/certs/myapp.com.pem;
        ssl_certificate_key /etc/nginx/certs/myapp.com.key;

        location / {
            proxy_pass http://dotnet_app;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection keep-alive;
            proxy_set_header Host $host;
            proxy_cache_bypass $http_upgrade;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }
}
```

## 6. 高级话题

### 6.1 健康检查 (Health Checks)

在 .NET 应用中注册健康检查：

```csharp
// Program.cs
builder.Services.AddHealthChecks();

var app = builder.Build();
app.MapHealthChecks("/health");
```

在 `docker-compose.yml` 中添加检查：

```yaml
  app:
    # ...
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 30s
      timeout: 10s
      retries: 3
```

### 6.2 滚动更新 (Zero Downtime)

如果单机部署，重启会有短暂亦即。要实现零停机，你可以：

1.  **蓝绿部署**：启动新容器，健康检查通过后，Nginx 切换流量，再关旧容器。
2.  **Kubernetes (K8s)**：如果你有 K8s 集群，它原生支持滚动更新。
3.  **多机负载均衡**：在前端挂一个云负载均衡（SLB），后端两台服务器。发布时一台一台发，SLB 会自动剔除不健康的节点。

### 6.3 日志与监控

*   **日志**：不要让日志只留在文件里。推荐使用 **ELK Stack** (Elasticsearch, Logstash, Kibana) 或轻量级的 **Loki + Grafana**。
*   **监控**：使用 **Prometheus** 抓取 .NET 的 Metrics，配合 **Grafana** 展示 CPU、内存、QPS 等仪表盘。

## 7. 上线前的检查清单

在按下发布按钮前，请确认：

*   [ ] **配置分离**：数据库密码、API Key 等敏感信息是否通过环境变量注入？
*   [ ] **数据库备份**：生产库是否开启了自动备份？
*   [ ] **HTTPS**：证书是否有效？SSL 评分是否达标？
*   [ ] **防火墙**：服务器安全组是否只开放了 80/443 和 SSH 端口？
*   [ ] **错误页**：当后端挂掉时，Nginx 是否有友好的 502 页面？

## 总结

部署不仅仅是把代码跑起来，更是一套关于稳定性、安全性和可维护性的系统工程。通过 **Docker + CI/CD + Nginx** 的组合，我们构建了一个标准化的现代 .NET 应用交付流程。

希望这篇指南能帮助你顺利将应用推向生产环境！

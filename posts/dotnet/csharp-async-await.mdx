# C# async/await 异步编程从原理到实践

异步编程是现代 .NET 开发的基础能力。Web API 调数据库、调用外部 HTTP 接口、读写文件、处理消息队列，几乎都会遇到 `Task`、`async` 和 `await`。

很多人一开始会把异步理解成“开一个新线程”，这并不准确。C# 的异步编程更核心的价值是：当代码在等待 I/O 结果时，不阻塞当前线程，让线程可以去处理别的工作。

这篇文章按一条完整链路展开：先理解同步代码的问题，再理解 `Task`、`async/await`，最后讲取消、异常、并发控制和常见误区。

## 为什么需要异步

同步代码在等待 I/O 时会阻塞线程。假设一个 Web API 需要调用数据库，数据库响应需要 200ms，如果使用同步等待，这 200ms 内请求线程基本处于空等状态。

```csharp
using System;
using System.Threading;

public class Program
{
    public static void Main()
    {
        Console.WriteLine("开始读取数据");

        // 模拟同步 I/O：当前线程会被阻塞 2 秒
        Thread.Sleep(2000);

        Console.WriteLine("读取完成");
    }
}
```

异步版本不是让数据库变快，而是让线程在等待期间释放出来。

```csharp
using System;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        Console.WriteLine("开始读取数据");

        // 模拟异步 I/O：等待期间不会阻塞当前线程
        await Task.Delay(2000);

        Console.WriteLine("读取完成");
    }
}
```

:::info
`Task.Delay` 只是演示用法。真实项目中常见的异步 I/O 包括 `HttpClient.GetAsync`、EF Core 的 `ToListAsync`、文件流的 `ReadAsync` 等。
:::

## Task 是什么

`Task` 表示一个将来会完成的操作。这个操作可能成功、失败，也可能被取消。

`Task` 不返回结果，`Task<T>` 返回一个 `T` 类型结果。

```csharp
using System;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        Task work = SaveLogAsync();
        await work;

        Task<int> countTask = GetOrderCountAsync();
        int count = await countTask;

        Console.WriteLine($"订单数量：{count}");
    }

    static async Task SaveLogAsync()
    {
        await Task.Delay(300);
        Console.WriteLine("日志保存完成");
    }

    static async Task<int> GetOrderCountAsync()
    {
        await Task.Delay(300);
        return 42;
    }
}
```

`Task` 有几个重要状态：

- `WaitingForActivation`：等待异步操作完成
- `RanToCompletion`：成功完成
- `Faulted`：执行过程中抛出异常
- `Canceled`：操作被取消

日常开发中通常不需要手动检查这些状态，直接 `await` 即可。

## ValueTask：避免不必要的堆分配

`Task` 是引用类型，每次创建都会在堆上分配。对于同步完成的高频场景，`ValueTask<T>` 可以避免这个分配。

```csharp
public class CacheService
{
    private readonly Dictionary<string, string> _cache = new();

    public ValueTask<string> GetAsync(string key)
    {
        if (_cache.TryGetValue(key, out string? value))
        {
            return new ValueTask<string>(value);
        }

        return new ValueTask<string>(LoadFromDbAsync(key));
    }

    private async Task<string> LoadFromDbAsync(string key)
    {
        await Task.Delay(100);
        return $"data_{key}";
    }
}
```

`ValueTask<T>` 的限制：
- **不能被多次 await**：一个 `ValueTask` 只能 await 一次，第二次会抛异常
- **不能并发 await**：多个调用者不能同时 await 同一个 `ValueTask`
- **不推荐 `.Result` 或 `.GetAwaiter().GetResult()`**

大多数场景用 `Task<T>` 就够了。只在性能分析确认 `Task` 分配是瓶颈、且方法经常同步完成时，才考虑 `ValueTask<T>`。

## TaskCompletionSource：手动创建 Task

`TaskCompletionSource<T>` 允许你手动控制 Task 的完成时机，常用于桥接回调模式到 async/await。

```csharp
public class ManualTaskExample
{
    public Task<string> WaitForUserInputAsync()
    {
        var tcs = new TaskCompletionSource<string>();

        Console.Write("请输入值：");
        string? input = Console.ReadLine();

        if (string.IsNullOrEmpty(input))
        {
            tcs.SetException(new InvalidOperationException("输入不能为空"));
        }
        else
        {
            tcs.SetResult(input);
        }

        return tcs.Task;
    }
}
```

`SetResult` 标记成功，`SetException` 标记失败，`SetCanceled` 标记取消。这在单元测试中模拟异步操作、封装事件驱动 API 时非常有用。

## async 和 await 做了什么

`async` 标记一个方法内部可以使用 `await`。`await` 会把方法拆成两段：等待之前的代码先执行，等待完成后再继续执行后面的代码。

```csharp
using System;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        Console.WriteLine("1. 调用前");
        string name = await GetNameAsync();
        Console.WriteLine($"3. 调用后：{name}");
    }

    static async Task<string> GetNameAsync()
    {
        Console.WriteLine("2. 开始等待");
        await Task.Delay(1000);
        return "Alice";
    }
}
```

编译器会把 `async` 方法转换成状态机。你不需要手写状态机，但要理解：`await` 后面的代码不是立刻执行，而是等任务完成后继续执行。

## 异步不是一定创建新线程

这是最常见的误解。对于 I/O 异步，等待期间通常不需要一个线程一直挂在那里。

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        Console.WriteLine($"开始线程：{Environment.CurrentManagedThreadId}");

        await Task.Delay(500);

        Console.WriteLine($"恢复线程：{Environment.CurrentManagedThreadId}");
    }
}
```

在控制台程序里，`await` 之后可能恢复到不同线程；在 ASP.NET Core 中没有传统 ASP.NET 的请求同步上下文，通常不需要为了避免死锁而到处写 `ConfigureAwait(false)`。

### ConfigureAwait 的原理

`ConfigureAwait(false)` 告诉编译器：`await` 之后不需要回到原来的上下文继续执行。

在有同步上下文的环境（WinForms、WPF、旧版 ASP.NET）中，`await` 默认会回到原上下文继续执行。如果同步上下文只有一个线程（如 UI 线程），而你在同步方法中用 `.Result` 等待异步结果，就会产生死锁：UI 线程在等 `.Result`，而异步方法在等 UI 线程回来继续执行。

```csharp
// UI 线程中：这段代码会死锁
private void Button_Click(object sender, EventArgs e)
{
    var data = GetDataAsync().Result; // 死锁！
}

// 修复方式一：一路异步到底
private async void Button_Click(object sender, EventArgs e)
{
    var data = await GetDataAsync();
}

// 修复方式二：库代码加 ConfigureAwait(false)
public async Task<string> GetDataAsync()
{
    await Task.Delay(100).ConfigureAwait(false);
    return "data";
}
```

ASP.NET Core 没有同步上下文，`ConfigureAwait(false)` 加不加效果一样。但库代码建议加，因为调用方可能是有同步上下文的环境。

## 顺序等待与并发等待

如果多个异步操作互不依赖，应该先启动，再统一等待。

```csharp
using System;
using System.Diagnostics;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        var stopwatch = Stopwatch.StartNew();

        Task<string> userTask = GetUserAsync();
        Task<string> orderTask = GetOrderAsync();
        Task<string> messageTask = GetMessageAsync();

        string[] results = await Task.WhenAll(userTask, orderTask, messageTask);

        Console.WriteLine(string.Join(", ", results));
        Console.WriteLine($"耗时：{stopwatch.ElapsedMilliseconds}ms");
    }

    static async Task<string> GetUserAsync()
    {
        await Task.Delay(1000);
        return "用户";
    }

    static async Task<string> GetOrderAsync()
    {
        await Task.Delay(1000);
        return "订单";
    }

    static async Task<string> GetMessageAsync()
    {
        await Task.Delay(1000);
        return "消息";
    }
}
```

如果写成连续 `await`，总耗时接近 3 秒；使用 `Task.WhenAll`，总耗时接近 1 秒。

### WhenAny：任一完成即可

`Task.WhenAny` 返回最先完成的任务，适合"竞速"场景。

```csharp
using System;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        Task<string> cacheTask = GetFromCacheAsync();
        Task<string> dbTask = GetFromDbAsync();

        Task<string> firstCompleted = await Task.WhenAny(cacheTask, dbTask);

        Console.WriteLine($"最先返回：{await firstCompleted}");
    }

    static async Task<string> GetFromCacheAsync()
    {
        await Task.Delay(100);
        return "缓存数据";
    }

    static async Task<string> GetFromDbAsync()
    {
        await Task.Delay(500);
        return "数据库数据";
    }
}
```

注意：`WhenAny` 返回的 `Task` 可能是失败的任务。如果需要处理异常，仍需 `await` 该任务。未完成的任务也不会自动取消，需要自行处理。

## 异常处理

异步方法内部抛出的异常会存储在 `Task` 中，`await` 时重新抛出。

```csharp
using System;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        try
        {
            await PayAsync();
        }
        catch (InvalidOperationException ex)
        {
            Console.WriteLine($"支付失败：{ex.Message}");
        }
    }

    static async Task PayAsync()
    {
        await Task.Delay(300);
        throw new InvalidOperationException("余额不足");
    }
}
```

不要用 `Task.Wait()` 或 `.Result` 去拿异步结果，它们会把异常包进 `AggregateException`，也可能造成线程阻塞。

### WhenAll 中的多个异常

`Task.WhenAll` 中多个任务失败时，`await` 只抛出第一个异常。要看到所有异常，需要检查 `Task.Exception`：

```csharp
Task task1 = Task.Run(() => throw new InvalidOperationException("任务1失败"));
Task task2 = Task.Run(() => throw new ArgumentException("任务2失败"));

Task all = Task.WhenAll(task1, task2);

try
{
    await all;
}
catch
{
    if (all.Exception is not null)
    {
        foreach (Exception inner in all.Exception.InnerExceptions)
        {
            Console.WriteLine($"{inner.GetType().Name}: {inner.Message}");
        }
    }
}
```

`all.Exception` 是 `AggregateException`，包含所有任务的异常。

```csharp
// 不推荐
var result = GetDataAsync().Result;

// 推荐
var result = await GetDataAsync();
```

## 取消异步操作

取消不是强制杀死任务，而是通过 `CancellationToken` 协作式通知。

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        using var cts = new CancellationTokenSource();
        cts.CancelAfter(1200);

        try
        {
            await DownloadAsync(cts.Token);
        }
        catch (OperationCanceledException)
        {
            Console.WriteLine("下载已取消");
        }
    }

    static async Task DownloadAsync(CancellationToken cancellationToken)
    {
        for (int i = 1; i <= 10; i++)
        {
            cancellationToken.ThrowIfCancellationRequested();
            await Task.Delay(500, cancellationToken);
            Console.WriteLine($"下载进度：{i * 10}%");
        }
    }
}
```

ASP.NET Core 的 Action 可以直接接收 `CancellationToken`，客户端断开连接时框架会触发取消。

```csharp
[HttpGet("orders")]
public async Task<IActionResult> GetOrders(CancellationToken cancellationToken)
{
    var orders = await _dbContext.Orders
        .AsNoTracking()
        .ToListAsync(cancellationToken);

    return Ok(orders);
}
```

## 控制并发数量

并发不是越多越好。比如同时调用 1000 个外部接口，可能把自己或对方服务打挂。可以用 `SemaphoreSlim` 限制并发数。

```csharp
using System;
using System.Collections.Generic;
using System.Linq;
using System.Threading;
using System.Threading.Tasks;

public class Program
{
    public static async Task Main()
    {
        var ids = Enumerable.Range(1, 10);
        using var semaphore = new SemaphoreSlim(3);

        List<Task> tasks = ids.Select(async id =>
        {
            await semaphore.WaitAsync();
            try
            {
                await ProcessAsync(id);
            }
            finally
            {
                semaphore.Release();
            }
        }).ToList();

        await Task.WhenAll(tasks);
    }

    static async Task ProcessAsync(int id)
    {
        Console.WriteLine($"开始处理 {id}");
        await Task.Delay(800);
        Console.WriteLine($"完成处理 {id}");
    }
}
```

## async void 只用于事件处理

普通异步方法不要返回 `void`。`async void` 的异常无法被调用方通过 `await` 捕获，也无法组合等待。

```csharp
// 不推荐
public async void SaveAsync()
{
    await Task.Delay(100);
}

// 推荐
public async Task SaveAsync()
{
    await Task.Delay(100);
}
```

`async void` 的主要合理场景是 UI 事件处理器，因为事件委托签名通常要求返回 `void`。

## ASP.NET Core 中的建议

在 ASP.NET Core 项目中，异步代码通常遵循这些规则：

- Controller、Minimal API、Service、Repository 尽量一路异步到底
- EF Core 查询使用 `ToListAsync`、`FirstOrDefaultAsync`、`SaveChangesAsync`
- HTTP 调用使用 `HttpClient` 的异步方法
- 不要用 `.Result`、`.Wait()` 阻塞异步调用
- 能传 `CancellationToken` 就传下去
- 并发调用外部资源时限制并发数量

## Channel：异步生产者-消费者模型

`Channel<T>` 是 .NET 提供的异步安全队列，适合生产者和消费者解耦的场景。

```csharp
using System.Threading.Channels;

var channel = Channel.CreateBounded<string>(capacity: 10);

// 生产者
async Task ProduceAsync()
{
    for (int i = 1; i <= 5; i++)
    {
        await channel.Writer.WriteAsync($"消息{i}");
        Console.WriteLine($"写入：消息{i}");
    }

    channel.Writer.Complete();
}

// 消费者
async Task ConsumeAsync()
{
    await foreach (string message in channel.Reader.ReadAllAsync())
    {
        Console.WriteLine($"读取：{message}");
    }
}

await Task.WhenAll(ProduceAsync(), ConsumeAsync());
```

`Bounded` 限制容量，满了会阻塞写入；`Unbounded` 不限容量。`ReadAllAsync` 返回 `IAsyncEnumerable<T>`，可以用 `await foreach` 消费。

`Channel<T>` 比自己用 `Queue<T>` + 锁实现更安全，也比 `BlockingCollection<T>` 更适合异步场景。

## 总结

`async/await` 解决的是等待 I/O 时的线程占用问题，不是让单个操作本身变快。理解它的关键是：`Task` 表示未来完成的操作，`await` 表示等待这个操作并在完成后继续执行。

进阶要点：`ValueTask<T>` 避免同步完成场景的堆分配；`TaskCompletionSource<T>` 手动控制 Task 完成；`WhenAny` 处理竞速场景；`ConfigureAwait(false)` 在库代码中避免死锁；`Channel<T>` 构建异步生产者-消费者模型。

掌握异步编程后，你才能更稳地理解 ASP.NET Core、EF Core、HttpClient、后台服务和微服务调用这些更上层的内容。

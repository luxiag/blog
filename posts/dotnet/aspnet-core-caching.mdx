# ASP.NET Core 缓存：MemoryCache、DistributedCache 与 Redis

缓存用于减少重复计算、降低数据库和外部服务压力。但缓存不是越多越好，真正困难的是 Key 设计、过期策略和一致性边界。

:::tip 阶段三阅读顺序
建议先掌握 [EF Core 数据访问](/posts/dotnet/aspnet-core-ef-core)，再学习缓存。缓存通常用于数据库查询结果、外部接口结果和热点配置数据。
:::

## IMemoryCache：单机内存缓存

注册：

```csharp
builder.Services.AddMemoryCache();
```

使用：

```csharp
public class ProductCacheService
{
    private readonly IMemoryCache _cache;
    private readonly AppDbContext _dbContext;

    public ProductCacheService(IMemoryCache cache, AppDbContext dbContext)
    {
        _cache = cache;
        _dbContext = dbContext;
    }

    public async Task<ProductDto?> GetByIdAsync(int id, CancellationToken cancellationToken)
    {
        string key = $"product:{id}";

        return await _cache.GetOrCreateAsync(key, async entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
            entry.SlidingExpiration = TimeSpan.FromMinutes(1);

            return await _dbContext.Products
                .AsNoTracking()
                .Where(p => p.Id == id)
                .Select(p => new ProductDto(p.Id, p.Name, p.Price))
                .FirstOrDefaultAsync(cancellationToken);
        });
    }
}
```

`IMemoryCache` 只适合单实例应用或不要求多实例共享的缓存。

## 过期策略

常见过期方式：

| 策略 | 含义 | 场景 |
|---|---|---|
| Absolute Expiration | 固定时间后过期 | 商品详情缓存 5 分钟 |
| Sliding Expiration | 一段时间不用才过期 | 热点配置、字典数据 |
| 手动删除 | 数据变更时删除 Key | 更新商品后删除缓存 |

更新数据后要考虑删除缓存：

```csharp
_cache.Remove($"product:{id}");
```

## IDistributedCache

多实例部署时，单机内存缓存无法共享。可以使用 `IDistributedCache` 抽象。

注册 Redis：

```bash
dotnet add package Microsoft.Extensions.Caching.StackExchangeRedis
```

```csharp
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = builder.Configuration.GetConnectionString("Redis");
    options.InstanceName = "ProductApi:";
});
```

使用：

```csharp
public class ProductDistributedCache
{
    private readonly IDistributedCache _cache;

    public ProductDistributedCache(IDistributedCache cache)
    {
        _cache = cache;
    }

    public async Task SetAsync(ProductDto product, CancellationToken cancellationToken)
    {
        string key = $"product:{product.Id}";
        string json = JsonSerializer.Serialize(product);

        await _cache.SetStringAsync(key, json, new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
        }, cancellationToken);
    }

    public async Task<ProductDto?> GetAsync(int id, CancellationToken cancellationToken)
    {
        string? json = await _cache.GetStringAsync($"product:{id}", cancellationToken);

        return json is null ? null : JsonSerializer.Deserialize<ProductDto>(json);
    }
}
```

## 缓存 Key 设计

建议 Key 具备明确层级和业务含义：

```text
product:{id}
product:list:category:{categoryId}:page:{page}:size:{pageSize}
user:{userId}:permissions
```

不要使用过短、含义不清或可能冲突的 Key。

## Output Cache

ASP.NET Core 7+ 提供了输出缓存中间件，可以直接缓存 HTTP 响应。

注册：

```csharp
builder.Services.AddOutputCache(options =>
{
    options.AddBasePolicy(builder => builder.Expire(TimeSpan.FromSeconds(30)));
    options.AddPolicy("Products", builder => builder.Expire(TimeSpan.FromMinutes(5)).Tag("products"));
});

var app = builder.Build();

app.UseOutputCache();
```

在 Controller 或 Minimal API 中使用：

```csharp
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    private readonly AppDbContext _dbContext;

    public ProductsController(AppDbContext dbContext)
    {
        _dbContext = dbContext;
    }

    [HttpGet]
    [OutputCache(PolicyName = "Products")]
    public async Task<ActionResult<List<ProductDto>>> GetProducts(
        int categoryId = 0, int page = 1, int pageSize = 20,
        CancellationToken cancellationToken = default)
    {
        var query = _dbContext.Products.AsNoTracking().AsQueryable();

        if (categoryId > 0)
            query = query.Where(p => p.CategoryId == categoryId);

        List<ProductDto> products = await query
            .OrderBy(p => p.Id)
            .Skip((page - 1) * pageSize)
            .Take(pageSize)
            .Select(p => new ProductDto(p.Id, p.Name, p.Price))
            .ToListAsync(cancellationToken);

        return Ok(products);
    }
}
```

首次请求时查询数据库并缓存整个 JSON 响应，后续 5 分钟内相同参数的请求直接返回缓存，不再执行 Action 方法。

手动清除缓存：

```csharp
await outputCacheStore.EvictByTagAsync("products", CancellationToken.None);
```

Output Cache 缓存的是整个 HTTP 响应，适合不依赖用户身份的公共接口。

## Response Cache

`[ResponseCache]` 通过设置 HTTP 缓存头（`Cache-Control`、`ETag`）让浏览器和代理服务器缓存响应：

```csharp
[HttpGet]
[ResponseCache(Duration = 60, VaryByQueryKeys = new[] { "page", "pageSize" })]
public IActionResult GetProducts(int page = 1, int pageSize = 20)
{
    return Ok();
}
```

| 特性 | Output Cache | Response Cache |
|---|---|---|
| 缓存位置 | 服务端内存 | 浏览器/代理（HTTP 头） |
| 控制权 | 服务端完全控制 | 客户端可能忽略 |
| 适用场景 | 服务端缓存计算结果 | 减少网络传输 |

Response Cache 不保证客户端一定使用缓存，它只是设置 HTTP 头。需要确定缓存命中时用 Output Cache。

## 数据一致性

缓存和数据库的数据可能不一致。常见策略：

| 策略 | 做法 | 适用场景 |
|---|---|---|
| Cache Aside | 读时填缓存，写时删缓存 | 最常用，通用方案 |
| Write Through | 写入时同时更新缓存和数据库 | 写少读多 |
| Write Behind | 先写缓存，异步写数据库 | 写密集，容忍短暂不一致 |

Cache Aside 是最常用的模式：

:::note 泛型扩展方法来源
前面 `IDistributedCache` 一节只演示了 `GetStringAsync`/`SetStringAsync` + 手动序列化。下面的 `_cache.GetAsync<ProductDto>` 和 `_cache.SetAsync(key, product, TimeSpan)` 是对 `IDistributedCache` 的泛型扩展方法，需要自行封装。核心实现如下：
:::

```csharp
public static class DistributedCacheExtensions
{
    private static readonly JsonSerializerOptions _jsonOptions = new()
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase
    };

    public static async Task<T?> GetAsync<T>(
        this IDistributedCache cache, string key, CancellationToken cancellationToken = default)
    {
        string? json = await cache.GetStringAsync(key, cancellationToken);
        if (json is null) return default;

        return JsonSerializer.Deserialize<T>(json, _jsonOptions);
    }

    public static async Task SetAsync<T>(
        this IDistributedCache cache, string key, T value, TimeSpan expiration,
        CancellationToken cancellationToken = default)
    {
        string json = JsonSerializer.Serialize(value, _jsonOptions);

        await cache.SetStringAsync(key, json, new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = expiration
        }, cancellationToken);
    }
}
```

将此静态类放在项目中即可全局使用 `_cache.GetAsync<T>()` 和 `_cache.SetAsync(key, value, expiration)`。

完整的 Cache Aside 实现：

```csharp
public async Task<ProductDto?> GetByIdAsync(int id, CancellationToken cancellationToken)
{
    string key = $"product:{id}";

    ProductDto? cached = await _cache.GetAsync<ProductDto>(key, cancellationToken);
    if (cached is not null) return cached;

    ProductDto? product = await _dbContext.Products
        .AsNoTracking()
        .Where(p => p.Id == id)
        .Select(p => new ProductDto(p.Id, p.Name, p.Price))
        .FirstOrDefaultAsync(cancellationToken);

    if (product is not null)
    {
        await _cache.SetAsync(key, product, TimeSpan.FromMinutes(5), cancellationToken);
    }

    return product;
}

public async Task UpdateAsync(int id, UpdateProductRequest request, CancellationToken cancellationToken)
{
    // update database
    await _dbContext.SaveChangesAsync(cancellationToken);

    // delete cache
    await _cache.RemoveAsync($"product:{id}", cancellationToken);
}
```

关键：**更新数据库后删除缓存，而不是更新缓存**。删除比更新更安全，避免并发写入导致缓存与数据库不一致。

## 常见问题

### 缓存穿透

查询一个数据库中不存在的数据，缓存中没有，数据库中也没有，每次请求都穿透缓存直接打到数据库。攻击者可以利用这一点用大量不存在的 Key 压垮数据库。

解决方式是缓存空结果，但必须设置较短的过期时间，否则大量无效 Key 会浪费缓存空间：

```csharp
public async Task<ProductDto?> GetByIdAsync(int id, CancellationToken cancellationToken)
{
    string key = $"product:{id}";
    string nullKey = $"product:null:{id}";

    ProductDto? cached = await _cache.GetAsync<ProductDto>(key, cancellationToken);
    if (cached is not null) return cached;

    string? nullFlag = await _cache.GetStringAsync(nullKey, cancellationToken);
    if (nullFlag is not null) return null;

    ProductDto? product = await _dbContext.Products
        .AsNoTracking()
        .Where(p => p.Id == id)
        .Select(p => new ProductDto(p.Id, p.Name, p.Price))
        .FirstOrDefaultAsync(cancellationToken);

    if (product is null)
    {
        await _cache.SetStringAsync(nullKey, "1", new DistributedCacheEntryOptions
        {
            AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(1)
        }, cancellationToken);
        return null;
    }

    await _cache.SetAsync(key, product, TimeSpan.FromMinutes(5), cancellationToken);
    return product;
}
```

也可以在入口层用布隆过滤器（Bloom Filter）快速判断 Key 是否可能存在，不存在直接返回，避免查数据库。

### 缓存击穿

某个热点 Key 过期的瞬间，大量并发请求同时发现缓存未命中，同时去数据库加载数据，导致数据库瞬时压力暴增。

解决方式是在缓存未命中时加互斥锁，只让一个请求去数据库加载，其余请求等待结果：

```csharp
public class ProductCacheService
{
    private readonly IMemoryCache _cache;
    private readonly AppDbContext _dbContext;
    private readonly SemaphoreSlim _semaphore = new(1, 1);

    public async Task<ProductDto?> GetByIdAsync(int id, CancellationToken cancellationToken)
    {
        string key = $"product:{id}";

        if (_cache.TryGetValue(key, out ProductDto? cached))
            return cached;

        await _semaphore.WaitAsync(cancellationToken);
        try
        {
            if (_cache.TryGetValue(key, out cached))
                return cached;

            ProductDto? product = await _dbContext.Products
                .AsNoTracking()
                .Where(p => p.Id == id)
                .Select(p => new ProductDto(p.Id, p.Name, p.Price))
                .FirstOrDefaultAsync(cancellationToken);

            if (product is not null)
            {
                _cache.Set(key, product, TimeSpan.FromMinutes(5));
            }

            return product;
        }
        finally
        {
            _semaphore.Release();
        }
    }
}
```

进入锁之后再次检查缓存（double-check），因为等待锁的请求醒来时第一个请求可能已经填充了缓存。

### 缓存雪崩

大量 Key 使用了相同的过期时间，在同一个时刻集中过期，瞬间所有请求涌向数据库。

解决方式是给过期时间加上随机抖动，让 Key 的过期时间分散开：

```csharp
public static class CacheExpirationHelper
{
    private static readonly Random _random = new();

    public static TimeSpan WithJitter(TimeSpan baseExpiration, int maxJitterSeconds = 30)
    {
        int jitter = _random.Next(0, maxJitterSeconds);
        return baseExpiration.Add(TimeSpan.FromSeconds(jitter));
    }
}
```

使用：

```csharp
await _cache.SetAsync(key, product, CacheExpirationHelper.WithJitter(TimeSpan.FromMinutes(5)), cancellationToken);
```

假设 1000 个 Key 的基础过期时间都是 5 分钟，加上 0~30 秒的随机抖动后，过期时间分布在 5:00~5:30 之间，避免同时失效。

## 使用建议

- 优先缓存读多写少的数据。
- 明确缓存失效策略。
- 不要缓存强一致性要求很高的数据。
- 缓存中不要存敏感明文。
- 分布式缓存要考虑序列化版本兼容。

## 总结

`IMemoryCache` 适合单机本地缓存，`IDistributedCache` 适合多实例共享缓存，Redis 是最常见实现。缓存的核心不是 API，而是 Key、过期、失效和一致性策略。

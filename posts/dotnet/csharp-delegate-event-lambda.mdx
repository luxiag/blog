委托、事件和 Lambda 是 C# 语言里非常核心的一组能力。LINQ、ASP.NET Core 中间件、事件通知、回调函数、依赖注入扩展方法，背后都能看到它们的影子。

理解这组概念的关键不是死记语法，而是建立一个心智模型：**方法也可以像变量一样被传递**。

## 从方法作为参数开始

假设有一个订单处理流程，不同场景下处理完成后的通知方式不同。

```csharp
using System;

public class Program
{
    public static void Main()
    {
        ProcessOrder(SendEmail);
        ProcessOrder(SendSms);
    }

    static void ProcessOrder(Action notify)
    {
        Console.WriteLine("订单处理完成");
        notify();
    }

    static void SendEmail()
    {
        Console.WriteLine("发送邮件通知");
    }

    static void SendSms()
    {
        Console.WriteLine("发送短信通知");
    }
}
```

这里的 `Action` 就是一种内置委托类型。`ProcessOrder` 不关心具体通知逻辑，只要求调用方传入一个没有参数、没有返回值的方法。

## delegate 是什么

委托是一种类型，它描述了“可以引用什么样的方法”。方法签名匹配，就可以赋值给这个委托。

```csharp
using System;

public delegate decimal DiscountRule(decimal amount);

public class Program
{
    public static void Main()
    {
        DiscountRule rule = TenPercentOff;
        decimal finalAmount = ApplyDiscount(200m, rule);

        Console.WriteLine($"最终金额：{finalAmount}");
    }

    static decimal ApplyDiscount(decimal amount, DiscountRule rule)
    {
        return rule(amount);
    }

    static decimal TenPercentOff(decimal amount)
    {
        return amount * 0.9m;
    }
}
```

`DiscountRule` 要求接收一个 `decimal`，返回一个 `decimal`。只要方法签名一致，就可以赋值。

## Action 与 Func

实际开发中很少手写 `delegate`，因为 .NET 已经提供了常用泛型委托。

`Action` 表示没有返回值的方法。

```csharp
Action<string> log = message => Console.WriteLine($"日志：{message}");
log("订单创建成功");
```

`Func` 表示有返回值的方法，最后一个泛型参数是返回值类型。

```csharp
Func<decimal, decimal> discount = amount => amount * 0.8m;
decimal result = discount(100m);

Console.WriteLine(result);
```

完整示例：

```csharp
using System;

public class Program
{
    public static void Main()
    {
        Action<string> logger = message => Console.WriteLine($"[LOG] {message}");
        Func<decimal, decimal> discount = amount => amount >= 100 ? amount - 20 : amount;

        decimal price = 120m;
        decimal finalPrice = discount(price);

        logger($"原价：{price}，优惠后：{finalPrice}");
    }
}
```

## Lambda 表达式

Lambda 表达式是创建委托实例的简洁写法。

```csharp
Func<int, int> square = x => x * x;
Console.WriteLine(square(5));
```

如果逻辑超过一行，可以使用语句体 Lambda。

```csharp
Func<int, string> describe = score =>
{
    if (score >= 60)
    {
        return "及格";
    }

    return "不及格";
};
```

Lambda 最常见的场景是 LINQ。

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public class Program
{
    public static void Main()
    {
        var products = new List<Product>
        {
            new("键盘", 199),
            new("显示器", 1299),
            new("鼠标", 99)
        };

        var expensiveProducts = products
            .Where(product => product.Price >= 200)
            .Select(product => product.Name)
            .ToList();

        Console.WriteLine(string.Join(", ", expensiveProducts));
    }
}

public record Product(string Name, decimal Price);
```

## 闭包

Lambda 可以访问外部变量，这叫闭包。

```csharp
using System;

public class Program
{
    public static void Main()
    {
        decimal threshold = 100m;

        Func<decimal, bool> isExpensive = price => price >= threshold;

        Console.WriteLine(isExpensive(120m));

        threshold = 200m;
        Console.WriteLine(isExpensive(120m));
    }
}
```

注意，闭包捕获的是变量本身，不是当时的值。因此外部变量变化后，Lambda 内部看到的值也会变化。

### 循环中的闭包陷阱

闭包最常见的坑是在 `for` 循环中捕获循环变量：

```csharp
var actions = new List<Action>();

for (int i = 0; i < 3; i++)
{
    actions.Add(() => Console.WriteLine(i));
}

foreach (Action action in actions)
{
    action();
}
```

你可能期望输出 `0`、`1`、`2`，但实际输出是 `3`、`3`、`3`。因为所有 Lambda 捕获的是同一个变量 `i`，循环结束后 `i` 已经变成 `3`。

解决方法是在循环内部创建一个局部变量副本：

```csharp
for (int i = 0; i < 3; i++)
{
    int copy = i;
    actions.Add(() => Console.WriteLine(copy));
}
```

C# 5 以后 `foreach` 循环变量已经是每次迭代独立的，不会出现这个问题。但 `for` 循环中仍然需要手动创建副本。

### 闭包延长变量生命周期

闭包会让局部变量在方法返回后仍然存活，因为委托持有对变量的引用：

```csharp
Func<int> CreateCounter()
{
    int count = 0;
    return () => ++count;
}

var counter = CreateCounter();

Console.WriteLine(counter()); // 1
Console.WriteLine(counter()); // 2
```

`count` 本来是 `CreateCounter` 的局部变量，但因为 Lambda 捕获了它，方法返回后它仍然存在。这在大多数场景下没问题，但如果捕获了大对象，可能导致内存无法及时回收。

## 多播委托

委托可以组合，调用时按顺序执行。

```csharp
using System;

public class Program
{
    public static void Main()
    {
        Action handlers = SendEmail;
        handlers += SendSms;
        handlers += WriteLog;

        handlers();
    }

    static void SendEmail() => Console.WriteLine("发送邮件");
    static void SendSms() => Console.WriteLine("发送短信");
    static void WriteLog() => Console.WriteLine("写入日志");
}
```

如果多播委托有返回值，最终只能拿到最后一个方法的返回值。因此多播委托更适合 `void` 场景。

### 多播委托的异常处理

多播委托中某个处理器抛异常时，后续处理器不会执行：

```csharp
Action handlers = () => Console.WriteLine("第一步");
handlers += () => throw new InvalidOperationException("第二步失败");
handlers += () => Console.WriteLine("第三步");

try
{
    handlers();
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"捕获异常：{ex.Message}");
}
// 输出：第一步 → 捕获异常：第二步失败
// "第三步"不会执行
```

如果需要每个处理器都执行并分别处理异常，可以用 `GetInvocationList` 逐个调用：

```csharp
foreach (Delegate handler in handlers.GetInvocationList())
{
    try
    {
        handler.DynamicInvoke();
    }
    catch (Exception ex)
    {
        Console.WriteLine($"处理器异常：{ex.InnerException?.Message}");
    }
}
```

## event 是什么

多播委托虽然可以组合多个处理器，但它有两个安全问题：外部可以用 `=` 覆盖所有处理器，也可以直接调用委托。`event` 就是对委托的一层限制，解决这两个问题。它允许外部订阅和取消订阅，但不允许外部直接触发事件或覆盖。

```csharp
using System;

public class Program
{
    public static void Main()
    {
        var orderService = new OrderService();

        orderService.OrderCreated += (_, orderNo) =>
        {
            Console.WriteLine($"收到订单创建事件：{orderNo}");
        };

        orderService.Create("NO-001");
    }
}

public class OrderService
{
    public event EventHandler<string>? OrderCreated;

    public void Create(string orderNo)
    {
        Console.WriteLine($"创建订单：{orderNo}");

        // 只有类内部可以触发事件
        OrderCreated?.Invoke(this, orderNo);
    }
}
```

`event` 的价值在于封装。外部代码只能 `+=` 或 `-=`，不能把事件清空，也不能直接调用事件。

## 自定义事件参数

复杂场景建议定义自己的 `EventArgs`。

```csharp
using System;

public class Program
{
    public static void Main()
    {
        var publisher = new OrderPublisher();
        publisher.OrderPaid += OnOrderPaid;

        publisher.Pay("NO-1001", 299m);
    }

    static void OnOrderPaid(object? sender, OrderPaidEventArgs e)
    {
        Console.WriteLine($"订单 {e.OrderNo} 已支付，金额 {e.Amount}");
    }
}

public class OrderPublisher
{
    public event EventHandler<OrderPaidEventArgs>? OrderPaid;

    public void Pay(string orderNo, decimal amount)
    {
        OrderPaid?.Invoke(this, new OrderPaidEventArgs(orderNo, amount));
    }
}

public class OrderPaidEventArgs : EventArgs
{
    public OrderPaidEventArgs(string orderNo, decimal amount)
    {
        OrderNo = orderNo;
        Amount = amount;
    }

    public string OrderNo { get; }
    public decimal Amount { get; }
}
```

## 事件访问器

默认情况下，编译器自动生成事件的 `add` 和 `remove` 访问器。如果需要自定义订阅逻辑（如线程安全、日志记录），可以显式实现：

```csharp
public class OrderService
{
    private EventHandler<string>? _orderCreated;

    public event EventHandler<string>? OrderCreated
    {
        add
        {
            Console.WriteLine("新订阅者注册");
            _orderCreated += value;
        }
        remove
        {
            _orderCreated -= value;
        }
    }

    public void Create(string orderNo)
    {
        _orderCreated?.Invoke(this, orderNo);
    }
}
```

日常开发中很少需要自定义事件访问器，编译器默认生成的版本已经够用。了解这个机制主要是为了理解 `event` 底层是如何工作的。

## 委托、事件和接口怎么选

| 场景 | 推荐方式 | 原因 |
|---|---|---|
| 传入一小段行为（筛选、转换、比较） | `Func` / `Action` | 轻量、内联 |
| 多个订阅者响应状态变化 | `event` | 安全的发布订阅 |
| 复杂行为、多个方法、需要清晰建模 | 接口 | 结构化、可测试 |

```csharp
// 传入行为：用 Func
var expensive = products.Where(p => p.Price >= 100m);

// 多订阅者：用 event
orderService.OrderCreated += OnOrderCreated;
orderService.OrderCreated += SendNotification;

// 复杂建模：用接口
public interface IPaymentGateway
{
    Task<PaymentResult> PayAsync(PaymentRequest request, CancellationToken cancellationToken);
    Task RefundAsync(string paymentId, CancellationToken cancellationToken);
}
```

不要为了少写一个接口，把复杂业务都塞进委托里。委托适合表达单个动作，接口适合表达一组能力。

## 总结

委托让方法可以被传递，Lambda 让委托写法更简洁，事件让发布订阅关系更安全。理解这三者后，再看 LINQ、中间件、回调、领域事件等 .NET 代码，会清晰很多。

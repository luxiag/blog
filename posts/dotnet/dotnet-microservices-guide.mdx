# .NET 微服务实战：从单体到分布式的完整落地指南

微服务在 .NET 生态中不是新概念了，但真正能把它落地到生产环境的团队并不多。

原因很简单：微服务不是一个技术选型问题，而是一系列工程决策的组合。你需要同时回答这些问题：

- 服务之间怎么通信？HTTP 还是 gRPC？
- 网关用什么？怎么做路由和限流？
- 某个下游服务挂了，上游怎么办？
- 分布式事务怎么处理？
- 日志、链路追踪、指标怎么统一收集？
- 怎么容器化部署？怎么编排？

这篇文章就是用 .NET 8 + ASP.NET Core 把上面每个问题逐一回答，给出可运行的代码和可复用的方案。

## 一、解决方案结构设计

微服务的代码组织是第一个要解决的问题。在 .NET 中，我们通常用一个 Solution 管理多个 Service 项目。

### 1.1 推荐的目录结构

### 1.2 关键设计原则

**每个服务独立数据库**：Ordering 用 PostgreSQL，Catalog 用 MongoDB，Identity 用 SQL Server——根据场景选最合适的。

**BuildingBlocks 是共享库，不是共享服务**：它以 NuGet 包的形式被各服务引用，不是一个独立运行的进程。

**测试和部署配置放在仓库根目录**：不要散落到各个服务内部。

## 二、服务通信：HTTP vs gRPC

微服务之间的通信方式选择直接决定了系统的性能和复杂度。

### 2.1 什么时候用 HTTP，什么时候用 gRPC

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 对外暴露 API（给前端调用） | HTTP/REST | 浏览器原生支持，工具链成熟 |
| 服务间同步调用 | gRPC | 高性能、强类型、代码生成 |
| 需要流式传输 | gRPC | 原生支持双向流 |
| 需要跨语言但团队不熟 protobuf | HTTP + OpenAPI | 降低团队学习成本 |

### 2.2 gRPC 服务实现

先定义 proto 文件：

```protobuf
// Protos/catalog.proto
syntax = "proto3";

option csharp_namespace = "EShop.Catalog.Grpc";

package catalog;

service CatalogService {
  rpc GetItemById (GetItemRequest) returns (CatalogItem);
  rpc GetItemsByIds (GetItemsRequest) returns (CatalogItemsResponse);
  rpc UpdateStock (UpdateStockRequest) returns (UpdateStockResponse);
}

message GetItemRequest {
  int32 id = 1;
}

message GetItemsRequest {
  repeated int32 ids = 1;
}

message CatalogItem {
  int32 id = 1;
  string name = 2;
  string description = 3;
  double price = 4;
  int32 available_stock = 5;
  string picture_uri = 6;
}

message CatalogItemsResponse {
  repeated CatalogItem items = 1;
}

message UpdateStockRequest {
  int32 item_id = 1;
  int32 quantity = 2;
}

message UpdateStockResponse {
  bool success = 1;
  int32 new_stock = 2;
}
```

服务端实现：

```csharp
// Catalog.API/Services/CatalogGrpcService.cs
using Grpc.Core;
using EShop.Catalog.Grpc;
using Microsoft.EntityFrameworkCore;

namespace Catalog.API.Services;

public class CatalogGrpcService : CatalogService.CatalogServiceBase
{
    private readonly CatalogDbContext _db;
    private readonly ILogger<CatalogGrpcService> _logger;

    public CatalogGrpcService(CatalogDbContext db, ILogger<CatalogGrpcService> logger)
    {
        _db = db;
        _logger = logger;
    }

    public override async Task<CatalogItem> GetItemById(
        GetItemRequest request, ServerCallContext context)
    {
        var item = await _db.CatalogItems.FindAsync(request.Id);

        if (item is null)
        {
            throw new RpcException(new Status(
                StatusCode.NotFound, $"商品 {request.Id} 不存在"));
        }

        return MapToGrpcModel(item);
    }

    public override async Task<UpdateStockResponse> UpdateStock(
        UpdateStockRequest request, ServerCallContext context)
    {
        var item = await _db.CatalogItems.FindAsync(request.ItemId);

        if (item is null)
        {
            throw new RpcException(new Status(
                StatusCode.NotFound, $"商品 {request.ItemId} 不存在"));
        }

        // 乐观并发控制
        item.AvailableStock -= request.Quantity;

        if (item.AvailableStock < 0)
        {
            throw new RpcException(new Status(
                StatusCode.FailedPrecondition, "库存不足"));
        }

        await _db.SaveChangesAsync();

        return new UpdateStockResponse
        {
            Success = true,
            NewStock = item.AvailableStock
        };
    }

    private static CatalogItem MapToGrpcModel(Domain.CatalogItem item) => new()
    {
        Id = item.Id,
        Name = item.Name,
        Description = item.Description ?? string.Empty,
        Price = (double)item.Price,
        AvailableStock = item.AvailableStock,
        PictureUri = item.PictureUri ?? string.Empty
    };
}
```

注册 gRPC 服务：

```csharp
// Catalog.API/Program.cs

builder.Services.AddDbContext<CatalogDbContext>(options =>
    options.UseNpgsql(builder.Configuration.GetConnectionString("CatalogDb")));

```

### 2.3 gRPC 客户端调用

在 Ordering 服务中调用 Catalog 服务：

```csharp
// Ordering.Infrastructure/Services/CatalogService.cs
using EShop.Catalog.Grpc;

namespace Ordering.Infrastructure.Services;

public class CatalogService : ICatalogService
{
    private readonly CatalogGrpc.CatalogServiceClient _client;
    private readonly ILogger<CatalogService> _logger;

    public CatalogService(
        CatalogGrpc.CatalogServiceClient client,
        ILogger<CatalogService> logger)
    {
        _client = client;
        _logger = logger;
    }

    public async Task<CatalogItemDto?> GetItemAsync(int itemId)
    {
        try
        {
            var response = await _client.GetItemByIdAsync(
                new GetItemRequest { Id = itemId });

            return new CatalogItemDto(
                response.Id, response.Name,
                (decimal)response.Price, response.AvailableStock);
        }
        catch (RpcException ex) when (ex.StatusCode == StatusCode.NotFound)
        {
            _logger.LogWarning("商品 {ItemId} 不存在", itemId);
            return null;
        }
    }

    public async Task<bool> DeductStockAsync(int itemId, int quantity)
    {
        var response = await _client.UpdateStockAsync(
            new UpdateStockRequest { ItemId = itemId, Quantity = quantity });

        return response.Success;
    }
}
```

## 三、API 网关：YARP 反向代理

API 网关是微服务对外的统一入口。.NET 生态中，**YARP (Yet Another Reverse Proxy)** 是微软官方维护的高性能反向代理库，比 Ocelot 更活跃、性能更好。

### 3.1 为什么选 YARP 而不是 Ocelot

| 对比项 | YARP | Ocelot |
|--------|------|--------|
| 维护者 | 微软官方 | 社区 |
| 性能 | 接近原生 Kestrel | 中等 |
| 配置方式 | JSON / 代码 / 动态提供者 | JSON |
| 可扩展性 | 管道中间件模型 | 有限 |
| 活跃度 | 活跃开发中 | 维护模式 |

### 3.2 基础配置

```csharp
// ApiGateways/WebGateway/Program.cs
var builder = WebApplication.CreateBuilder(args);

// 从配置文件加载 YARP 路由规则
builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));

// 添加限流
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("default", opt =>
    {
        opt.PermitLimit = 100;
        opt.Window = TimeSpan.FromMinutes(1);
    });
});

var app = builder.Build();

app.UseRateLimiter();
app.MapReverseProxy();

app.Run();
```

### 3.3 动态路由配置（从数据库/Consul 加载）

生产环境通常不会把路由写死在 JSON 里，而是从服务注册中心动态获取：

```csharp
// 自定义配置提供者
public class ConsulProxyConfigProvider : IProxyConfigProvider
{
    private readonly IConsulClient _consul;
    private readonly ILogger<ConsulProxyConfigProvider> _logger;
    private volatile ConsulProxyConfig _config;

    public ConsulProxyConfigProvider(
        IConsulClient consul,
        ILogger<ConsulProxyConfigProvider> logger)
    {
        _consul = consul;
        _logger = logger;
        _config = new ConsulProxyConfig([], []);

        // 启动后台刷新任务
        _ = RefreshConfigLoop();
    }

    public IProxyConfig GetConfig() => _config;

    private async Task RefreshConfigLoop()
    {
        while (true)
        {
            try
            {
                var services = await _consul.Agent.Services();
                var (routes, clusters) = BuildConfig(services.Response);
                var newConfig = new ConsulProxyConfig(routes, clusters);

                // 原子替换配置
                var oldConfig = _config;
                _config = newConfig;
                oldConfig.SignalChange(); // 通知 YARP 重新加载

                _logger.LogDebug("YARP 配置已刷新，发现 {Count} 个服务",
                    clusters.Count);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "刷新 YARP 配置失败");
            }

            await Task.Delay(TimeSpan.FromSeconds(30));
        }
    }

    private (List<RouteConfig>, List<ClusterConfig>) BuildConfig(
        Dictionary<string, AgentService> services)
    {
        var routes = new List<RouteConfig>();
        var clusters = new List<ClusterConfig>();

        // 按服务名分组
        var grouped = services.Values.GroupBy(s => s.Service);

        foreach (var group in grouped)
        {
            var serviceName = group.Key;
            var destinations = group.ToDictionary(
                s => s.ID,
                s => new DestinationConfig
                {
                    Address = $"http://{s.Address}:{s.Port}"
                });

            clusters.Add(new ClusterConfig
            {
                ClusterId = $"{serviceName}-cluster",
                Destinations = destinations,
                LoadBalancingPolicy = "RoundRobin"
            });

            routes.Add(new RouteConfig
            {
                RouteId = $"{serviceName}-route",
                ClusterId = $"{serviceName}-cluster",
                Match = new RouteMatch
                {
                    Path = $"/api/{serviceName}/{{**catch-all}}"
                }
            });
        }

        return (routes, clusters);
    }
}
```

## 四、弹性策略：Polly 与 Microsoft.Extensions.Http.Resilience

服务间调用不可避免地会遇到网络抖动、超时、下游宕机等问题。弹性策略让你的系统在这些情况下依然可用。

### 4.1 .NET 8 推荐方式：Microsoft.Extensions.Resilience

.NET 8 引入了 `Microsoft.Extensions.Http.Resilience`，它基于 Polly v8 构建，提供了更简洁的配置方式：

```bash
dotnet add package Microsoft.Extensions.Http.Resilience
```

```csharp
// 标准弹性管道：重试 + 断路器 + 超时
builder.Services.AddHttpClient<CatalogHttpClient>(client =>
{
    client.BaseAddress = new Uri("http://catalog-api:8080");
})
.AddStandardResilienceHandler(options =>
{
    // 重试策略：指数退避，最多重试 3 次
    options.Retry.MaxRetryAttempts = 3;
    options.Retry.Delay = TimeSpan.FromMilliseconds(500);
    options.Retry.BackoffType = DelayBackoffType.Exponential;

    // 断路器：连续 10 次失败中有 50% 以上失败则打开
    options.CircuitBreaker.SamplingDuration = TimeSpan.FromSeconds(30);
    options.CircuitBreaker.FailureRatio = 0.5;
    options.CircuitBreaker.MinimumThroughput = 10;
    options.CircuitBreaker.BreakDuration = TimeSpan.FromSeconds(30);

    // 总超时
    options.TotalRequestTimeout.Timeout = TimeSpan.FromSeconds(30);

    // 单次尝试超时
    options.AttemptTimeout.Timeout = TimeSpan.FromSeconds(5);
});
```

### 4.2 自定义弹性策略

当标准管道不够用时，自己组合策略：

```csharp
using Polly;
using Polly.CircuitBreaker;
using Polly.Retry;
using Polly.Timeout;

// 为 gRPC 客户端配置弹性策略
builder.Services.AddGrpcClient<CatalogGrpc.CatalogServiceClient>(options =>
{
    options.Address = new Uri("http://catalog-api:8081");
})
.AddResilienceHandler("catalog-grpc", pipeline =>
{
    // 1. 超时：单次调用最多等 3 秒
    pipeline.AddTimeout(new TimeoutStrategyOptions
    {
        Timeout = TimeSpan.FromSeconds(3),
        OnTimeout = args =>
        {
            Console.WriteLine($"gRPC 调用超时: {args.Context.OperationKey}");
            return default;
        }
    });

    // 2. 重试：遇到暂时性错误重试
    pipeline.AddRetry(new RetryStrategyOptions<HttpResponseMessage>
    {
        MaxRetryAttempts = 2,
        Delay = TimeSpan.FromMilliseconds(200),
        BackoffType = DelayBackoffType.Exponential,
        ShouldHandle = new PredicateBuilder<HttpResponseMessage>()
            .Handle<TimeoutRejectedException>()
            .Handle<HttpRequestException>()
    });

    // 3. 断路器：下游持续不可用时快速失败
    pipeline.AddCircuitBreaker(new CircuitBreakerStrategyOptions<HttpResponseMessage>
    {
        FailureRatio = 0.5,
        SamplingDuration = TimeSpan.FromSeconds(10),
        MinimumThroughput = 5,
        BreakDuration = TimeSpan.FromSeconds(15),
        OnOpened = args =>
        {
            Console.WriteLine("断路器已打开，后续请求将快速失败");
            return default;
        },
        OnClosed = args =>
        {
            Console.WriteLine("断路器已关闭，恢复正常请求");
            return default;
        }
    });
});
```

### 4.3 降级策略

当断路器打开或重试耗尽时，返回降级响应而非直接报错：

```csharp
public class ResilientCatalogService : ICatalogService
{
    private readonly CatalogGrpc.CatalogServiceClient _client;
    private readonly IDistributedCache _cache;
    private readonly ILogger<ResilientCatalogService> _logger;

    public ResilientCatalogService(
        CatalogGrpc.CatalogServiceClient client,
        IDistributedCache cache,
        ILogger<ResilientCatalogService> logger)
    {
        _client = client;
        _cache = cache;
        _logger = logger;
    }

    public async Task<CatalogItemDto?> GetItemAsync(int itemId)
    {
        try
        {
            // 正常路径：调用 gRPC
            var response = await _client.GetItemByIdAsync(
                new GetItemRequest { Id = itemId });

            var dto = MapToDto(response);

            // 写入缓存作为降级数据源
            await _cache.SetStringAsync(
                $"catalog:item:{itemId}",
                JsonSerializer.Serialize(dto),
                new DistributedCacheEntryOptions
                {
                    AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
                });

            return dto;
        }
        catch (RpcException ex) when (
            ex.StatusCode == StatusCode.Unavailable ||
            ex.StatusCode == StatusCode.DeadlineExceeded)
        {
            // 降级路径：从缓存读取
            _logger.LogWarning("Catalog 服务不可用，使用缓存数据。异常: {Status}",
                ex.StatusCode);

            var cached = await _cache.GetStringAsync($"catalog:item:{itemId}");
            if (cached is not null)
            {
                return JsonSerializer.Deserialize<CatalogItemDto>(cached);
            }

            _logger.LogError("缓存中也没有商品 {ItemId} 的数据", itemId);
            return null;
        }
    }
}
```

### 5.2 基于 RabbitMQ 的事件总线

```csharp
// BuildingBlocks/EventBus.RabbitMQ/RabbitMQEventBus.cs
using System.Text;
using System.Text.Json;
using RabbitMQ.Client;
using RabbitMQ.Client.Events;

namespace EShop.BuildingBlocks.EventBus.RabbitMQ;

public class RabbitMQEventBus : IEventBus, IDisposable
{
    private readonly IConnection _connection;
    private readonly IModel _channel;
    private readonly string _exchangeName = "eshop_event_bus";
    private readonly string _queueName;
    private readonly IServiceProvider _serviceProvider;
    private readonly ILogger<RabbitMQEventBus> _logger;
    private readonly Dictionary<string, List<Type>> _handlers = new();

    public RabbitMQEventBus(
        IConnection connection,
        IServiceProvider serviceProvider,
        ILogger<RabbitMQEventBus> logger,
        string queueName)
    {
        _connection = connection;
        _channel = connection.CreateModel();
        _serviceProvider = serviceProvider;
        _logger = logger;
        _queueName = queueName;

        // 声明 Exchange
        _channel.ExchangeDeclare(_exchangeName, ExchangeType.Direct, durable: true);

        // 声明当前服务的队列
        _channel.QueueDeclare(_queueName, durable: true,
            exclusive: false, autoDelete: false);
    }

    public void Publish(IntegrationEvent @event)
    {
        var eventName = @event.GetType().Name;
        var body = Encoding.UTF8.GetBytes(JsonSerializer.Serialize(
            @event, @event.GetType()));

        var properties = _channel.CreateBasicProperties();
        properties.DeliveryMode = 2; // 持久化
        properties.MessageId = @event.Id.ToString();
        properties.Timestamp = new AmqpTimestamp(
            DateTimeOffset.UtcNow.ToUnixTimeSeconds());

        _channel.BasicPublish(
            exchange: _exchangeName,
            routingKey: eventName,
            basicProperties: properties,
            body: body);

        _logger.LogInformation("已发布事件 {EventName}，ID: {EventId}",
            eventName, @event.Id);
    }

    public void Subscribe<TEvent, THandler>()
        where TEvent : IntegrationEvent
        where THandler : IIntegrationEventHandler<TEvent>
    {
        var eventName = typeof(TEvent).Name;

        // 绑定队列到 Exchange
        _channel.QueueBind(_queueName, _exchangeName, eventName);

        if (!_handlers.ContainsKey(eventName))
        {
            _handlers[eventName] = new List<Type>();
            StartConsume(eventName);
        }

        _handlers[eventName].Add(typeof(THandler));
    }

    private void StartConsume(string eventName)
    {
        var consumer = new AsyncEventingBasicConsumer(_channel);

        consumer.Received += async (_, ea) =>
        {
            var body = Encoding.UTF8.GetString(ea.Body.Span);

            try
            {
                await ProcessEvent(eventName, body);
                _channel.BasicAck(ea.DeliveryTag, multiple: false);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "处理事件 {EventName} 失败", eventName);
                // 重新入队，等待重试
                _channel.BasicNack(ea.DeliveryTag, multiple: false, requeue: true);
            }
        };

        _channel.BasicConsume(_queueName, autoAck: false, consumer: consumer);
    }

    private async Task ProcessEvent(string eventName, string message)
    {
        if (!_handlers.TryGetValue(eventName, out var handlerTypes))
            return;

        using var scope = _serviceProvider.CreateScope();

        foreach (var handlerType in handlerTypes)
        {
            var handler = scope.ServiceProvider.GetRequiredService(handlerType);
            var eventType = handler.GetType().GetInterfaces()
                .First(i => i.IsGenericType &&
                    i.GetGenericTypeDefinition() == typeof(IIntegrationEventHandler<>))
                .GetGenericArguments()[0];

            var @event = JsonSerializer.Deserialize(message, eventType)
                as IntegrationEvent;

            var method = handlerType.GetMethod("HandleAsync");
            await (Task)method!.Invoke(handler, [@event])!;
        }
    }

    public void Dispose()
    {
        _channel?.Dispose();
        _connection?.Dispose();
    }
}
```

```csharp
// Catalog.API/EventHandlers/OrderCreatedEventHandler.cs
public class OrderCreatedEventHandler : IIntegrationEventHandler<OrderCreatedIntegrationEvent>
{
    private readonly CatalogDbContext _db;
    private readonly IEventBus _eventBus;
    private readonly ILogger<OrderCreatedEventHandler> _logger;

    public OrderCreatedEventHandler(
        CatalogDbContext db,
        IEventBus eventBus,
        ILogger<OrderCreatedEventHandler> logger)
    {
        _db = db;
        _eventBus = eventBus;
        _logger = logger;
    }

    public async Task HandleAsync(OrderCreatedIntegrationEvent @event)
    {
        _logger.LogInformation("收到订单创建事件，订单ID: {OrderId}，开始扣减库存",
            @event.OrderId);

        using var transaction = await _db.Database.BeginTransactionAsync();

        try
        {
            foreach (var item in @event.Items)
            {
                var catalogItem = await _db.CatalogItems.FindAsync(item.ProductId);

                if (catalogItem is null || catalogItem.AvailableStock < item.Quantity)
                {
                    // 库存不足，发布失败事件
                    _eventBus.Publish(new StockDeductedIntegrationEvent(
                        @event.OrderId, false,
                        $"商品 {item.ProductId} 库存不足"));

                    await transaction.RollbackAsync();
                    return;
                }

                catalogItem.AvailableStock -= item.Quantity;
            }

            await _db.SaveChangesAsync();
            await transaction.CommitAsync();

            // 库存扣减成功
            _eventBus.Publish(new StockDeductedIntegrationEvent(
                @event.OrderId, true));
        }
        catch (Exception ex)
        {
            await transaction.RollbackAsync();
            _logger.LogError(ex, "扣减库存异常，订单ID: {OrderId}", @event.OrderId);
            throw; // 重新抛出，触发消息重试
        }
    }
}
```

### 5.4 Outbox 模式：保证事件可靠发布

直接在业务操作后发事件，存在数据库写成功但事件发布失败的风险。Outbox 模式解决这个问题：

```csharp
// 1. Outbox 表实体
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string EventType { get; set; } = default!;
    public string Payload { get; set; } = default!;
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
    public int RetryCount { get; set; }
}

// 2. 在同一个事务中写业务数据 + Outbox 记录
public class OrderService
{
    private readonly OrderDbContext _db;

    public async Task CreateOrderAsync(CreateOrderCommand command)
    {
        using var transaction = await _db.Database.BeginTransactionAsync();

        // 写业务数据
        var order = new Order(command.BuyerId, command.Items);
        _db.Orders.Add(order);

        // 写 Outbox（同一个事务！）
        var @event = new OrderCreatedIntegrationEvent(
            order.Id, order.BuyerId, order.Items.Select(MapToDto).ToList());

        _db.OutboxMessages.Add(new OutboxMessage
        {
            Id = @event.Id,
            EventType = nameof(OrderCreatedIntegrationEvent),
            Payload = JsonSerializer.Serialize(@event),
            CreatedAt = DateTime.UtcNow
        });

        await _db.SaveChangesAsync();
        await transaction.CommitAsync();
    }
}

// 3. 后台任务轮询 Outbox 并发布事件
public class OutboxProcessor : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly IEventBus _eventBus;
    private readonly ILogger<OutboxProcessor> _logger;

    public OutboxProcessor(
        IServiceScopeFactory scopeFactory,
        IEventBus eventBus,
        ILogger<OutboxProcessor> logger)
    {
        _scopeFactory = scopeFactory;
        _eventBus = eventBus;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopeFactory.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<OrderDbContext>();

            var messages = await db.OutboxMessages
                .Where(m => m.ProcessedAt == null && m.RetryCount < 5)
                .OrderBy(m => m.CreatedAt)
                .Take(20)
                .ToListAsync(stoppingToken);

            foreach (var message in messages)
            {
                try
                {
                    var eventType = Type.GetType(message.EventType)
                        ?? throw new InvalidOperationException(
                            $"未知事件类型: {message.EventType}");

                    var @event = (IntegrationEvent)JsonSerializer.Deserialize(
                        message.Payload, eventType)!;

                    _eventBus.Publish(@event);

                    message.ProcessedAt = DateTime.UtcNow;
                }
                catch (Exception ex)
                {
                    message.RetryCount++;
                    _logger.LogError(ex,
                        "Outbox 消息 {MessageId} 发布失败，重试次数: {Retry}",
                        message.Id, message.RetryCount);
                }
            }

            await db.SaveChangesAsync(stoppingToken);
            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }
}
```

```csharp
        var serviceHost = _config["Service:Host"]!;
```

```csharp
namespace EShop.BuildingBlocks.Common;

public static class OpenTelemetryExtensions
{
    public static IHostApplicationBuilder AddServiceObservability(
        this IHostApplicationBuilder builder)
    {
        var serviceName = builder.Configuration["Service:Name"] ?? "unknown";
        var otlpEndpoint = builder.Configuration["Otlp:Endpoint"]
            ?? "http://otel-collector:4317";

            .WithTracing(tracing => tracing
                .SetResourceBuilder(resourceBuilder)
                .AddAspNetCoreInstrumentation(options =>
                {
                    // 过滤健康检查等噪音请求
                    options.Filter = ctx =>
                        !ctx.Request.Path.StartsWithSegments("/health") &&
                        !ctx.Request.Path.StartsWithSegments("/metrics");
                })
                .AddHttpClientInstrumentation()
                .AddGrpcClientInstrumentation()
                .AddEntityFrameworkCoreInstrumentation(options =>
                {
                    options.SetDbStatementForText = true;
                })
                .AddSource(serviceName) // 自定义 ActivitySource
                .AddOtlpExporter(options =>
                {
                    options.Endpoint = new Uri(otlpEndpoint);
                }))
            .WithMetrics(metrics => metrics
                .SetResourceBuilder(resourceBuilder)
                .AddAspNetCoreInstrumentation()
                .AddHttpClientInstrumentation()
                .AddRuntimeInstrumentation()
                .AddProcessInstrumentation()
                .AddMeter(serviceName) // 自定义 Meter
                .AddOtlpExporter(options =>
                {
                    options.Endpoint = new Uri(otlpEndpoint);
                }));

        // 结构化日志
        builder.Logging.AddOpenTelemetry(logging =>
        {
            logging.SetResourceBuilder(resourceBuilder);
            logging.IncludeFormattedMessage = true;
            logging.IncludeScopes = true;
            logging.AddOtlpExporter(options =>
            {
                options.Endpoint = new Uri(otlpEndpoint);
            });
        });

        return builder;
    }
```

### 9.2 服务间身份传播

网关验证 Token 后，将用户信息通过 HTTP Header 传递给下游：

```csharp
// YARP 配置中的 Transform
{
  "Routes": {
    "ordering-route": {
      "Transforms": [
        { "RequestHeader": "X-User-Id", "Set": "{ClaimValue:sub}" },
        { "RequestHeader": "X-User-Role", "Set": "{ClaimValue:role}" },
        { "RequestHeader": "X-Request-Id", "Set": "{Header:X-Request-Id}" }
      ]
    }
  }
}
```

下游服务读取身份信息：

```csharp
// 自定义中间件
public class ServiceAuthMiddleware
{
    private readonly RequestDelegate _next;

    public ServiceAuthMiddleware(RequestDelegate next) => _next = next;

    public async Task InvokeAsync(HttpContext context)
    {
        if (context.Request.Headers.TryGetValue("X-User-Id", out var userId))
        {
            var claims = new List<Claim>
            {
                new(ClaimTypes.NameIdentifier, userId.ToString()!)
            };

            if (context.Request.Headers.TryGetValue("X-User-Role", out var role))
            {
                claims.Add(new Claim(ClaimTypes.Role, role.ToString()!));
            }

            var identity = new ClaimsIdentity(claims, "Gateway");
            context.User = new ClaimsPrincipal(identity);
        }

        await _next(context);
    }
}
```

## 十二、常见问题与最佳实践

### 不要过早拆分

:::warning
如果你的团队少于 5 人，或者业务还在快速变化阶段，**不要上微服务**。先把单体做好，等到单体的某些模块开始成为瓶颈（部署频率不同、扩展需求不同、技术栈需求不同），再拆分。
:::

### 服务粒度怎么把握

一个好的拆分原则是：**一个服务由一个 2-pizza team（5-8人）负责**。太细的服务带来的运维成本远大于它带来的灵活性。

### 数据一致性

:::tip
微服务间不做分布式事务（Saga 除外）。接受最终一致性，用事件驱动 + Outbox + 补偿机制解决。如果两个操作必须强一致，说明它们不应该分成两个服务。
:::

### 版本管理

API 版本通过 URL 前缀管理：

```
/api/v1/orders
/api/v2/orders
```

Proto 文件通过 package 版本管理：

```protobuf
package catalog.v2;
```

### 本地开发

不要求开发者启动所有服务。提供以下方案：

1. **Docker Compose**：一键启动所有基础设施 + 需要联调的服务
2. **Mock 服务**：用 WireMock 或 Mountebank 模拟其他服务
3. **Tye**（已停止维护）/ **Aspire**：微软官方的本地编排工具

```bash
# 只启动基础设施，业务服务本地跑
docker compose up postgresql rabbitmq redis consul -d

# 或者使用 .NET Aspire（推荐）
dotnet run --project src/EShop.AppHost
```

### .NET Aspire：下一代编排方案

:::note
.NET Aspire 是微软 2024 年推出的云原生应用编排框架，它可以替代 Docker Compose 作为本地开发编排工具，并且能生成 Kubernetes 部署清单。如果是新项目，强烈建议使用 Aspire 作为本地开发体验的基础。
:::

```csharp
// EShop.AppHost/Program.cs（.NET Aspire）
var builder = DistributedApplication.CreateBuilder(args);

// 基础设施
var postgres = builder.AddPostgres("postgres");
var orderingDb = postgres.AddDatabase("ordering");
var catalogDb = postgres.AddDatabase("catalog");

var rabbitmq = builder.AddRabbitMQ("rabbitmq");
var redis = builder.AddRedis("redis");

// 业务服务
var catalogApi = builder.AddProject<Projects.Catalog_API>("catalog-api")
    .WithReference(catalogDb)
    .WithReference(rabbitmq);

var orderingApi = builder.AddProject<Projects.Ordering_API>("ordering-api")
    .WithReference(orderingDb)
    .WithReference(rabbitmq)
    .WithReference(redis)
    .WithReference(catalogApi);

// 网关
builder.AddProject<Projects.WebGateway>("web-gateway")
    .WithReference(catalogApi)
    .WithReference(orderingApi);

builder.Build().Run();
```

## 总结

.NET 微服务的技术栈选择：

| 关注点 | 推荐方案 |
|--------|---------|
| 服务间同步通信 | gRPC（内部）、HTTP/REST（对外） |
| 服务间异步通信 | RabbitMQ + Outbox 模式 |
| API 网关 | YARP |
| 弹性策略 | Microsoft.Extensions.Http.Resilience (Polly v8) |
| 服务发现 | Consul / Kubernetes DNS |
| 配置中心 | Consul KV / Kubernetes ConfigMap |
| 可观测性 | OpenTelemetry → Jaeger + Prometheus + Grafana |
| 容器化 | Docker 多阶段构建 |
| 编排 | Kubernetes + HPA |
| 本地开发 | .NET Aspire / Docker Compose |
| 测试 | xUnit + WebApplicationFactory + Pact |

微服务不是银弹。它解决的是组织扩展问题（多团队独立交付），不是技术问题。如果你的痛点是"代码太烂"，微服务只会让它烂得更分散。先把代码写好，再谈架构。

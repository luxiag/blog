# C# 类型系统：值类型、引用类型、enum、struct 与装箱拆箱

C# 是强类型语言。变量、参数、属性、集合元素都必须有明确类型。理解类型系统，才能真正理解为什么 `int`、`string`、`class`、`struct`、`enum`、`List<T>` 的行为不一样。

## 值类型和引用类型

C# 类型大体分为值类型和引用类型。

值类型变量通常直接保存值本身，例如 `int`、`decimal`、`bool`、`DateTime`、`enum`、`struct`。

引用类型变量保存的是对象引用，例如 `class`、`string`、数组、接口、委托。

```csharp
int a = 10;
int b = a;
b = 20;

Console.WriteLine(a); // 10
Console.WriteLine(b); // 20

var p1 = new Person { Name = "Alice" };
var p2 = p1;
p2.Name = "Bob";

Console.WriteLine(p1.Name); // Bob

public class Person
{
    public string Name { get; set; } = string.Empty;
}
```

`int` 赋值会复制值；`Person` 赋值复制的是引用，两个变量指向同一个对象。

## class 与 struct

`class` 是引用类型，`struct` 是值类型。

```csharp
public class UserClass
{
    public string Name { get; set; } = string.Empty;
}

public struct Money
{
    public decimal Amount { get; set; }
    public string Currency { get; set; }
}

var user1 = new UserClass { Name = "Alice" };
var user2 = user1;
user2.Name = "Bob";

var money1 = new Money { Amount = 100m, Currency = "CNY" };
var money2 = money1;
money2.Amount = 200m;

Console.WriteLine(user1.Name);     // Bob
Console.WriteLine(money1.Amount);  // 100
```

一般建议：

- 有身份、生命周期、可变状态的业务对象，用 `class`
- 小型、不可变、表达一个值的对象，可以考虑 `readonly struct` 或 `record struct`
- 不要为了性能随意把业务对象改成 `struct`

### struct 的常见陷阱

struct 是值类型，赋值时会完整复制。这可能在某些场景下造成意外行为：

```csharp
public struct Money
{
    public decimal Amount { get; set; }
    public string Currency { get; set; }
}

var wallet = new List<Money> { new() { Amount = 100m, Currency = "CNY" } };

// 编译错误：无法修改 struct 属性，因为它是值拷贝
// wallet[0].Amount = 200m;

// 必须整体替换
var money = wallet[0];
money.Amount = 200m;
wallet[0] = money;
```

struct 通过方法返回时也是值拷贝，修改返回值不会影响原始数据。这是 struct 最常踩的坑。

struct 的默认值是所有字段为零值，可能导致无效状态：

```csharp
Money defaultMoney = default; // Amount = 0, Currency = null
```

如果不希望出现这种默认状态，用 `class` 或 `record struct` 加构造约束更安全。

### readonly struct

`readonly struct` 保证所有字段不可变，编译器可以据此做优化。

```csharp
public readonly struct Point
{
    public double X { get; }
    public double Y { get; }

    public Point(double x, double y)
    {
        X = x;
        Y = y;
    }

    public double DistanceTo(Point other)
        => Math.Sqrt(Math.Pow(X - other.X, 2) + Math.Pow(Y - other.Y, 2));
}
```

`readonly struct` 的所有成员也必须是 readonly。小型不可变值对象推荐使用 `readonly struct` 或 `readonly record struct`。

### ref struct

`ref struct` 必须只能在栈上分配，不能被装箱、不能作为类字段、不能被 Lambda 捕获。`Span<T>` 就是 `ref struct`。

```csharp
ReadOnlySpan<char> span = "Hello, C#".AsSpan();

Console.WriteLine(span.Length);
```

`ref struct` 是高性能场景避免堆分配的核心工具，日常业务代码很少需要自己定义 `ref struct`。

## enum：表达有限状态

`enum` 适合表达一组有限、固定的状态或选项。

```csharp
public enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Canceled = 3
}

OrderStatus status = OrderStatus.Paid;

string text = status switch
{
    OrderStatus.Pending => "待支付",
    OrderStatus.Paid => "已支付",
    OrderStatus.Shipped => "已发货",
    OrderStatus.Canceled => "已取消",
    _ => "未知状态"
};

Console.WriteLine(text);
```

不要用魔法字符串散落表达状态：

```csharp
// 不推荐
if (status == "paid") { }

// 推荐
if (status == OrderStatus.Paid) { }
```

## Flags 枚举

当多个选项可以组合时，可以使用 `[Flags]`。

```csharp
[Flags]
public enum Permission
{
    None = 0,
    Read = 1,
    Write = 2,
    Delete = 4
}

Permission permission = Permission.Read | Permission.Write;

Console.WriteLine(permission.HasFlag(Permission.Read));
Console.WriteLine(permission.HasFlag(Permission.Delete));
```

标志枚举的值必须使用 2 的幂（1、2、4、8...），因为按位组合依赖二进制位：`Read | Write` 的值是 `3`（二进制 `011`），如果 `Write` 的值是 `3` 而非 `2`，`Read | Write` 就会等于 `5`，组合结果会混乱。

### enum 的底层类型

默认底层类型是 `int`，可以显式指定：

```csharp
public enum OrderStatus : byte
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Canceled = 3
}
```

使用 `byte` 可以节省存储空间，适合值域小的枚举。

### enum 的安全隐患

C# 允许把任意整数强制转换为枚举，不会报错：

```csharp
OrderStatus invalid = (OrderStatus)99;

Console.WriteLine(invalid); // 99
```

可以用 `Enum.IsDefined` 检查值是否合法：

```csharp
OrderStatus status = (OrderStatus)99;

if (!Enum.IsDefined(status))
{
    Console.WriteLine($"非法状态值：{status}");
}
```

在接收外部输入（API 参数、数据库值）转枚举时，务必用 `IsDefined` 校验。

## Nullable`<T>` 与可空值类型

值类型默认不能为 `null`。如果值类型需要表达“没有值”，可以使用 `Nullable<T>`，简写为 `T?`。

```csharp
int? age = null;

if (age.HasValue)
{
    Console.WriteLine(age.Value);
}
else
{
    Console.WriteLine("年龄未知");
}

DateTime? paidAt = null;
Console.WriteLine(paidAt?.ToString("yyyy-MM-dd") ?? "未支付");
```

注意这里的 `int?` 是 `Nullable<int>`，和可空引用类型里的 `string?` 不是同一种机制。

## 装箱和拆箱

装箱是把值类型转换成 `object` 或接口类型；拆箱是从 `object` 转回具体值类型。

```csharp
int number = 42;

object boxed = number;       // 装箱
int unboxed = (int)boxed;    // 拆箱

Console.WriteLine(unboxed);
```

装箱会产生额外分配，拆箱类型不匹配会抛异常。

```csharp
object value = 42;

// long wrong = (long)value; // InvalidCastException
int right = (int)value;
```

泛型集合 `List<int>` 比 `ArrayList` 更安全也更高效，一个原因就是它避免了频繁装箱拆箱。

## 参数传递：值传递与 ref/out/in

C# 默认按值传递参数。对于引用类型，复制的是引用本身。

```csharp
void Rename(Person person)
{
    person.Name = "Bob";
}

var person = new Person { Name = "Alice" };
Rename(person);

Console.WriteLine(person.Name); // Bob
```

如果在方法内部把参数重新指向新对象，不会改变调用方变量本身。

```csharp
void Replace(Person person)
{
    person = new Person { Name = "Cindy" };
}

var person = new Person { Name = "Alice" };
Replace(person);

Console.WriteLine(person.Name); // Alice
```

需要改变调用方变量指向时，可以使用 `ref`，但业务代码中应谨慎使用。

```csharp
void Replace(ref Person person)
{
    person = new Person { Name = "Cindy" };
}

var person = new Person { Name = "Alice" };
Replace(ref person);

Console.WriteLine(person.Name); // Cindy
```

### out：必须赋值的输出参数

`out` 参数要求方法内部必须赋值，调用方必须在调用时声明 `out` 变量。

```csharp
bool TryGetDiscount(string code, out decimal discount)
{
    discount = 0m;

    if (code == "VIP50")
    {
        discount = 50m;
        return true;
    }

    return false;
}

if (TryGetDiscount("VIP50", out decimal discount))
{
    Console.WriteLine($"优惠金额：{discount}");
}
```

`TryParse`、`TryGetValue` 等方法都用 `out` 返回额外数据。

### in：只读引用传递

`in` 传递引用但不允许修改，避免 struct 拷贝的同时保证安全。

```csharp
decimal CalculateDistance(in Point from, in Point to)
{
    // from.X = 0; // 编译错误：in 参数不能修改
    return (decimal)Math.Sqrt(Math.Pow(from.X - to.X, 2) + Math.Pow(from.Y - to.Y, 2));
}
```

`in` 主要用于传递较大的 `struct` 时避免值拷贝开销。小型 struct（如 `int`、`decimal`）用 `in` 反而可能因间接寻址更慢。

### record 与值/引用类型

`record class`（简写 `record`）是引用类型，`record struct` 是值类型。`record` 在对应基础上增加了按值比较、`with` 表达式、`ToString()` 等自动生成的成员。

```csharp
public record class UserDto(int Id, string Name);       // 引用类型，按值比较
public readonly record struct Money(decimal Amount, string Currency); // 值类型，按值比较
```

选择 `record class` 还是 `record struct` 的原则和 `class` vs `struct` 一致：数据量小、不可变、强调值语义用 `record struct`；有身份、需要引用语义用 `record class`。

## 类型转换

隐式转换不会丢失信息，显式转换需要强制写出。

```csharp
int count = 10;
long bigCount = count;       // 隐式转换

double price = 19.9;
int rounded = (int)price;    // 显式转换，小数部分被截断

Console.WriteLine(rounded);  // 19
```

字符串转换优先使用 `TryParse`，不要用异常控制正常输入流程。

```csharp
string input = "123";

if (int.TryParse(input, out int result))
{
    Console.WriteLine(result);
}
```

## 总结

类型系统决定了数据如何被保存、复制、比较和传递。掌握值类型、引用类型、`class`、`struct`、`enum`、可空值类型和装箱拆箱后，再看泛型、集合、LINQ、EF Core 实体建模，会更容易理解它们的边界。

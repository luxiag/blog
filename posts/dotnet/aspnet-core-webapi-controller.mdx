# ASP.NET Core Web API：Controller、Action 与结果返回

Controller 是 ASP.NET Core Web API 最常见的组织方式。它把一组相关接口放在一个类中，每个 Action 处理一个具体请求。

阶段一先用 Controller 写标准 Web API，因为它适合中大型项目，也能清晰展示路由、参数绑定、模型验证和结果返回。

## 创建 Controller

Controller 通常放在 `Controllers` 目录下。

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetAll()
    {
        return Ok(new[] { "Keyboard", "Mouse" });
    }
}
```

关键点：

- `[ApiController]` 启用 Web API 约定，例如自动模型验证。
- `[Route("api/products")]` 定义控制器路由前缀。
- `ControllerBase` 提供 `Ok`、`NotFound`、`BadRequest` 等辅助方法。

## [ApiController] 约定详解

`[ApiController]` 不只是"自动模型验证"，它启用了多项约定，每一条都在减少你的样板代码：

**自动 400 响应**：模型验证失败时，框架自动返回 HTTP 400，不需要手动检查 `ModelState.IsValid`。

```csharp
[HttpPost]
public ActionResult<ProductDto> Create(CreateProductRequest request)
{
    // 如果 request 验证失败，这里不会执行，框架已经返回 400
    return CreatedAtAction(nameof(GetById), new { id = 1 }, request);
}
```

没有 `[ApiController]` 时你需要这样写：

```csharp
[HttpPost]
public ActionResult<ProductDto> Create(CreateProductRequest request)
{
    if (!ModelState.IsValid)
    {
        return BadRequest(ModelState);
    }

    return CreatedAtAction(nameof(GetById), new { id = 1 }, request);
}
```

**参数来源推断**：没有 `[ApiController]` 时，复杂类型默认从表单绑定。加上 `[ApiController]` 后，复杂类型默认从请求体（`[FromBody]`）绑定，简单类型从路由/查询字符串绑定，不再需要每个参数都显式标注 `[FromBody]`。

**ProblemDetails 响应格式**：4xx 和 5xx 错误自动使用 RFC 7807 标准格式返回：

```json
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "traceId": "00-abc123-def456-01",
  "errors": {
    "Name": ["The Name field is required."]
  }
}
```

这种格式对前端解析更友好，`type` 字段可以链接到错误文档，`errors` 按字段分组。

**必填参数推断**：Action 参数中不可为 null 的类型（如 `int`、`Guid`）会被自动视为必填。请求中缺少这些参数时直接返回 400，而不是传入默认值导致运行时异常。

## ControllerBase 与 Controller

| 类型 | 用途 |
|---|---|
| `ControllerBase` | Web API，不需要 View |
| `Controller` | MVC 页面，支持 View |

纯 Web API 项目使用 `ControllerBase` 即可。

## Action 返回类型

常见返回类型：

| 返回类型 | 场景 |
|---|---|
| `IActionResult` | 灵活返回不同状态码 |
| `ActionResult<T>` | 返回具体数据，同时支持状态码 |
| `T` | 简单返回数据，不推荐复杂场景 |

推荐使用 `ActionResult<T>`：

```csharp
[HttpGet("{id:int}")]
public ActionResult<ProductDto> GetById(int id)
{
    ProductDto? product = FindProduct(id);

    if (product is null)
    {
        return NotFound();
    }

    return Ok(product);
}
```

## 常用结果方法

| 方法 | 状态码 | 场景 |
|---|---|---|
| `Ok(value)` | 200 | 查询成功 |
| `CreatedAtAction(...)` | 201 | 创建成功 |
| `NoContent()` | 204 | 成功但无响应体 |
| `BadRequest(...)` | 400 | 请求错误 |
| `Unauthorized()` | 401 | 未认证 |
| `Forbid()` | 403 | 无权限 |
| `NotFound()` | 404 | 资源不存在 |
| `Conflict(...)` | 409 | 状态冲突 |

## 用 DTO 表达请求和响应

不要直接把数据库实体暴露给 API。建议使用 DTO。

```csharp
public record ProductDto(int Id, string Name, decimal Price);

public class CreateProductRequest
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

DTO 的好处：

- API 契约更稳定
- 避免暴露内部字段
- 请求和响应可以分别建模
- 便于模型验证

## 完整 CRUD 示例

下面用内存集合实现一个阶段一练习用的商品 API。

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    private static readonly List<ProductDto> Products = new()
    {
        new ProductDto(1, "Keyboard", 199m),
        new ProductDto(2, "Mouse", 99m)
    };

    [HttpGet]
    public ActionResult<List<ProductDto>> GetAll()
    {
        return Ok(Products);
    }

    [HttpGet("{id:int}")]
    public ActionResult<ProductDto> GetById(int id)
    {
        ProductDto? product = Products.FirstOrDefault(item => item.Id == id);

        if (product is null)
        {
            return NotFound();
        }

        return Ok(product);
    }

    [HttpPost]
    public ActionResult<ProductDto> Create(CreateProductRequest request)
    {
        int id = Products.Count == 0 ? 1 : Products.Max(item => item.Id) + 1;
        var product = new ProductDto(id, request.Name, request.Price);

        Products.Add(product);

        return CreatedAtAction(nameof(GetById), new { id = product.Id }, product);
    }

    [HttpPut("{id:int}")]
    public IActionResult Update(int id, UpdateProductRequest request)
    {
        int index = Products.FindIndex(item => item.Id == id);

        if (index < 0)
        {
            return NotFound();
        }

        Products[index] = new ProductDto(id, request.Name, request.Price);

        return NoContent();
    }

    [HttpDelete("{id:int}")]
    public IActionResult Delete(int id)
    {
        ProductDto? product = Products.FirstOrDefault(item => item.Id == id);

        if (product is null)
        {
            return NotFound();
        }

        Products.Remove(product);

        return NoContent();
    }
}

public record ProductDto(int Id, string Name, decimal Price);

public class CreateProductRequest
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}

public class UpdateProductRequest
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

这个例子暂时用静态集合保存数据，只为了练习 Web API 主链路。生产项目应使用数据库和服务层。

## Controller 不应该承担太多职责

阶段一为了示例简单，把逻辑写在 Controller 中。真实项目里，Controller 应该尽量薄：

- 接收请求
- 调用应用服务
- 返回 HTTP 结果

业务规则、数据库访问、外部服务调用应该放到 Service / Repository / Application 层。

### 薄 Controller 示例

把 CRUD 示例中的逻辑抽取到 Service 层后，Controller 变成：

```csharp
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    private readonly IProductService _productService;

    public ProductsController(IProductService productService)
    {
        _productService = productService;
    }

    [HttpGet]
    public async Task<ActionResult<List<ProductDto>>> GetAll()
    {
        var products = await _productService.GetAllAsync();
        return Ok(products);
    }

    [HttpGet("{id:int}")]
    public async Task<ActionResult<ProductDto>> GetById(int id)
    {
        var product = await _productService.GetByIdAsync(id);

        if (product is null)
        {
            return NotFound();
        }

        return Ok(product);
    }

    [HttpPost]
    public async Task<ActionResult<ProductDto>> Create(CreateProductRequest request)
    {
        var product = await _productService.CreateAsync(request);

        return CreatedAtAction(nameof(GetById), new { id = product.Id }, product);
    }

    [HttpPut("{id:int}")]
    public async Task<IActionResult> Update(int id, UpdateProductRequest request)
    {
        var success = await _productService.UpdateAsync(id, request);

        if (!success)
        {
            return NotFound();
        }

        return NoContent();
    }

    [HttpDelete("{id:int}")]
    public async Task<IActionResult> Delete(int id)
    {
        var success = await _productService.DeleteAsync(id);

        if (!success)
        {
            return NotFound();
        }

        return NoContent();
    }
}
```

Service 层负责业务逻辑和数据访问：

```csharp
public interface IProductService
{
    Task<List<ProductDto>> GetAllAsync();
    Task<ProductDto?> GetByIdAsync(int id);
    Task<ProductDto> CreateAsync(CreateProductRequest request);
    Task<bool> UpdateAsync(int id, UpdateProductRequest request);
    Task<bool> DeleteAsync(int id);
}

public class ProductService : IProductService
{
    private readonly IProductRepository _repository;

    public ProductService(IProductRepository repository)
    {
        _repository = repository;
    }

    public async Task<List<ProductDto>> GetAllAsync()
    {
        return await _repository.GetAllAsync();
    }

    public async Task<ProductDto?> GetByIdAsync(int id)
    {
        return await _repository.GetByIdAsync(id);
    }

    public async Task<ProductDto> CreateAsync(CreateProductRequest request)
    {
        var product = new ProductDto(0, request.Name, request.Price);
        return await _repository.CreateAsync(product);
    }

    public async Task<bool> UpdateAsync(int id, UpdateProductRequest request)
    {
        return await _repository.UpdateAsync(id, request.Name, request.Price);
    }

    public async Task<bool> DeleteAsync(int id)
    {
        return await _repository.DeleteAsync(id);
    }
}
```

Controller 现在只做三件事：接收请求、调用 Service、返回 HTTP 结果。业务变化改 Service，数据存储改 Repository，Controller 基本不需要动。

## 总结

Controller 是 ASP.NET Core Web API 的常规入口。掌握 `ControllerBase`、`ActionResult<T>`、状态码和 DTO 后，就可以写出清晰的 RESTful API。

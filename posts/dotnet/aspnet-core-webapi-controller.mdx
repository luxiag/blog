# ASP.NET Core Web API：Controller、Action 与结果返回

Controller 是 ASP.NET Core Web API 最常见的组织方式。它把一组相关接口放在一个类中，每个 Action 处理一个具体请求。

阶段一先用 Controller 写标准 Web API，因为它适合中大型项目，也能清晰展示路由、参数绑定、模型验证和结果返回。

## 创建 Controller

Controller 通常放在 `Controllers` 目录下。

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetAll()
    {
        return Ok(new[] { "Keyboard", "Mouse" });
    }
}
```

关键点：

- `[ApiController]` 启用 Web API 约定，例如自动模型验证。
- `[Route("api/products")]` 定义控制器路由前缀。
- `ControllerBase` 提供 `Ok`、`NotFound`、`BadRequest` 等辅助方法。

## [ApiController] 约定详解

`[ApiController]` 不只是"自动模型验证"，它启用了多项约定，每一条都在减少你的样板代码。

### 模型验证是什么

模型验证（Model Validation）是指：ASP.NET Core 先把请求体、路由参数或查询字符串转换成 C# 对象，再检查这个对象是否满足预先定义的规则。

下面的请求模型使用 `System.ComponentModel.DataAnnotations` 中的特性声明验证规则：

```csharp
using System.ComponentModel.DataAnnotations;

public class CreateProductRequest
{
    [Required(ErrorMessage = "商品名称不能为空")]
    [StringLength(100, ErrorMessage = "商品名称不能超过 100 个字符")]
    public string Name { get; set; } = string.Empty;

    [Range(typeof(decimal), "0.01", "999999", ErrorMessage = "商品价格必须在 0.01 到 999999 之间")]
    public decimal Price { get; set; }
}
```

如果客户端提交空名称和负数价格：

```json
{
  "name": "",
  "price": -10
}
```

验证结果会分别指出 `Name` 不符合 `[Required]`、`Price` 不符合 `[Range]`。这里需要区分两个连续的步骤：

1. **模型绑定（Model Binding）**：把 JSON、路由参数或查询字符串转换成 C# 对象。
2. **模型验证（Model Validation）**：检查绑定后的对象是否满足 `[Required]`、`[StringLength]`、`[Range]` 等规则。

模型验证适合处理字段必填、字符串长度和数值范围等输入规则。“商品是否存在”“库存是否充足”这类需要访问数据库或结合业务状态才能判断的规则，应放在业务服务中验证。

**自动 400 响应**：模型验证失败时，框架自动返回 HTTP 400，不需要手动检查 `ModelState.IsValid`。

```csharp
[HttpPost]
public ActionResult<ProductDto> Create(CreateProductRequest request)
{
    // 如果 request 验证失败，这里不会执行，框架已经返回 400
    return CreatedAtAction(nameof(GetById), new { id = 1 }, request);
}
```

没有 `[ApiController]` 时你需要这样写：

```csharp
[HttpPost]
public ActionResult<ProductDto> Create(CreateProductRequest request)
{
    if (!ModelState.IsValid)
    {
        return BadRequest(ModelState);
    }

    return CreatedAtAction(nameof(GetById), new { id = 1 }, request);
}
```

**参数来源推断**：没有 `[ApiController]` 时，复杂类型默认从表单绑定。加上 `[ApiController]` 后，复杂类型默认从请求体（`[FromBody]`）绑定，简单类型从路由/查询字符串绑定，不再需要每个参数都显式标注 `[FromBody]`。

**ProblemDetails 响应格式**：4xx 和 5xx 错误自动使用 RFC 7807 标准格式返回：

```json
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "traceId": "00-abc123-def456-01",
  "errors": {
    "Name": ["The Name field is required."]
  }
}
```

这种格式对前端解析更友好，`type` 字段可以链接到错误文档，`errors` 按字段分组。

**必填参数推断**：Action 参数中不可为 null 的类型（如 `int`、`Guid`）会被自动视为必填。请求中缺少这些参数时直接返回 400，而不是传入默认值导致运行时异常。

## ControllerBase 与 Controller

| 类型 | 用途 |
|---|---|
| `ControllerBase` | Web API，不需要 View |
| `Controller` | MVC 页面，支持 View |

纯 Web API 项目使用 `ControllerBase` 即可。

## Action 返回类型

这里的“Action 返回类型”指的是**控制器方法的返回值类型**，不是方法名。控制器中用于处理 HTTP 请求的公开方法称为 Action，例如：

```csharp
[HttpGet("{id:int}")]
public ActionResult<ProductDto> GetById(int id)
{
    return Ok(new ProductDto(id, "Keyboard", 199m));
}
```

方法签名可以拆成下面几部分：

- `public`：访问修饰符。
- `ActionResult<ProductDto>`：方法的返回类型。
- `GetById`：方法名。
- `int id`：方法参数。

常见返回类型：

| 返回类型 | 场景 |
|---|---|
| `IActionResult` | 灵活返回不同状态码，但方法签名不描述成功响应的数据类型 |
| `ActionResult<T>` | 既描述成功响应的数据类型，也允许返回不同状态码 |
| `T` | 直接返回数据，适合只会产生成功响应的简单场景 |

### IActionResult

`IActionResult` 表示 Action 返回某一种 HTTP 操作结果，因此可以根据执行情况返回不同状态码：

```csharp
[HttpGet("{id:int}")]
public IActionResult GetById(int id)
{
    if (id <= 0)
    {
        return BadRequest("商品 ID 必须大于 0");
    }

    if (id != 1)
    {
        return NotFound();
    }

    return Ok(new ProductDto(1, "Keyboard", 199m));
}
```

这种写法很灵活，但仅从 `IActionResult` 无法看出接口成功时返回的是 `ProductDto`。

### `ActionResult<T>`

`ActionResult<T>` 中的 `T` 是类型占位符。`ActionResult<ProductDto>` 表示这个 Action 成功时主要返回 `ProductDto`，同时也可以返回 `NotFound()`、`BadRequest()` 等 HTTP 结果，因此通常推荐用于 Web API：

```csharp
[HttpGet("{id:int}")]
public ActionResult<ProductDto> GetById(int id)
{
    ProductDto? product = FindProduct(id);

    if (product is null)
    {
        return NotFound();
    }

    return Ok(product);
}
```

成功时也可以直接返回 `T`，ASP.NET Core 会把它转换为响应结果：

```csharp
return product;
```

如果接口返回集合，可以把 `T` 换成集合类型：

```csharp
[HttpGet]
public ActionResult<List<ProductDto>> GetAll()
{
    return Ok(new List<ProductDto>
    {
        new(1, "Keyboard", 199m),
        new(2, "Mouse", 99m)
    });
}
```

### 直接返回 T

直接使用业务类型作为返回类型时，写法最简单：

```csharp
[HttpGet("{id:int}")]
public ProductDto GetById(int id)
{
    return new ProductDto(id, "Keyboard", 199m);
}
```

但这个方法只能返回 `ProductDto`，不能直接返回 `NotFound()` 等其他结果，因此不适合需要表达失败状态的接口。

异步 Action 通常在外层增加 `Task`：

```csharp
[HttpGet("{id:int}")]
public async Task<ActionResult<ProductDto>> GetByIdAsync(int id)
{
    ProductDto? product = await FindProductAsync(id);

    if (product is null)
    {
        return NotFound();
    }

    return Ok(product);
}
```

这里的 `Task` 表示异步操作，Action 最终产生的结果仍然是 `ActionResult<ProductDto>`。

## 常用结果方法

| 方法 | 状态码 | 场景 |
|---|---|---|
| `Ok(value)` | 200 | 查询成功 |
| `CreatedAtAction(...)` | 201 | 创建成功 |
| `NoContent()` | 204 | 成功但无响应体 |
| `BadRequest(...)` | 400 | 请求错误 |
| `Unauthorized()` | 401 | 未认证 |
| `Forbid()` | 403 | 无权限 |
| `NotFound()` | 404 | 资源不存在 |
| `Conflict(...)` | 409 | 状态冲突 |

这些方法由 `ControllerBase` 提供，不需要为每个方法单独引入包。控制器继承 `ControllerBase` 后就可以直接调用它们；项目通常仍需要 `using Microsoft.AspNetCore.Mvc;` 来使用控制器基类和相关特性。

### 与统一 JSON 响应的关系

`Ok()`、`NotFound()` 等方法负责设置真正的 **HTTP 状态码**，而 `{ code, data, msg }` 负责定义项目自己的 **JSON 响应结构**。两者并不冲突，通常应该结合使用。

先定义统一响应模型。C# 属性名经过 ASP.NET Core 默认的 camelCase JSON 序列化后，会分别变成 `code`、`data` 和 `msg`：

```csharp
public sealed record ApiResponse<T>(
    int Code,
    T? Data,
    string Msg
);
```

查询接口可以同时返回标准 HTTP 状态和统一响应体：

```csharp
[HttpGet("{id:int}")]
public ActionResult<ApiResponse<ProductDto>> GetById(int id)
{
    ProductDto? product = FindProduct(id);

    if (product is null)
    {
        return NotFound(new ApiResponse<ProductDto>(
            Code: 404,
            Data: null,
            Msg: "商品不存在"
        ));
    }

    return Ok(new ApiResponse<ProductDto>(
        Code: 200,
        Data: product,
        Msg: "查询成功"
    ));
}
```

查询成功时，真正的 HTTP 状态是 `200 OK`，响应体为：

```json
{
  "code": 200,
  "data": {
    "id": 1,
    "name": "Keyboard",
    "price": 199
  },
  "msg": "查询成功"
}
```

商品不存在时，应通过 `NotFound(...)` 返回真正的 `404 Not Found`，同时让响应体中的 `code` 也保持为 404：

```json
{
  "code": 404,
  "data": null,
  "msg": "商品不存在"
}
```

不建议错误发生时仍调用 `Ok(...)`，只在响应体中写入 404：

```csharp
// 不推荐：真正的 HTTP 状态仍然是 200
return Ok(new ApiResponse<ProductDto>(404, null, "商品不存在"));
```

如果所有请求都返回 HTTP 200，浏览器、网关、缓存和监控系统都会把失败请求判断为成功，客户端也必须额外检查响应体中的 `code`。因此，通常应让 HTTP 状态码与响应体中的状态保持一致。

创建资源时，`CreatedAtAction(...)` 除了返回 `201 Created`，还会生成指向新资源的 `Location` 响应头：

```csharp
return CreatedAtAction(
    nameof(GetById),
    new { id = product.Id },
    new ApiResponse<ProductDto>(201, product, "创建成功")
);
```

需要注意，`NoContent()` 表示 `204 No Content`，按照 HTTP 语义不能包含 JSON 响应体。如果项目规定所有成功响应都必须包含统一结构，就不应对该接口使用 `NoContent()`，而应根据团队约定返回 `Ok(...)`。

:::tip 统一响应不只涉及 Controller
`[ApiController]` 自动生成的模型验证 400 响应默认使用 `ValidationProblemDetails`，未处理异常也可能使用其他错误格式。如果项目要求所有错误都使用 `{ code, data, msg }`，应在全局统一配置模型验证响应和异常处理，而不是在每个 Action 中重复包装。
:::

## 用 DTO 表达请求和响应

不要直接把数据库实体暴露给 API。建议使用 DTO。

```csharp
public record ProductDto(int Id, string Name, decimal Price);

public class CreateProductRequest
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

DTO 的好处：

- API 契约更稳定
- 避免暴露内部字段
- 请求和响应可以分别建模
- 便于模型验证

## 完整 CRUD 示例

下面用内存集合实现一个阶段一练习用的商品 API。

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    private static readonly List<ProductDto> Products = new()
    {
        new ProductDto(1, "Keyboard", 199m),
        new ProductDto(2, "Mouse", 99m)
    };

    [HttpGet]
    public ActionResult<List<ProductDto>> GetAll()
    {
        return Ok(Products);
    }

    [HttpGet("{id:int}")]
    public ActionResult<ProductDto> GetById(int id)
    {
        ProductDto? product = Products.FirstOrDefault(item => item.Id == id);

        if (product is null)
        {
            return NotFound();
        }

        return Ok(product);
    }

    [HttpPost]
    public ActionResult<ProductDto> Create(CreateProductRequest request)
    {
        int id = Products.Count == 0 ? 1 : Products.Max(item => item.Id) + 1;
        var product = new ProductDto(id, request.Name, request.Price);

        Products.Add(product);

        return CreatedAtAction(nameof(GetById), new { id = product.Id }, product);
    }

    [HttpPut("{id:int}")]
    public IActionResult Update(int id, UpdateProductRequest request)
    {
        int index = Products.FindIndex(item => item.Id == id);

        if (index < 0)
        {
            return NotFound();
        }

        Products[index] = new ProductDto(id, request.Name, request.Price);

        return NoContent();
    }

    [HttpDelete("{id:int}")]
    public IActionResult Delete(int id)
    {
        ProductDto? product = Products.FirstOrDefault(item => item.Id == id);

        if (product is null)
        {
            return NotFound();
        }

        Products.Remove(product);

        return NoContent();
    }
}

public record ProductDto(int Id, string Name, decimal Price);

public class CreateProductRequest
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}

public class UpdateProductRequest
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

这个例子暂时用静态集合保存数据，只为了练习 Web API 主链路。生产项目应使用数据库和服务层。

## Controller 不应该承担太多职责

阶段一为了示例简单，把逻辑写在 Controller 中。真实项目里，Controller 应该尽量薄：

- 接收请求
- 调用应用服务
- 返回 HTTP 结果

业务规则、数据库访问、外部服务调用应该放到 Service / Repository / Application 层。

### 薄 Controller 示例

把 CRUD 示例中的逻辑抽取到 Service 层后，Controller 变成：

```csharp
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    private readonly IProductService _productService;

    public ProductsController(IProductService productService)
    {
        _productService = productService;
    }

    [HttpGet]
    public async Task<ActionResult<List<ProductDto>>> GetAll()
    {
        var products = await _productService.GetAllAsync();
        return Ok(products);
    }

    [HttpGet("{id:int}")]
    public async Task<ActionResult<ProductDto>> GetById(int id)
    {
        var product = await _productService.GetByIdAsync(id);

        if (product is null)
        {
            return NotFound();
        }

        return Ok(product);
    }

    [HttpPost]
    public async Task<ActionResult<ProductDto>> Create(CreateProductRequest request)
    {
        var product = await _productService.CreateAsync(request);

        return CreatedAtAction(nameof(GetById), new { id = product.Id }, product);
    }

    [HttpPut("{id:int}")]
    public async Task<IActionResult> Update(int id, UpdateProductRequest request)
    {
        var success = await _productService.UpdateAsync(id, request);

        if (!success)
        {
            return NotFound();
        }

        return NoContent();
    }

    [HttpDelete("{id:int}")]
    public async Task<IActionResult> Delete(int id)
    {
        var success = await _productService.DeleteAsync(id);

        if (!success)
        {
            return NotFound();
        }

        return NoContent();
    }
}
```

Service 层负责业务逻辑和数据访问：

```csharp
public interface IProductService
{
    Task<List<ProductDto>> GetAllAsync();
    Task<ProductDto?> GetByIdAsync(int id);
    Task<ProductDto> CreateAsync(CreateProductRequest request);
    Task<bool> UpdateAsync(int id, UpdateProductRequest request);
    Task<bool> DeleteAsync(int id);
}

public class ProductService : IProductService
{
    private readonly IProductRepository _repository;

    public ProductService(IProductRepository repository)
    {
        _repository = repository;
    }

    public async Task<List<ProductDto>> GetAllAsync()
    {
        return await _repository.GetAllAsync();
    }

    public async Task<ProductDto?> GetByIdAsync(int id)
    {
        return await _repository.GetByIdAsync(id);
    }

    public async Task<ProductDto> CreateAsync(CreateProductRequest request)
    {
        var product = new ProductDto(0, request.Name, request.Price);
        return await _repository.CreateAsync(product);
    }

    public async Task<bool> UpdateAsync(int id, UpdateProductRequest request)
    {
        return await _repository.UpdateAsync(id, request.Name, request.Price);
    }

    public async Task<bool> DeleteAsync(int id)
    {
        return await _repository.DeleteAsync(id);
    }
}
```

Controller 现在只做三件事：接收请求、调用 Service、返回 HTTP 结果。业务变化改 Service，数据存储改 Repository，Controller 基本不需要动。

## 总结

Controller 是 ASP.NET Core Web API 的常规入口。掌握 `ControllerBase`、`ActionResult<T>`、状态码和 DTO 后，就可以写出清晰的 RESTful API。

下一步需要重点学习参数绑定和模型验证，让 API 能正确接收和校验客户端输入。

# Three.js 相机体系详解：从投影到稳定运镜

相机不是把场景“拍成图片”的实体模型，而是一组观察变换与投影参数。渲染器用它判断物体如何从世界空间进入屏幕，以及哪些内容应被裁掉。

相机建立在坐标变换和场景树之上，建议先读：

## 从世界坐标到屏幕像素

一个顶点大致经过以下步骤：

```text
局部空间 → 世界空间 → View（相机）空间 → Clip 空间 → NDC → Viewport 像素
```

- **View 变换**是相机世界矩阵的逆矩阵 `camera.matrixWorldInverse`，相当于把整个世界搬到相机坐标系。
- **Projection 变换**由 `camera.projectionMatrix` 完成，把相机空间映射到 Clip 空间。
- Clip 坐标仍是齐次坐标 `(x, y, z, w)`；GPU 做透视除法 `(x/w, y/w, z/w)` 后得到 **NDC**。
- WebGL 的 NDC 可见范围是三个轴都在 `[-1, 1]` 内；超出裁剪范围的图元会被裁剪，随后 viewport 再把 NDC 映射为 canvas 像素。

这解释了为什么只移动相机不会修改场景对象的世界坐标：变化的是 View 矩阵。

## 透视相机：距离参与大小计算

```javascript
const camera = new THREE.PerspectiveCamera(fov, aspect, near, far)
```

- `fov` 是**垂直**视野角，单位为度；
- `aspect` 是画布宽高比；
- `near`、`far` 是沿相机观察方向的近、远裁剪距离，必须满足 `0 < near < far`。

在相机前方距离 `d` 处，视锥体可见高度为：

```text
visibleHeight = 2 · d · tan(fov / 2)
visibleWidth  = visibleHeight · aspect
```

公式计算时要把角度转为弧度：

```javascript
const height = 2 * distance * Math.tan(THREE.MathUtils.degToRad(camera.fov) / 2)
const width = height * camera.aspect
```

因此，距离加倍时，同一物体在屏幕上约缩小为一半；增大 FOV 也会让同一距离处容纳更多内容。


### near、far 与深度精度

透视投影的深度缓冲精度不是沿距离均匀分配的，而是大量集中在 near 附近。把 `near` 从合理的 `0.1` 降到极小值，或把 `far` 无必要地推到很远，都会扩大 `far / near` 比值并加重远处表面的 Z-fighting。

原则是：**near 设为业务允许的尽可能大值，far 设为覆盖场景所需的尽可能小值**。大型场景还可按尺度拆分、使用对数深度缓冲等方案，但不要先用极端裁剪面掩盖尺度设计问题。

## 正交相机：距离不改变投影大小

```javascript
const camera = new THREE.OrthographicCamera(left, right, top, bottom, near, far)
```

正交相机的可见体是长方体。忽略旋转时，基础可见范围为：

```text
width  = right - left
height = top - bottom
```

考虑 `camera.zoom` 后，实际可见宽高为：

```text
visibleWidth  = (right - left) / zoom
visibleHeight = (top - bottom) / zoom
```

一个常见策略是固定垂直世界范围，根据宽高比扩展水平方向：

```javascript
const viewHeight = 10
const aspect = width / height
camera.left = -(viewHeight * aspect) / 2
camera.right = (viewHeight * aspect) / 2
camera.top = viewHeight / 2
camera.bottom = -viewHeight / 2
camera.updateProjectionMatrix()
```

正交相机适合工程视图、2D/伪 3D 场景和需要稳定世界单位比例的 UI。物体远近不改变屏幕大小，但仍受 near/far 裁剪并参与深度测试。

## Resize：画布和投影必须一起更新

只改变 renderer 尺寸而不改相机投影，画面会被拉伸。原生 Three.js 可统一处理：

```javascript
function resize() {
  const width = container.clientWidth
  const height = container.clientHeight

  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))
  // 让 drawing buffer 与 canvas CSS 尺寸都匹配容器。
  renderer.setSize(width, height)

  if (camera.isPerspectiveCamera) {
    camera.aspect = width / height
  } else {
    const viewHeight = 10
    const aspect = width / height
    camera.left = -(viewHeight * aspect) / 2
    camera.right = (viewHeight * aspect) / 2
    camera.top = viewHeight / 2
    camera.bottom = -viewHeight / 2
  }
  camera.updateProjectionMatrix()
}

const observer = new ResizeObserver(resize)
observer.observe(container)
resize()
```

监听容器而不是只监听 `window`，可以覆盖侧栏收起、布局变化等情况。R3F 的 `<Canvas>` 会同步其默认相机和渲染尺寸；自建相机或自定义正交边界时，仍要明确实现自己的更新规则。


## Dolly、FOV 与 zoom 不是同一件事

三者都可能让主体“看起来变大”，但空间效果不同：

- **Dolly**：沿观察方向移动相机。相机与物体的相对距离改变，因此前后景相对位移和视差也改变。
- **FOV**：改变透视相机的视锥角，不移动相机。只改 FOV 会改变主体屏幕大小；若同时移动相机以保持主体大小，会产生常称为 dolly zoom 的透视变化。
- **`camera.zoom`**：修改投影倍率并需要 `updateProjectionMatrix()`。它不改变相机世界位置，因此不会像 dolly 那样改变视差；正交相机尤其常用 zoom。

OrbitControls 对透视相机的滚轮操作通常是 dolly，对正交相机则通常调整 zoom。选择方式应依据你希望改变的是观察位置、透视关系，还是单纯构图比例。

## OrbitControls：围绕 target 管理观察关系

`OrbitControls` 让相机围绕 `target` 旋转，并提供 dolly、pan 与限制范围。原生 Three.js 开启 damping 后需要在动画循环调用 `controls.update()`；R3F 中使用 drei 的 `<OrbitControls />` 时，组件会接入帧循环。

```javascript
const controls = new OrbitControls(camera, renderer.domElement)
controls.target.set(0, 1, 0)
controls.enableDamping = true
controls.minDistance = 2
controls.maxDistance = 12

renderer.setAnimationLoop(() => {
  controls.update()
  renderer.render(scene, camera)
})
```

它适合检查模型、展厅浏览和编辑器视口。若产品需要严格编排的镜头，应把相机位置与注视目标放入自己的 camera rig，而不是让 controls 与业务动画同时争夺相机。

## 与帧率无关的指数平滑

固定写法 `current += (target - current) * 0.05` 每帧推进固定比例，因此 144 FPS 会比 30 FPS 更快接近目标。用 delta 计算指数平滑系数可让响应速度跨帧率更一致：

```text
alpha = 1 - exp(-lambda · delta)
```

`lambda` 是每秒收敛强度，越大响应越快。R3F 示例：

```jsx
import * as THREE from 'three'
import { useFrame } from '@react-three/fiber'
import { useMemo } from 'react'

function CameraRig() {
  const targetPosition = useMemo(() => new THREE.Vector3(), [])
  const lookTarget = useMemo(() => new THREE.Vector3(), [])
  const desiredLookTarget = useMemo(() => new THREE.Vector3(), [])

  useFrame(({ camera, pointer }, delta) => {
    // 防止切回后台后的超大 delta 造成突跳。
    const dt = Math.min(delta, 0.1)
    const alpha = 1 - Math.exp(-6 * dt)

    targetPosition.set(pointer.x * 1.5, pointer.y * 0.8, 8)
    desiredLookTarget.set(pointer.x * 0.2, pointer.y * 0.1, 0)

    camera.position.lerp(targetPosition, alpha)
    lookTarget.lerp(desiredLookTarget, alpha)
    camera.lookAt(lookTarget)
  })

  return null
}
```

临时向量通过 `useMemo` 复用，避免每帧创建对象。`lookAt()` 在这里直接设置朝向，但注视点本身已平滑；需要更精细的姿态插值时，可计算目标 quaternion 并使用 `slerp`。

这能得到稳定、可调的网页视差或跟随镜头，但是否具有“电影感”还取决于构图、节奏、镜头焦段、运动曲线和场景内容，不能由一次 lerp 自动保证。

## 总结

- View 矩阵把世界变到相机空间，Projection 矩阵把它变到 Clip 空间；透视除法后进入 NDC。
- 透视相机在距离 `d` 处的可见高度为 `2d·tan(fov/2)`；正交范围由边界差值与 zoom 决定。
- resize 时要同步 renderer 尺寸、DPR、相机宽高比或正交边界，并更新投影矩阵。
- 合理收紧 near/far 能改善深度精度；不要把 near 设得无谓地小。
- dolly 改位置与视差，FOV 和 zoom 改投影；它们不能按“都能放大”混为一谈。
- 相机跟随应使用基于 delta 的指数平滑，而不是固定的每帧系数。

理解这些后，相机就不再是一组靠试出来的参数，而是从世界变换到屏幕构图的一条可推导链路。

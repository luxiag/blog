# Three.js 入门：完成并解释第一帧

这篇文章只解决一个目标：**让一个立方体正确出现在浏览器的第一帧里，并知道每一行为什么存在**。模型加载、光照、交互和后期处理都建立在这一步之上，先不急着展开。

Three.js 是 WebGL 之上的 JavaScript 3D 库。它替我们组织 GPU 资源、场景层级与绘制流程，但“画什么、从哪里看、画到哪里”仍需要明确给出。

## 第一帧需要什么

一次绘制可以概括为：

```text
Scene 中的对象 + Camera 的观察范围 → Renderer → canvas 像素
```

- `Scene` 是场景图根节点，保存要参与渲染的物体。
- `Camera` 决定观察位置与可见范围；它本身不会自动拍摄。
- `WebGLRenderer` 把 `scene` 从 `camera` 的视角绘制到 `<canvas>`。
- `Mesh` 是第一种可见对象，但它必须同时拥有 Geometry 与 Material。

## 第一个 Mesh：形状、表面与变换节点

```javascript
const geometry = new THREE.BoxGeometry(1, 1, 1)
const material = new THREE.MeshBasicMaterial({ color: 0x35c98b })
const cube = new THREE.Mesh(geometry, material)
scene.add(cube)
```

这里不是三个可以互换的概念：

1. **Geometry** 保存形状数据，例如顶点位置、法线、UV 和索引；`BoxGeometry` 描述“立方体长什么样”。
2. **Material** 描述这些表面如何着色；`MeshBasicMaterial` 不依赖灯光，适合验证第一帧。
3. **Mesh** 把 Geometry 与 Material 组合成可绘制对象。`Mesh` 继承自 `Object3D`，因此还拥有 `position`、`rotation`、`scale`、父子关系和局部/世界矩阵。

Geometry 和 Material 可以被多个 Mesh 共享；Mesh 的变换则属于该对象自身。第一帧看不到物体时，应依次检查：它是否加入 Scene、Camera 是否朝向它、是否落在 near/far 之间，以及材质是否需要场景中不存在的灯光。

## 原生 Three.js：从空页面到第一帧

先安装 `three`，再把下面代码放入由 Vite 等构建工具加载的模块中：

```bash
npm install three
```


```javascript
import * as THREE from 'three'

const scene = new THREE.Scene()
scene.background = new THREE.Color(0x111827)

const camera = new THREE.PerspectiveCamera(
  60,
  window.innerWidth / window.innerHeight,
  0.1,
  100
)
camera.position.set(0, 0, 3)

const renderer = new THREE.WebGLRenderer({ antialias: true })
// DPR 越高，像素越多；限制上限可避免高密度屏幕带来过高开销。
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))
renderer.setSize(window.innerWidth, window.innerHeight)
document.body.style.margin = '0'
document.body.appendChild(renderer.domElement)

const geometry = new THREE.BoxGeometry(1, 1, 1)
const material = new THREE.MeshBasicMaterial({ color: 0x35c98b })
const cube = new THREE.Mesh(geometry, material)
scene.add(cube)

// 到这里已经具备第一帧所需的一切。
renderer.render(scene, camera)
```

`camera.position.z = 3` 很关键：立方体位于原点，默认相机朝局部 `-Z` 看；把相机移到正 Z 轴后，原点才位于它前方。最后的 `render` 是一次明确的绘制调用，不会自动持续执行。

## 从第一帧扩展到可靠的动画循环

浏览器尺寸和屏幕像素密度都可能变化；动画速度也不应依赖设备每秒能画多少帧。下面补齐 resize、DPR 和 delta：

```javascript
const clock = new THREE.Clock()

function resize() {
  const width = window.innerWidth
  const height = window.innerHeight

  camera.aspect = width / height
  camera.updateProjectionMatrix()

  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))
  renderer.setSize(width, height)
}

window.addEventListener('resize', resize)

renderer.setAnimationLoop(() => {
  const delta = Math.min(clock.getDelta(), 0.1)
  cube.rotation.x += delta * 0.6 // 弧度/秒
  cube.rotation.y += delta * 1.0
  renderer.render(scene, camera)
})
```

`delta` 是距上一帧经过的秒数。使用 `角速度 × delta` 后，60 Hz 与 144 Hz 屏幕上的旋转速度基本一致。这里把 delta 限到 `0.1`，避免页面从后台恢复时一次跳过太大角度；若是物理模拟，通常还需要固定时间步长。

相机参数变化后必须调用 `updateProjectionMatrix()`。`renderer.setSize()` 调整 canvas 的绘制缓冲区与 CSS 尺寸；重新限制 DPR，则能在窗口跨屏或缩放变化时保持清晰度与成本的平衡。

组件卸载或页面不再使用这段场景时，还应移除 resize 监听、调用 `renderer.setAnimationLoop(null)`，并对自己创建且不再共享的 Geometry、Material、纹理和 Renderer 调用 `dispose()`。JavaScript 对象被回收不等于 GPU 资源会立刻自动释放。


## 同一第一帧在 React Three Fiber 中怎么写

React Three Fiber（R3F）是 React 的 Three.js renderer：它用 JSX 创建并协调 Three.js 对象，但底层对象与图形学概念没有改变。

```jsx
import { Canvas, useFrame } from '@react-three/fiber'
import { useRef } from 'react'

function Cube() {
  const cube = useRef()

  useFrame((_, delta) => {
    cube.current.rotation.x += delta * 0.6
    cube.current.rotation.y += delta
  })

  return (
    <mesh ref={cube}>
      <boxGeometry args={[1, 1, 1]} />
      <meshBasicMaterial color="#35c98b" />
    </mesh>
  )
}

export default function App() {
  return (
    <Canvas
      camera={{ position: [0, 0, 3], fov: 60, near: 0.1, far: 100 }}
      dpr={[1, 2]}
    >
      <color attach="background" args={["#111827"]} />
      <Cube />
    </Canvas>
  )
}
```

对应关系如下：

| 原生 Three.js | R3F |
| --- | --- |
| `new THREE.Scene()` | `<Canvas>` 创建并维护默认 Scene |
| `new THREE.PerspectiveCamera(...)` | `<Canvas camera={...}>` 的默认 Camera |
| `new THREE.WebGLRenderer(...)` 与 canvas | `<Canvas>` 管理 Renderer 与 canvas |
| `new THREE.Mesh(g, m)` | `<mesh>` 内嵌 geometry 与 material |
| `scene.add(cube)` | JSX 父子关系 |
| `setAnimationLoop` / `requestAnimationFrame` | `useFrame((state, delta) => ...)` |
| 手动 resize 与 DPR | `<Canvas>` 的尺寸监听与 `dpr` 配置 |

R3F 的主要价值是 React 式声明、组件组合和生命周期协调，**不是保证比原生 Three.js 更快**。最终性能仍取决于 draw call、Geometry、Material、纹理、着色器以及每帧工作量。它会为常见的声明式资源处理挂载/卸载，但外部创建、缓存或共享的资源仍需由应用明确管理，不能把它理解为“自动管理 GPU 垃圾回收”。

`@react-three/drei` 是 pmndrs 生态中常用的社区辅助组件库，与 R3F 配合紧密，但它不是 Three.js 核心包的一部分。应在理解底层对象后按需使用，而不是用辅助组件替代基本概念。

## 第一帧检查清单

1. Scene 中存在 Mesh，Mesh 同时有 Geometry 与 Material。
2. Camera 位于合适位置，物体在视锥和 near/far 范围内。
3. Renderer 尺寸与 DPR 已设置，并确实执行了一次 `render(scene, camera)`。
4. 动画使用 `delta` 表示每秒速度，resize 后更新相机投影。
5. 资源不再使用时，清理循环、事件监听与自己负责的 GPU 资源。

# Three.js 渲染器详解：数字世界的暗房师

如果说场景是拍摄现场，相机是摄影机，那么**渲染器 (Renderer)** 就是冲洗胶卷的暗房师。

它的工作是将场景中的 3D 数据（顶点、材质、光照），经过复杂的计算，最终绘制成一张张 2D 图像，显示在你的屏幕上。这个过程每秒钟要发生 60 次甚至更多。

Three.js 的核心渲染器是 **`WebGLRenderer`**，它封装了底层晦涩难懂的 WebGL API，让我们能用简单的配置实现高质量的画面。

---

## 一、 基础配置：画质与性能的平衡

在创建渲染器时，有几个关键参数决定了画面的基础质量。

### 1. 抗锯齿 (Antialias)
3D 物体边缘的锯齿是图形学的顽疾。
*   **`antialias: true`**: 开启 MSAA (多重采样抗锯齿)。这会让边缘平滑很多，但会消耗更多显卡性能。
*   **注意**: 在高分屏（如 Retina）上，像素密度极高，锯齿本就不明显，有时可以关闭抗锯齿以节省性能。

### 2. 透明背景 (Alpha)
默认情况下，渲染器的背景是黑色的。
*   **`alpha: true`**: 允许背景透明，这样 `<canvas>` 下面的网页内容（如 CSS 背景图）就能透出来。

### 3. 像素比 (PixelRatio)
这是移动端开发的大坑。Retina 屏幕的物理像素是 CSS 像素的 2-3 倍。如果不处理，画面会模糊。
*   **最佳实践**: `Math.min(window.devicePixelRatio, 2)`。
*   **解释**: 虽然手机屏幕可能是 3 倍甚至 4 倍屏，但渲染 3 倍像素的开销是巨大的（像素量是 1 倍的 9 倍！）。限制在 2 倍通常是画质与发热的最佳平衡点。

## 二、 色调映射 (Tone Mapping)：电影感的来源

现实世界的光照强度范围极其巨大（从微弱烛光到刺眼太阳），这被称为 **HDR (高动态范围)**。
但显示器只能显示有限的亮度范围（通常是 0.0 到 1.0），这被称为 **LDR (低动态范围)**。

**色调映射**就是把 HDR 压缩到 LDR 的过程。如果没有它，过亮的地方会直接变成一片死白（过曝），丢失所有细节。

### 常用算法
Three.js 提供了多种映射算法：
1.  **`NoToneMapping`**: 不处理。容易过曝，色彩生硬。
2.  **`LinearToneMapping`**: 线性压缩。效果一般。
3.  **`ReinhardToneMapping`**: 经典的压制高光算法，但会让画面整体偏灰。
4.  **`ACESFilmicToneMapping`**: **工业标准**。电影级的对比度和色彩，色彩鲜艳，高光柔和。推荐默认使用。

## 三、 阴影配置 (Shadow Map)：让世界立体起来

Three.js 的阴影不是自动生成的，因为它非常消耗性能。它使用 **Shadow Map**（阴影贴图）技术：从光源的视角拍一张照片，记录深度，再在渲染时对比。

### 开启阴影的“三步走”
1.  **渲染器开启**: `renderer.shadowMap.enabled = true`。
2.  **光源开启**: `light.castShadow = true`。
3.  **物体开启**: 投射阴影的物体 `castShadow`，接收阴影的物体 `receiveShadow`。

### 常见阴影类型
*   **`BasicShadowMap`**: 性能最好，但锯齿严重，像像素画。
*   **`PCFShadowMap`**: (默认) 边缘经过平滑处理，效果不错。
*   **`PCFSoftShadowMap`**: 边缘更加柔和，接近真实阴影。
*   **`VSMShadowMap`**: 高级方差阴影，能解决某些阴影伪影问题，但配置复杂。

<CodePenDemo title="Shadow Types" code={`
function ShadowScene() {
  const { gl } = useThree()
  const [type, setType] = useState(THREE.PCFSoftShadowMap)
  
  // 动态切换阴影类型
  useFrame(() => {
    gl.shadowMap.type = type
    gl.shadowMap.needsUpdate = true // 必须标记更新，否则不会生效
  })

  return (
    <>
      {/* 投射阴影的球体 */}
      <mesh position={[0, 1, 0]} castShadow>
        <sphereGeometry args={[0.5, 32, 32]} />
        <meshStandardMaterial color="hotpink" />
      </mesh>
      
      {/* 接收阴影的平面 */}
      <mesh rotation={[-Math.PI/2, 0, 0]} receiveShadow>
        <planeGeometry args={[10, 10]} />
        <meshStandardMaterial color="#eee" />
      </mesh>

      {/* 产生阴影的光源 */}
      <directionalLight 
        position={[5, 5, 5]} 
        intensity={1} 
        castShadow 
        // 阴影贴图分辨率：越大越清晰，越卡
        shadow-mapSize={[1024, 1024]} 
      />
      <ambientLight intensity={0.2} />

      <Html position={[0, 2.5, 0]} center>
         <div className="bg-black/80 text-white p-2 rounded">
           <select 
             className="text-black p-1 rounded"
             onChange={e => setType(Number(e.target.value))}
             value={type}
           >
             <option value={THREE.BasicShadowMap}>Basic (Fastest)</option>
             <option value={THREE.PCFShadowMap}>PCF (Default)</option>
             <option value={THREE.PCFSoftShadowMap}>PCF Soft (Nicest)</option>
           </select>
         </div>
      </Html>
      <OrbitControls />
    </>
  )
}

render(
  <Canvas shadows>
    <ShadowScene />
  </Canvas>
)
`} />

## 四、 深度排序与透明 (Transparency)

渲染器最头疼的问题之一就是**透明物体**。
如果场景里有玻璃、水、半透明塑料，渲染器必须小心翼翼地决定**谁在谁前面**。

### 渲染顺序
1.  先画所有**不透明**物体（由近到远，利用深度缓冲剔除被遮挡的像素，提升性能）。
2.  再画所有**透明**物体（由远到近，这样才能透过前面的看到后面的）。

### 常见 Bug：透明物体乱序
如果你发现透过一个玻璃球看不到里面的东西，或者看到的顺序反了，通常是因为：
*   **`depthWrite: false`**: 很多透明材质默认会关闭深度写入。
*   **排序失败**: 当物体互相穿插时，简单的“由远到近”排序就失效了。

### 解决方案
*   尽量减少透明物体的重叠。
*   使用 `alphaTest`：对于树叶这种“要么全透要么不透”的纹理，不要用 `transparent: true`，而是用 `alphaTest: 0.5`，把它当成不透明物体渲染。

## 总结

WebGLRenderer 虽然只是一个“画图的”，但它决定了画面的下限。
*   **基础配置**：记得开启 `antialias` 并在移动端限制 `pixelRatio`。
*   **色彩管理**：**ACESFilmic** 色调映射是提升质感的捷径。
*   **阴影系统**：`PCFSoftShadowMap` 能提供最自然的阴影，但要注意性能。
*   **透明物体**：是性能杀手也是 Bug 之源，能用 `alphaTest` 就别用 `transparent`。

掌握了这些，你就能像专业的暗房师一样，精准控制画面的每一个像素。

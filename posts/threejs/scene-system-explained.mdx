# Three.js 场景系统详解：层级、坐标与变换

场景不是“装物体的数组”，而是一棵变换树。父节点的移动、旋转与缩放会通过矩阵传给子节点；理解这条传播链，才能可靠地搭建车辆、角色骨架和行星系统。

## 阅读前置

本文默认你已经知道 Mesh 由 Geometry 与 Material 组成。若这些概念还不熟悉，先读：

- [Geometry、BufferGeometry 与 Mesh 基础](/posts/threejs/geometry-buffergeometry-mesh-explained)
- [Three.js 数学与坐标变换基础](/posts/threejs/math-coordinate-transform-explained)

## Object3D 与场景树

`Scene`、`Group`、`Mesh`、`Light` 和 `Camera` 都继承自 `Object3D`。每个节点都可以有父节点和子节点，并具有三类局部变换：

- `position`：平移；
- `rotation` / `quaternion`：旋转；
- `scale`：缩放。

```javascript
const car = new THREE.Group()
const wheel = new THREE.Mesh(wheelGeometry, wheelMaterial)
wheel.position.set(1, -0.5, 1.5) // 相对于 car
car.add(wheel)
scene.add(car)
```

移动 `car` 时，`wheel.position` 没有变化，但轮子的世界位置会变化。这正是层级的价值：把需要共同运动的对象放到同一父节点下。

## 先统一坐标与角度约定

Three.js 使用右手坐标系：默认可把 `+X` 看作右、`+Y` 看作上、`+Z` 看作从屏幕指向观察者，并满足 `X × Y = Z`。未旋转的相机沿局部 `-Z` 方向观察。具体模型仍可能因为建模软件导出约定不同而需要校正朝向。

旋转 API 使用**弧度**而不是角度：

```javascript
object.rotation.y = THREE.MathUtils.degToRad(90)
// 一整圈是 Math.PI * 2
```

`rotation` 是 Euler 角的便捷表示，Three.js 内部也维护对应的 quaternion。复杂插值或避免 Euler 顺序问题时，优先操作 quaternion，不要同时无规则地改两者。

## TRS：局部变换如何传到世界

Three.js 用位置、四元数和缩放组合局部矩阵，可写成：

```text
M_local = T · R · S
M_world = M_parentWorld · M_local
```


按列向量理解时，一个点先缩放、再旋转、最后平移。父节点矩阵继续乘在外侧，所以子节点的局部轴、位置和尺寸都会受到祖先影响。通常不需要手写这些矩阵，但需要知道 `position` 始终是**相对父节点**的值。

```javascript
const localPoint = new THREE.Vector3(0, 1, 0)
object.localToWorld(localPoint) // 原地改写为世界坐标
object.worldToLocal(localPoint) // 再转换回 object 的局部坐标

const worldPosition = new THREE.Vector3()
object.getWorldPosition(worldPosition)
```

常用的世界查询还包括 `getWorldQuaternion()` 与 `getWorldScale()`。在读取前，正常渲染循环会更新世界矩阵；若你刚修改层级并在渲染前立即查询，可先调用 `object.updateWorldMatrix(true, false)`。

## 自转与公转必须拆成不同节点

“旋转一个位于父节点中心之外的 Mesh”会同时表现为绕父原点公转和自身姿态变化。如果把太阳、地球与月球直接层层嵌在 Mesh 中，再旋转太阳 Mesh 来驱动地球，就会错误地把**太阳自转速度**绑定成**地球公转速度**；旋转地球 Mesh 也会把地球自转绑定到月球公转。

正确建模方式是把“轨道轴心”和“天体自身”拆开：

```text
SolarSystem
├─ SunBody（太阳自转）
└─ EarthOrbitPivot（地球公转）
   └─ EarthAnchor（轨道半径）
      ├─ EarthBody（地球自转）
      └─ MoonOrbitPivot（月球公转）
         └─ MoonBody（轨道半径，可再独立自转）
```

<CodePenDemo title="Orbit Pivot and Body Spin" code={`

  const sunBody = useRef()
  const earthOrbit = useRef()
  const earthBody = useRef()
  const moonOrbit = useRef()

    earthOrbit.current.rotation.y += delta * 0.25
    earthBody.current.rotation.y += delta * 1.5

    moonBody.current.rotation.y += delta * 0.3

这样每个 Ref 只有一个职责：orbit pivot 决定公转，body 决定自转。`EarthAnchor` 只提供轨道半径，月球继承地球的平移与公转，但不会继承 `EarthBody` 的自转。


## Group 与 Pivot：给变换增加语义

`Group` 没有 Geometry，但它是 `Object3D`，适合表达“整车”“炮塔轴”“门铰链”这样的逻辑节点。所谓 pivot 并不是特殊类型，通常就是放在旋转中心的 `Group`：

```javascript
const hinge = new THREE.Group()
const door = new THREE.Mesh(doorGeometry, doorMaterial)

door.position.x = 0.5 // 门板中心从铰链偏开半个门宽
hinge.add(door)
scene.add(hinge)

hinge.rotation.y = -Math.PI / 2
```

把层级按“哪种运动应该影响谁”拆分，比按“屏幕上看起来谁包着谁”更可靠。节点名称也应表达职责，例如 `turretYawPivot`、`barrelPitchPivot`，避免一个节点同时承担平移、两个轴向旋转和视觉缩放。

## 局部坐标与世界坐标

- 局部坐标描述节点相对于父节点的位置和朝向；
- 世界坐标描述完整祖先链计算后，相对于 Scene 根节点的结果。

改变父节点不会改写子节点的 `position`，但会改变它的世界位置。反过来，把对象换到新父节点通常会改变世界姿态；若希望换父级时保持视觉位置，可用：

```javascript
newParent.attach(child) // 尽量保持 child 的世界变换
```

但 `attach()` 在存在非均匀缩放的祖先链时有约束，不能把任意带剪切的世界矩阵无损还原成简单 TRS。

## 非均匀父缩放：问题是有条件的

“父节点只要缩放，子节点就一定剪切”并不准确。父节点使用均匀缩放 `(s, s, s)` 通常安全；非均匀缩放如 `(2, 1, 1)` 在子节点与父轴保持对齐时也未必立刻出现可见剪切。

风险出现在**非均匀缩放的祖先与后续旋转组合**时：世界矩阵可能包含 shear，无法再被一个仅有 position/quaternion/scale 的 `Object3D` 精确表示。这会影响重新挂载、矩阵分解、`lookAt()`，也可能让子物体形变不符合预期。

实用规则：

- 需要旋转的逻辑父节点尽量保持 `scale = (1, 1, 1)` 或均匀缩放；
- 改变模型外形时，优先缩放叶子 Mesh，或直接调整 Geometry/建模资源；
- 必须使用非均匀父缩放时，先确认后代不会进行导致剪切的旋转与重挂载；
- 从外部模型导入后，检查并尽可能在建模工具中应用缩放。

## 场景树的维护边界

场景图层级越深，每次更新世界矩阵需要遍历的节点越多，但不要为了“扁平”牺牲正确语义。先建立清晰层级，再通过性能数据决定是否优化。大量完全静态的对象可以在矩阵正确计算后关闭 `matrixAutoUpdate`；此后若再改 TRS，需要手动 `updateMatrix()`。

对于不再使用的 Mesh，`parent.remove(mesh)` 只会解除层级关系，不会自动释放 Geometry、Material 或纹理对应的 GPU 资源。共享资源应由拥有者统一计数和释放，避免某个子组件提前 dispose 后影响其他 Mesh。

## 总结

- 场景图是一棵 `Object3D` 变换树，子节点的世界矩阵来自 `parentWorld × local`。
- Three.js 使用右手坐标系，旋转值使用弧度，局部变换按 TRS 组合。
- orbit pivot 与 body spin 应拆成不同节点，避免自转和公转耦合。
- Group 是表达轴心与运动职责的工具；局部/世界转换用于跨层级协作。
- 非均匀父缩放并非总会剪切，但与后代旋转组合时必须谨慎。

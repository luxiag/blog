# 从零开始构建 AI 编程助手：Learn Claude Code 项目解析

> 用 550 行代码，理解现代 AI 代理的核心原理

## 什么是这个项目？

这是一个开源教程项目，教你从零开始构建一个类似 Claude Code 的 AI 编程助手。不需要复杂的框架，不需要庞大的代码库——**最简版本只需要 50 行代码**。

项目的核心理念是：**模型占 80%，代码只占 20%**。现代 AI 代理之所以强大，不是因为代码有多巧妙，而是因为模型本身就具备了成为代理的能力。我们的任务只是给它提供工具，然后不要挡道。

---

## 五个版本，循序渐进

项目通过 5 个递进版本（v0-v4），从零构建到功能完整的 AI 代理。每个版本都在上一个版本基础上增加约 100 行代码，却带来质的飞跃。

### v0：Bash 就是一切（50 行代码）

**核心思想：极简主义**

v0 回答了这个问题：一个 AI 代理的最核心是什么？

答案是：一个循环 + 一个工具（bash）。

Unix 哲学告诉我们：一切都是文件，一切都可以管道化。Bash 是通往这个世界的门户：
- 读取文件？用 `cat`、`head`、`grep`
- 写入文件？用 `echo '...' > file`
- 搜索？用 `find`、`grep`、`rg`
- 执行程序？用 `python`、`npm`、`make`

最巧妙的创新是：**通过 bash 调用自己来实现子代理**。不需要专门的 Task 工具，不需要代理注册表——简单的递归就够了。

```python
# 伪代码展示核心循环
while True:
    response = model(messages, tools)
    if response.stop_reason != "tool_use":
        return response.text
    results = execute(response.tool_calls)
    messages.append(results)
```

**v0 证明了一个道理：复杂的能力可以从简单的规则中涌现。**

### v1：模型即代理（200 行代码）

**核心思想：代理的本质是一个循环**

v1 在 v0 基础上增加了 3 个工具，形成了完整的工具集：

| 工具 | 用途 | 示例 |
|------|------|------|
| `bash` | 执行命令 | `npm install`、`git status` |
| `read_file` | 读取文件 | 查看 `src/index.ts` |
| `write_file` | 创建/覆盖文件 | 创建 `README.md` |
| `edit_file` | 精确修改 | 替换某个函数 |

有了这 4 个工具，模型就能：
- 探索代码库（bash: find, grep, ls）
- 理解代码（read_file）
- 进行修改（write_file, edit_file）
- 运行任何东西（bash: python, npm, make）

**关键洞察**：传统助手是 "用户 -> 模型 -> 文本回复"，而代理系统是 "用户 -> 模型 -> [工具 -> 结果]* -> 回复"。这个星号很重要——模型会**反复**调用工具直到任务完成。

这让聊天机器人变成了自主代理。模型是决策者，代码只是提供工具并运行循环。

---

### v2：结构化规划（300 行代码）

**核心思想：让计划可见**

v1 能工作，但对于复杂任务，模型可能会"失忆"。比如让它"重构认证、添加测试、更新文档"，它可能会在任务间跳来跳去，忘记步骤，失去焦点。

v2 增加了一个工具：**TodoWrite**（待办事项）。

把原本只在模型"脑子里"的计划变成显式的：

```
重构前：
  "我要做 A，然后 B，然后 C"（看不见，10 个工具后："等等，我要做什么？"）

重构后：
  [ ] 重构认证模块
  [>] 添加单元测试（当前进行）
  [ ] 更新文档
```

Todo 工具的设计有几个约束：
- 最多 20 项（防止无限列表）
- 只能有一项"进行中"（强制专注）
- 每个任务需要内容、状态、进行中的描述

**深层洞察：结构既是约束，也是赋能。**

这些约束不是随意设置的——它们是护栏。好的约束不是限制，而是脚手架。

---

### v3：子代理机制（450 行代码）

**核心思想：分而治之，上下文隔离**

v2 添加了计划功能，但对于大型任务（如"探索代码库然后重构认证"），单个代理会达到上下文限制。探索会往历史记录里塞 20 个文件，重构时就失去了焦点。

v3 的解决方案是：**把探索委托给子代理**。

```
主代理历史记录（改进前）：
  [探索中...] cat file1.py -> 500 行
  [探索中...] cat file2.py -> 300 行
  ... 15 个文件 ...
  [现在重构...] "等等，file1 里有什么来着？"

主代理历史记录（改进后）：
  [Task: 探索代码库]
    -> 子代理探索 20 个文件
    -> 返回："认证在 src/auth/，数据库在 src/models/"
  [现在用干净上下文重构]
```

v3 引入了**代理类型注册表**，不同类型的代理有不同的能力：
- `explore`（探索型）：只读，用于搜索和分析
- `code`（编码型）：完整工具，用于实现
- `plan`（规划型）：只读，用于规划和分析

**关键概念**：
- 上下文隔离：子代理有全新的历史记录
- 工具过滤：不同类型代理只能使用特定工具
- 专业化行为：每个类型有专门的系统提示
- 结果抽象：只返回最终文本，不污染主代理上下文

### v4：技能机制（550 行代码）

**核心思想：知识外部化，按需加载专业知识**

v3 给了我们子代理来分解任务。但还有一个更深层的问题：**模型如何处理特定领域的任务？**

- 处理 PDF？它需要知道 `pdftotext` 还是 `PyMuPDF`
- 构建 MCP 服务器？它需要协议规范和最佳实践
- 代码审查？它需要系统性检查清单

这些知识不是工具——而是**专业知识**。技能机制通过在需要时加载领域知识来解决这个问题。

#### 范式转变：从训练到编辑

**传统方式（知识内化）**：
- 知识锁定在模型参数中
- 修改需要训练（LoRA、全量微调）
- 用户无法访问或理解
- 成本：$10K-$1M+，时间：数周

**新方式（知识外部化）**：
```
模型参数 → 上下文窗口 → 文件系统 → 技能库
(内部)      (运行时)     (持久化)    (结构化)
←————— 需要训练 —————→  ←——— 自然语言编辑 ———→
```

修改模型行为 = 编辑 SKILL.md = 编辑文本文件 = 任何人都能做

**这就像给基础模型附加一个可热插拔的 LoRA 适配器，但不需要任何参数训练。**

#### 渐进式披露

技能采用三层结构：

```
第 1 层：元数据（始终加载）    ~100 tokens/技能
         └─ 名称 + 描述

第 2 层：SKILL.md 主体（触发时） ~2000 tokens
         └─ 详细说明

第 3 层：资源（按需）          无限制
         └─ 脚本/、参考资料/、资源/
```

这让上下文保持精简，同时允许任意深度的知识。

#### 为什么重要：缓存经济学

很多开发者在使用 LangGraph、LangChain、AutoGen 时习惯：
- 将动态状态注入系统提示
- 编辑和压缩消息历史
- 使用滑动窗口截断对话

**这些操作会破坏缓存，使成本暴涨 7-50 倍。**

一个典型的 50 轮软件工程任务：
- **破坏缓存**: $14.06
- **优化缓存**: $1.85
- **节省**: 86.9%

对于每天处理 100 个任务的应用，这意味着**每年节省 $45,000+**。

**核心原则：将上下文视为仅追加的日志，而不是可编辑的文档。**

## 学习路径建议

```
从这里开始
    |
    v
[v0: Bash 代理] -----> "一个工具就够了"
    |                    16-50 行代码
    v
[v1: 基础代理] -----> "完整的代理模式"
    |                    4 个工具，约 200 行
    v
[v2: Todo 代理] -----> "让计划显式化"
    |                    +TodoManager，约 300 行
    v
[v3: 子代理] -------> "分而治之"
    |                    +Task 工具，约 450 行
    v
[v4: 技能代理] -----> "按需加载领域知识"
                         +Skill 工具，约 550 行
```

**推荐学习方法**：
1. 先读并运行 v0——理解核心循环
2. 对比 v0 和 v1——看工具如何演进
3. 学习 v2 的规划模式
4. 探索 v3 的复杂任务分解
5. 掌握 v4 构建可扩展代理

| 版本 | 主题 | 代码增量 | 核心洞察 |
|------|------|----------|----------|
| v0 | Bash 就是一切 | ~50 行 | 一个工具就够了 |

### 哲学

> **模型占 80%。代码占 20%。**

现代代理如 Kode 和 Claude Code 之所以有效，不是因为巧妙的工程，而是因为模型被训练成了代理。我们的工作是给它工具，然后不要挡道。

### 终极秘密

```python
while not done:
    response = model(conversation, tools)
    results = execute(response.tool_calls)
    conversation.append(results)
```

**模型即代理。这就是全部秘密。**
